# Аналіз: як подавати лор Квестарні зараз

## Короткий висновок

Перша версія пакета добре ловила ідею «коротких переказів», але частина seed-контенту відʼїхала від поточної гри: вигадані народи, нейтральні скрині, щури-книжники і загальна «країна між квестами» звучали нормально як окремий фентезі-світ, але слабше як Квестарня станом на зараз.

Нова версія тримається за те, що вже є в runtime: раси, класи, монстри, місцини, Бочка, Шинок, Низ, Пропамʼятна дошка, манатки, технічні пригоди й fair-play позиція.

## Принципи

1. **Переказ має підсилювати існуючу кнопку.** Якщо гравець уже бачив `Мімік-шаурма`, `Єгерський куток` або `Бюрокромант`, лор має робити це смішнішим, а не відкривати паралельний світ.
2. **Раси й класи — з поточного content source.** Не вигадувати «лісових» чи «тінників», поки їх немає в onboarding.
3. **Монстри — з поточного roster.** Для MVP достатньо spotlight-записів; повний список можна мати як індекс або future unlock.
4. **Українськість не як табличка, а як спосіб жарту.** Квасний голем, Бісини, Вареник-мант, Песиголовець із відділу кадрів і Писар тихої катастрофи вже роблять більше, ніж загальна фраза «українське фентезі».
5. **Не спойлерити hidden-механіки.** `sun/moon/boundary` і точні бойові формули не виходять у player-facing текст.

## Категорії для MVP

- 🏚 Про Квестарню
- 🪧 Місцини корчми
- 🧝 Раси пригодників
- ⚔️ Класи пригодників
- 🧌 Бестіарій
- 🎒 Манатки
- 📜 Звичаї й чутки

## Що прибрано з попередньої версії

- Абстрактні `Люди тракту`, `Лісові`, `Камінні роди`, `Тінники`, бо вони не є поточними playable race ids.
- `Щури-книжники` і `Скрині, що рахують образи`, бо в актуальному monster roster є значно сильніші й конкретніші істоти.
- Суху «вікі»-рамку навколо світу. Квестарня краще працює як дошка коротких переказів із конкретними гачками.

## Формула запису

`Назва` → `джерело` → 1–3 короткі абзаци → конкретний жарт/дивина → optional canonical refs.

Головна перевірка: запис має звучати так, ніби його могла видати Дошка корчми, Корчмар, Єгер або торба з манатками.

# Специфікація фічі: 📖 Перекази в Дошці корчми

## Ціль

Додати в **Дошку корчми** легкий розділ `📖 Перекази`, де гравець читає короткі записи про вже наявні елементи Квестарні: місцини, раси, класи, монстрів, манатки й звичаї гри.

Це не окрема вікі й не lore dump. Це ще одна кнопка з fun-per-message.

## Вхід

Основна кнопка:

```text
📖 Перекази
```

Місце інтеграції: поточний `news-corner` / Дошка корчми або поруч із `/news`, але не замість новин.

Не називати головну кнопку `📜 Лор` у першому варіянті: «Перекази» звучить природніше для корчми й менше схоже на технічний розділ.

## Меню

```text
📖 Перекази Квестарні

На краю Дошки корчми висить тека з переказами. Тут не все правда, але в Квестарні правда й не завжди найдорожча.

Обери, про що почитати:
```

Кнопки:

```text
🏚 Про Квестарню
🪧 Місцини корчми
🧝 Раси пригодників
⚔️ Класи пригодників
🧌 Бестіарій
🎒 Манатки
📜 Звичаї й чутки
🎲 Випадковий переказ
⬅️ До Дошки корчми
```

## Дані

MVP може почати зі статичного `lore-seed.json` або TypeScript data file, але runtime-source для індексів має лишатися в існуючих content-файлах:

- `src/content/races.ts`
- `src/content/classes.ts`
- `src/content/monsters.ts`
- `src/services/presenceService.ts`

`canon-snapshot.json` у цьому архіві — не production source of truth. Це допоміжний snapshot для планування й ревʼю.

## Callback naming

Використати окремий callback namespace:

```text
v1:lore:menu
v1:lore:cat:<categoryId>
v1:lore:entry:<entryId>
v1:lore:random
v1:lore:random:<categoryId>
```

Перед мерджем перевірити, що callback data вкладається в Telegram 64 bytes.

## Екран категорії

```text
<emoji> <Назва категорії>

<короткий опис>

Перекази:
```

Кнопки:

```text
<назва запису>
🎲 Випадковий із цієї категорії
⬅️ До переказів
🪧 До Дошки корчми
```

## Екран запису

```text
📖 <Назва>
<i>Джерело: ...</i>

<текст>

— <Категорія> · <номер>/<усього>
```

Використовувати HTML parse mode й escaping, як у решті bot presenters.

## Unlock / gating не в MVP

У першій версії можна показувати всі seed-записи. Але код краще спроєктувати так, щоб пізніше можна було:

- ховати високорівневих монстрів до зустрічі або рівня;
- відкривати записи за досягненнями / перемогами / титулами;
- показувати race/class entries тільки після створення персонажа.

## Не робити в MVP

- Не робити базу даних для лору.
- Не додавати reward за читання.
- Не показувати hidden `sun/moon/boundary`.
- Не спойлерити точні формули бою або лут-шанси.
- Не вигадувати нові playable race/class names у player-facing entries.
