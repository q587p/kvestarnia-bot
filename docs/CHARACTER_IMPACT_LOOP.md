# Character Impact Loop

## Навіщо

Створення персонажа вже має добрий гачок: гравець обирає звертання, расу, клас, отримує унікальний титул і може сміятися з недоступних комбінацій. Наступний крок — щоб ця біографія почала відповідати в грі.

Ціль: зробити `/restart` не лише технічною командою, а discovery loop.

Гравець має думати:

> «А що скаже корчмар, якщо я зайду Дрантогором-бюрокромантом?»

> «А миша інакше реагує на Домовика?»

> «А Бісини справді бісять шаурму?»

Це не має ставати важкою RPG-системою. Перший шар — тексти, альтернативні назви кнопок, дрібні route-флейвори, іноді мікро-винагорода або інший item flavor. Гумор/іронія/пародія важливіші за оптимізацію білдів.

## Поточна база

Видимі звертання:

- `Він` → `he`
- `Вона` → `she`
- `Вони` → `they`

Приховані path-id лишаються внутрішньою канцелярською позначкою:

- `he` → `sun`
- `she` → `moon`
- `they` → `boundary`

Не показувати гравцю «Шлях Сонця/Місяця/Межі» як серйозний лор. Якщо треба пояснювати недоступність — пояснювати через корчмарську бюрократію, фольклор і дивні правила світу.

Активні раси на момент цієї доки:

- `race.human-ish` — Людисько
- `race.dwarf` — Гном
- `race.elf` — Ельф
- `race.bisyny` — Бісини
- `race.drantohor` — Дрантогор
- `race.domovyk` — Домовик
- `race.dryland-rusalka` — Русалка сухопутна
- `race.intellectual-orc` — Орк-інтелігент
- `race.molfar-soul` — Мольфарська душа

Deprecated/fallback:

- `race.kharakternyk` — тільки для старих персонажів; нові пригодники обирають `class.kharakternyk`.

Активні класи:

- `class.warrior` — Воїн
- `class.mage` — Маг
- `class.bard` — Бард
- `class.rogue` — Злодій
- `class.priest` — Жрець
- `class.varenyk-mancer` — Вареник-мант
- `class.bureaucramancer` — Бюрокромант
- `class.ranger` — Єгер
- `class.kharakternyk` — Козак-характерник

## Новий loop: «персонаж відповідає світом»

Базовий цикл:

1. Гравець створює пригодника.
2. Персонаж отримує унікальний титул.
3. При вході в корчму корчмар реагує на расу/клас/звертання/path/титул/комбінацію.
4. Квести дають хоча б одну персоналізовану репліку, кнопку або outcome.
5. Рейди дають role-hint або жарт про те, як цей персонаж поводився б у повному рейді.
6. Гравець бачить, що біографія реально змінює текстову гру.
7. Після денних квестів/льоху/рейду `/restart` стає способом подивитися інші реакції, а не лише «почати спочатку».

## Принципи

### 1. Спершу флейвор, потім механіка

MVP-вплив:

- інший рядок корчмаря;
- альтернативна назва кнопки;
- додаткова репліка в старті квесту;
- додатковий рядок в outcome;
- інший joke reward note;
- інший коментар у cooldown/already-completed;
- role-hint перед рейдом.

Не робити одразу:

- великі stat-бонуси;
- складний класовий combat;
- unlock-only контент, який блокує основний loop;
- hidden path як серйозну метафізику.

### 2. Не карати гравця за вибір

Якщо комбінація «неідеальна», вона має бути смішною, а не слабкою.

Погано:

> Дрантогор не може пройти квест, бо не той клас.

Добре:

> Дрантогор показує міміку карту Остромагу. Мімік теж губиться, і це рахується як план.

### 3. Максимум дві персоналізовані вставки на сцену

Щоб текст не перетворився на анкету:

- 1 коротка персоналізована репліка на старті;
- 1 короткий персоналізований outcome або reward note;
- далі fallback.

### 4. Пріоритет селекторів

Якщо одночасно підходить кілька реплік:

1. exact combo: `raceId + classId`;
2. class-specific;
3. race-specific;
4. pronoun/path-specific;
5. title/fallback.

Для корчмаря можна іноді навпаки: combo → race → class, бо раса часто видиміша в жарті.

### 5. Не повторювати одну й ту саму репліку постійно

Для кожного селектора тримати 2–4 варіанти. Вибір має бути deterministic у тестах і досить різний у production.

Мінімальний варіант без нової таблиці:

- `seed = character.id + localDate + locationId + flavorKind`
- стабільно протягом дня;
- завтра той самий герой може побачити інший варіант.

Якщо хочеться різноманітності навіть при повторному заході того ж дня:

- додати service-level `flavorSeed`, який у production бере `clock` із 10–15 хвилинним bucket-ом;
- у тестах передавати фіксований seed;
- не використовувати `Math.random()` напряму в presenter.

### 6. Ніяких реальних стереотипів

Жарти привʼязуються до внутрішньосвітових тегів:

- Домовик → хата, пил, ложки, піч, «це моє»;
- Бісини → назви, правки, перекладачі, коментарі, суперечки;
- Дрантогор → Остромаг, заблукав, Межа, пропуски, чужі карти;
- Русалка сухопутна → чайники, калюжі, уявний хвіст, море без моря;
- Орк-інтелігент → диплом, рецензія, етика, аргумент обличчям;
- Мольфарська душа → туман, обереги, кишені, «спитав у вітру».

## Рекомендована структура коду

Новий модуль:

```ts
src/content/characterFlavor.ts
```

Типи:

```ts
export type FlavorPlacement =
  | "korchma.greeting"
  | "quest.start"
  | "quest.choice"
  | "quest.outcome"
  | "quest.reward-note"
  | "raid.prep-hint"
  | "raid.ranger-action"
  | "item.inspect";

export interface CharacterFlavorSelector {
  raceIds?: string[];
  classIds?: string[];
  pronouns?: Pronoun[];
  paths?: CharacterPath[];
  combos?: Array<{ raceId: string; classId: string }>;
}

export interface CharacterFlavorLine {
  id: string;
  placement: FlavorPlacement;
  selector: CharacterFlavorSelector;
  priority?: number;
  text: string;
}
```

Helper-и:

```ts
getCharacterFlavorContext(character: CharacterSummary)
selectFlavorLine(lines, context, seedParts)
selectFlavorLines(lines, context, seedParts, limit)
```

Важливо: presenter не має знати весь вміст контенту. Presenter має отримати вже обрані 0–2 рядки або викликати маленький helper.

## Де підключати спочатку

### Корчма

- `presentKorchmaHall()` — додати корчмарське greeting-line після заголовка персонажа або перед «Куди йдемо?».
- `presentTavernRaidPending()` активного рейду біля бочки — додати `raid.prep-hint` перед таймером і `raid.ranger-action` для дій єгеря.
- `presentKorchmaFront()` можна лишити статичним; це ще не вхід у корчму.

### Шаурма-квест

- `presentAdventureStart()` — додати `quest.start` line.
- `presentActionOutcome()` — додати character-aware outcome або додатковий рядок після базового outcome.
- 0.0.19 тримає перший playable loop щільнішим: льох і Дошка полювання відкриваються рівнями, тому шаурма має давати більше варіятивності одразу.
- Для `shawarma` потрібні окремі race/class pools і combo-lines для всіх доступних onboarding комбінацій.
- Character-aware labels на кнопках можуть міняти текст дії, але не callback payload, reward math або idempotency key.
- Не міняти reward keys у першому PR.

### Сутичка з шаурмою

- `presentFightStart()` — додати 1 рядок class/race hint.
- `presentOutcome()` — додати 1 рядок для класу/комбо.
- Стартовий текст має уникати раннього reveal, що підозрілий монстр є Міміком-шаурмою; розкриття краще давати в результатах дій.
- Для `fight` теж потрібні race/class pools і combo-lines для всіх доступних onboarding комбінацій.
- Квест має звучати як дослідити/допитати/оформити підозрілу їжу, а fight — як удар/трюк/контроль/відступ проти монстра.
- Бойова математика лишається deterministic і без нових бонусів.

### Льохова справа

- `presentCellarStart()` — додати персоналізований старт.
- `presentCellarOutcome()` — додати character-aware outcome для `negotiate`, `cheese-trap`, `sweep-bravely`.
- Домовик + negotiate має бути першим obvious win у флейворі.
- Льох — друге знайомство з варіятивністю після шаурми, тому потрібні race/class pools і combo-lines для всіх доступних onboarding комбінацій.
- Character-aware labels на кнопках льоху можуть міняти текст дії, але не callback payload, cooldown, reward math або item grants.
- Дії мають звучати різно: сирна пастка, хоробре підмітання й переговори з мишею не повинні відчуватись як одна кнопка з різними емоджі.

### Манатки

Поки без реалізації: при inspect item у майбутньому показувати 0–1 рядок:

- Бюрокромант дивиться на чек як на родича.
- Бісини сперечаються з назвою предмета.
- Дрантогор шукає на квитку печатку Остромагу.

## Restart як частина гри

Після денного контенту і в `/hero` можна іноді дуже обережно натякати:

> Інша біографія — інші підозри корчмаря. `/restart`, якщо хочеться зіпсувати йому картотеку.

Не показувати це постійно. Варіанти місць:

- після `already-completed` для шаурми, якщо і quest, і fight сьогодні вже закриті;
- після льохової справи на cooldown;
- у `/hero` раз на N переглядів у майбутньому;
- у restart confirmation: «Старий титул піде в архів, але корчмар отримає нову причину нервувати».

У майбутньому можна додати collection/discovery:

- `seenFlavorHookIds`;
- «корчмар уже сказав про вас 7 дивних речей»;
- косметичний badge за 3 різні раси або 5 різних класів.

Для MVP це не треба. Достатньо зробити так, щоб інша комбінація давала помітно інший текст.
