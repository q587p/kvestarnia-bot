# 0.2.13 — Party Session Foundation

## Goal

Ship a restart-safe, concurrency-safe party/session recruiting foundation behind a dev-only or feature-flagged entry point. This is a prerequisite for future party combat and real raids, not a playable boss release.

## Scope

Base on `docs/tasks/0.2.x-raid-party-session-foundation.md` and current repo state.

- Session + participant persistence.
- Recruiting/cancelled/expired statuses.
- One live recruiting session per leader.
- One live party membership per character.
- Opaque deep link token.
- Join/rejoin/leave/cancel/expiry.
- Deterministic leader transfer.
- Nearby invite integration if privacy-safe.
- Dev helpers for QA.
- Feature flag/config seam.

## Non-goals

- No boss.
- No combat rounds.
- No HP/mana/actions.
- No rewards.
- No production Barrel route change.
- No guild, matchmaking, public roster or Redis/BullMQ.

## Acceptance criteria

- Duplicate create converges.
- Concurrent joins do not exceed cap.
- Duplicate joins do not duplicate rows.
- Expiry cannot be revived by old links.
- Leave/leader transfer/last-member terminalization are canonical.
- Old buttons replay state.
- Production Barrel behavior remains unchanged.

## Tests

- lifecycle and concurrency repository tests;
- deep link/callback parser byte limits;
- restart/expiry behavior;
- presenter HTML escaping;
- privacy filtering;
- legacy Barrel regression;
- full check.

## Manual QA

1. Enable feature flag/dev commands locally.
2. Create party as A.
3. Join as B by deep link and replay.
4. Invite C nearby if supported.
5. Leave/rejoin.
6. Leader leaves; verify transfer.
7. Fill to cap and attempt extra joins.
8. Restart and refresh.
9. Expire and replay old links.
10. Disable flag; verify no production access.
