# 0.2.8 — Achievements and Cosmetic Title Records

## Goal

Ship the first rewardless achievement system and future-title records: players can browse earned/locked/hidden achievements, unlock a small seed set through existing events, and receive compact grouped notifications without any gameplay power.

## Scope

- Add achievement definitions in content with validation.
- Start from the existing Phase 1 achievement seed direction; disable definitions for unshipped systems.
- Persist unlocked achievements and optional progress only where no existing source of truth exists.
- Add character-screen entry `🏅 Ачівки`.
- Render earned, locked and hidden rows with pagination.
- Track a minimal event set from already-shipped systems:
  - character created;
  - level reached;
  - combat finished / monster killed where source data exists;
  - quest/problem completed where source data exists;
  - item received/equipped where safe;
  - presence/daily activity only if source data is reliable.
- Group multiple unlock notifications from one action.
- Store cosmetic title grants as records for later, but do not require active-title selection unless it is tiny and safe.

## Non-goals

- No XP, gold, items, stat effects, loot odds, combat power or donor perks.
- No active title selection if it needs a larger model.
- No bestiary/museum collection system in this release.
- No broad telemetry/analytics engine.
- No reward backfill spam.

## Acceptance criteria

- Achievement definitions have unique ids and stable order.
- Hidden achievements do not reveal criteria before unlock.
- Duplicate events do not duplicate unlocks.
- Backfill is silent or explicitly summarized once.
- Player-facing copy is Ukrainian and short.
- Callback data stays under Telegram limits.
- No achievement can alter combat, economy, loot, quest progress or paid support behavior.
