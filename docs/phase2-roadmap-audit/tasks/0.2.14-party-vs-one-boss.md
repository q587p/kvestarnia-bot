# 0.2.14 — Party vs One Boss

## Goal

After the party/session foundation has shipped and survived QA, implement the first production party combat proof: a small party against one shared boss-like enemy, with compact actions and conservative exactly-once settlement.

## Scope

- Reuse party/session foundation.
- One shared enemy target.
- Short deterministic rounds.
- AFK/stale participant fallback.
- Restart-safe session recovery.
- Exactly-once terminal reward, if a reward is approved.
- Qualitative pre-commit copy; exact reward only after resolution/internal docs.

## Non-goals

- No targetable adds.
- No broad party-vs-many runtime.
- No Senior Barrel Brother production content.
- No guilds, market, crafting, scheduler or Mini App.
- No reward faucet without explicit balance review.

## Acceptance criteria

- Party can enter one-boss encounter without corrupting solo fight state.
- Duplicate/stale callbacks cannot double-spend actions or duplicate rewards.
- Existing solo combat, starter flows, duels and safe gifting remain stable.
- UI clearly distinguishes this from real raids.

## Tests

- party start and active-session gating;
- turn/action uniqueness;
- stale/duplicate callback idempotency;
- AFK fallback;
- settlement replay;
- solo combat regression;
- reward exactly-once behavior.

## Manual QA

1. Create/join party.
2. Start one-boss encounter.
3. Let one participant act and another miss/stale.
4. Finish encounter.
5. Replay old buttons.
6. Run normal solo fight afterward.
