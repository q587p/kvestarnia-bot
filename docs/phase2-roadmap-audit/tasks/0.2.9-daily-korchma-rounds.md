# 0.2.9 — Daily Korchma Rounds

## Goal

Activate the existing Daily Korchma Rounds design as a low-pressure once-per-Kyiv-day route: level 3+ players see three authored korchma incidents, complete any two in their locations, then return to Quest Table for one small replay-safe reward.

## Scope

Use `docs/tasks/0.2.x-daily-korchma-rounds.md` and `docs/design/daily-korchma-rounds.md` as the canonical base, then renumber to the actual release.

Keep the first implementation narrow:

- exactly three daily scenes;
- exactly two required completions;
- no combat, items, stat checks or costs in steps;
- explicit Quest Table claim;
- Kyiv-local day identity;
- no Prisma migration if existing `daily_actions` suffices;
- add `Задвірок корчми` only as much as the daily route needs.

## Non-goals

- No daily checklist over unrelated systems.
- No streak, FOMO, catch-up or third-step bonus.
- No broad quest engine.
- No achievement implementation inside this task.
- No item-use, Bard Performance, party or market work.

## Acceptance criteria

- One stable daily offer per Kyiv day.
- Offer survives restart and remort without duplicating the reward.
- Exactly one yard scene and two different interior scenes.
- Any two unique steps are enough; third locks after `2/2`.
- Wrong-location, old-day, old-life and duplicate callbacks are no-ops or replay canonical state.
- Final claim is once and only from Quest Table.
- Existing adventure/fight/Yeger/Shynok/cellar flows retain behavior.

## Focused tests

Follow the existing task doc, especially:

- Kyiv date rollover and DST;
- offer persistence;
- scene/action uniqueness;
- callback byte length;
- wrong-location/stale-day/old-life;
- exactly-once reward;
- remort boundaries;
- combat lock and pending Barrel integration.

## Manual Telegram QA

1. Level 2 locked state.
2. Level 3 daily overview.
3. Complete first scene in correct location.
4. Attempt second scene from wrong location.
5. Complete second scene, verify third locked.
6. Claim from Quest Table.
7. Replay old buttons.
8. Remort before/after claim.
9. Restart before/after claim.
