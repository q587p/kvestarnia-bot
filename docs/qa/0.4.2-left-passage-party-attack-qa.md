Deep-review coverage strengthens the combat row above: every authored
target/damage modifier, heal, shield, mana drain, cleanse/removal/reapply,
lock/pressure, counter/reflect, damage-over-time, accuracy/evasion, mark,
cooldown and conditional follow-up component compiles to typed deterministic
execution. Persisted effects retain exact source ability, target, trigger,
duration and charges and are rederived on restart. There is no label-only
fallback; unsupported start-time recipes and unknown/corrupt persisted
semantics fail closed.

The catalog-wide assertion maps every semantically active authored parameter to
exactly one typed execution consumer rather than merely recognizing emitted
component kinds. Focused state deltas cover class-only, race-only and one
deterministically selected frozen-ability locks. Mana-cost pressure is included
once in an eligible ability's validation, keyboard availability and committed
spend; attack, guard, flee and item actions never pay it. `monster.false-exit`
modifies the single canonical flee chance before its one roll while attempt
seven remains guaranteed. Charged marks survive misses and zero-damage attempts
and are consumed by the first landed incoming hit, including a hit reduced by
guard. Reapplied expired effects keep their original authored semantic source
and separately validate deterministic reapplication provenance across JSON
round-trip, restart and duplicate resolution.

The authoritative lease row also fails closed for a missing, terminal,
quarantined, wrong-participant or unknown-kind owner: one recovery notice, no
downstream navigation and no unrelated ownership probes. After a terminal result/main-menu
publication is acknowledged, its exact claim/navigation lease remains held through result
card adoption and cleanup and is released only by the final token/reference
CAS; restart after adoption remains recoverable.
The recognized temporary `group-combat-exit-navigation` owner is the exception
to active-combat dispatch: middleware resumes that exact healthy exit, then
continues the original quest/location route without a repeated mismatch
warning. Repair accepts both unclaimed and exactly claimed `menu-delivered`
evidence, so it cannot quarantine the normal interval between Telegram
acknowledgement and the final navigation CAS.

Explicit `🔎 Оновити` persists that participant's control-publication request before
the immediate Telegram attempt. A busy/dead publisher therefore leaves bounded
delivery work, and active delivery cannot be finalized until a private reply
inline-control fingerprint is acknowledged.

The active publication claim is renewed atomically before every active-card Bot
API send/edit/delete and each request aborts after 13 seconds, below the
23-second stale boundary. The independent exit-navigation claim is likewise
renewed after current navigation markers resolve and immediately before its
main-menu send, which uses the same 13-second abort. Ownership loss stops the
send; ordinary rejection releases to pending, acknowledgement failure retains
the live claim, and the terminal result card does not replace the persistent
reply keyboard. Control fingerprint/generation acknowledgement occurs only
when the inline grid was attached to a private canonical card; a supergroup
notice leaves it due. An explicitly fresh private actor card republishes the
current inline controls without treating unchanged party controls as a reason
for routine replacement sends.
The first authoritative keyboard-generation owner sends the production intro
separately inside the participant's durable publication claim immediately
before the canonical card; the intro carries persistent main navigation and
the canonical card carries current inline combat actions. Neither releases the
canonical reference. An unchanged active-card redraw retains inline controls on
the same message; a start/scheduler overlap therefore leaves one full
first-turn card, and ordinary five-second delivery ticks remain silent.
A completed exit clears pending terminal delivery independently of an older
legacy delivered revision. A validated manual action commits before the separate bounded resolution
attempt, so final win/flee rows survive process death and duplicate or timeout
work can adopt them after restart without replaying gameplay effects. Telegram
acceptance immediately before abort or network failure remains externally
at-least-once because the Bot API supplies no idempotency key.
