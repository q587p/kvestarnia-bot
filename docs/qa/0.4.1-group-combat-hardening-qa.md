# 0.4.1 Group Combat Hardening QA

Status: automated acceptance coverage implemented; manual Telegram QA pending
until executed against the final exact PR head.

## Preconditions

- Use the isolated non-production bot with `GROUP_COMBAT_PROOF_ENABLED=true`
  and dev helpers enabled. Never use production data.
- Use three private Telegram accounts with current-life characters. Prepare
  Priest, Bard, Varenyk-mancer, Dwarf, Domovyk and Molfar combinations across
  fresh parties; use existing supported Mantok gear and each existing combat
  healing item where owned.
- Record Character HP, mana, XP, gold and inventory before each scenario.
  Create a fresh party through `/dev_party`, then start only through the
  private leader button or `/dev_group_combat <invite-suffix>`.
- Record the exact Git head, local snapshot id and start/end Kyiv timestamps.

## Target and ability matrix

1. **Self and exact ally.** Use Varenyk-mancer steam on self and each living
   ally. Confirm the callback/card names the selected target, dead targets have
   no button, and another valid choice replaces the queued one before resolve.
2. **Lowest HP.** Give two allies equal HP ratios, then use Priest and Domovyk.
   Confirm roster order breaks the tie. Kill the earlier ally and repeat;
   support must move to the next living eligible ally without revival.
3. **All allies.** Use Bard, Dwarf and Molfar support. Confirm every living ally
   receives only the authored guard/mitigation/counter effect and dead allies do
   not. Force the deterministic fumble fixture through the dev snapshot if
   available; it must spend the committed ability cost/cooldown without applying
   friendly support.
4. **Enemies.** Exercise one-enemy and all-enemies abilities against 2×2 and
   3×3 encounters. Kill the selected enemy before a later queued action resolves;
   the later action may retarget only to the stable first legal living enemy.
5. **Unavailable actions.** Exhaust mana and keep an ability on cooldown. Its
   action must disappear or return an explicit unavailable refresh without
   claiming the choice was queued or spending a turn.

## AI, status and death matrix

1. Build threat with direct damage, healing and guard. Confirm enemies choose
   only living legal targets using the same committed state after refresh and
   restart.
2. Let the first enemy response kill the highest-threat participant. Later
   enemies in that turn must retarget a living participant; no recap/card may
   damage the dead participant again.
3. Exercise guard prevention, response mitigation, Molfar counter and supported
   gear bleed. Confirm the terminal contribution row reports actual prevented,
   controlled, taken and dealt amounts rather than authored maximums.
4. End one turn with multiple participant deaths and another with multiple
   enemy deaths. Confirm one deterministic terminal outcome, no post-terminal
   mutation and identical participant cards.

## Item, gear and race matrix

1. Queue each supported healing item at valid HP, replace it before resolution,
   and double-tap it. Only the final committed item action may consume one copy.
2. Race an item-bearing final action against timeout. Timeout remains a
   resource-free self guard; whichever path wins, inventory changes by at most
   one and the recap/state/action row agree.
3. Use the same item as the last owned copy. After the winning turn, refresh and
   restart; the item must remain absent and the receipt must not consume again.
4. Exercise every frozen supported Mantok combat ability. Unequipping or
   changing live inventory outside the locked proof must not change the frozen
   action recipe; unsupported or foreign payloads must fail closed.

## Settlement, lifecycle and delivery matrix

1. Finish win, loss and invalid-repair sessions. Confirm one terminal settlement
   plan, zero XP/gold/items and unchanged Character economy/resources.
2. Settle participant A, restart, settle participant B, then replay A and B.
   Each receipt must return independently with the same zero-reward identity;
   the terminal combat state and plan must remain byte-identical.
3. During active combat try `/restart`, `/remort`, another combat and timed-status
   reads. Confirm transaction-level blocking and paused `Ситий`/`Натхнення`.
   After win/loss/invalid repair, confirm every participant lease and recoverable
   frozen status releases exactly once.
4. Corrupt one recipe/status/target/action payload in a disposable local DB,
   then run repair beside a healthy due session. The malformed session must
   invalidate rewardlessly without preventing the healthy session from moving.
5. Delete/bury one canonical card and race refresh with timeout/final action.
   Confirm one canonical private card per participant, no public mutation, no
   new card each round, accurate remaining seconds and a terminal contribution
   block inside one Telegram card.

## Required evidence

- Exact head and isolated snapshot id.
- Screenshots or message exports for each target scope, multi-death turn,
  item/gear action, timeout/restart and terminal contribution/receipt path.
- Before/after resource and inventory records with private ids sanitized.
- Confirmation that ordinary single/multi-enemy PvE, Training Doppelgänger,
  turn duel and Big Barrel smoke remain unchanged.

Do not mark manual QA complete from automated output. Append results only after
