## Manual Telegram QA

### 1. Normal performance grants free Inspiration

- Preconditions: level-eligible Bard and one active listener at the same location; neither in combat/raid; no current Inspiration.
- User action: Bard starts the existing performance. Listener does not press any reaction button.
- Expected bot response: normal performance card and reaction controls remain; listener immediately receives `✨ Натхнення`, strength matching the frozen performance grade, with 13-minute explanation.
- Expected state: one performance, one audience reaction offer, and one versioned Inspiration state commit atomically; no listener payment.
- Verify: source performance id/location/life identity and frozen grade match; no location rows changed.

### 2. Tips remain social, not pay-to-win

- Preconditions: three listeners receive the same performance: one applauds, one tips, one declines/times out.
- User action: resolve each reaction differently.
- Expected bot response: existing money/reaction copy behaves as before; no copy implies that payment buys power.
- Expected keyboard: listeners with `0/1/3/5/13` gold see tip choices `— / 1 / 1,3 / 1,3,5 / 1,3,5,13`; applause and decline remain available at every balance.
- Expected state: all three keep identical Inspiration strength and original duration cursor; only existing economic reaction fields differ.
- Verify: no status write occurs solely because of a tip callback; spending gold elsewhere before pressing an old tip button still fails transactionally and rebuilds only currently affordable choices.

### 3. Audience boundaries

- Preconditions: performer; active same-location listener; listener elsewhere; late arrival; player in persistent combat; player already in raid.
- User action: start performance, then move the late arrival into the location.
- Expected bot response: only the canonical starting listener receives the effect/notification.
- Expected state: no Inspiration row for excluded characters or late arrival.
- Verify: the performance’s normalized actual location is unchanged through callbacks.

### 4. Non-stacking rule

- Preconditions: use the dev helper to create `+3` with a visibly reduced remaining time; arrange later `+2`, `+3`, then `+5` performances.
- User action: trigger each in sequence.
- Expected bot response: `+2` and `+3` report/no-op without refreshing; `+5` reports replacement and returns to 13 minutes.
- Expected state: one slot; no summed bonus; only strictly stronger activation id replaces.
- Verify: original expiry/cursor survives equal/weaker attempts.

### 5. Outside time to combat handoff

- Preconditions: Inspiration active with a fractional remaining duration; no `Ситий` state.
- User action: enter persistent PvE, resolve one offensive and one defensive turn, then flee/finish.
- Expected bot response: bonus visible on the offensive hit context; remaining value drops by two combat minutes; status card resumes outside timing.
- Expected state: wall clock paused while lease active; two unique pulse ids; exact fractional remainder restored.
- Verify: no double release and the active combat lease is cleaned once.

### 6. Inspiration and `Ситий` together

- Preconditions: both states active with different remaining durations.
- User action: enter combat, press one action twice rapidly, continue until one status expires, finish combat.
- Expected bot response: duplicate callback has no second result; each committed turn pulses both applicable states once; one expiring does not corrupt the other.
- Expected state: one lease owns/synchronizes both; final outside remainders are correct.
- Verify: no orphan lease or re-created expired cooldown payload.

### 7. Turn duel actor isolation

- Preconditions: only one duelist has Inspiration.
- User action: play several actions from both accounts.
- Expected bot response: only the inspired actor’s canonical hit rolls receive the bonus; both timers pulse only on their own committed turns according to the chosen duel lease contract.
- Expected state: no modifier leaks to the opponent or permanent stats.
- Verify: replayed duel journal remains deterministic.

### 8. Quick duel regression

- Preconditions: inspired participant starts the current quick-duel flow.
- User action: resolve the quick duel.
- Expected bot response: quick duel behaves exactly as the current `Ситий` support contract specifies; no invented hidden 13-pulse simulation.
- Expected state: Inspiration outside expiry/cursor is not corrupted.
- Verify: result replay is stable.

### 9. Barrel-origin performance occupies the raid music slot

- Preconditions: recruit a party at the Barrel; at least one eventual starting participant has active Inspiration from a performance at the normalized Barrel presence location.
- User action: start the boss fight as normal and view a living Bard’s actions.
- Expected bot response: Inspiration works for its recipients; the Lament button is absent or returns a precise already-contributed explanation.
- Expected state: active boss snapshot has music kind `inspiration` and source performance ids; no global location lock.
- Verify: an unrelated simultaneous raid session is not blocked.

### 10. Different-location Inspiration does not occupy the Barrel slot

- Preconditions: one participant carries active Inspiration from another location; no Barrel-origin recipient in the starting party; Bard cooldown at Barrel ready.
- User action: start raid and inspect actions.
- Expected bot response: `🎻 Заграти журливу баладу` is offered; travelling Inspiration remains on its recipient.
- Expected state: music kind begins `none`.
- Verify: source normalized location controls arbitration, not current location alone.

### 11. Successful Lament

- Preconditions: active boss, free slot, living Bard, ready shared local availability; arrange known deterministic grade and Bard level through test/dev setup.
- User action: press `🎻 Заграти журливу баладу` for the current round.
- Expected bot response: success copy shows exact frozen `-N` and boss-response count; Bard does not attack; raid status/journal shows remaining duration.
- Expected state: slot becomes `lament`, action locks, shared 93-minute Barrel availability starts, no payout/tip/Inspiration is created.
- Verify: activation id/seed/grade/level/reduction/counter persist after process restart.

### 12. Two-Bard race

- Preconditions: two eligible Bards view the same free-slot raid card.
- User action: press Lament from both accounts nearly simultaneously, then repeat the winning callback.
- Expected bot response: exactly one success; loser receives current explanation and can still select another action; repeated winner callback does not repeat copy/effect.
- Expected state: one activation, one cooldown, one action cost, one journal event.
- Verify: no partial cooldown write on loser and no duplicate activation after retry.

### 13. Focused and broad boss responses

- Preconditions: active known Lament; arrange rounds covering focused, broad, and Warrior Taunt redirect.
- User action: complete rounds through the existing test/dev raid flow.
- Expected bot response: every actual target receives `max(0, damageBeforeLament - N)` in the established order; zero is preserved when pre-Lament damage is at most `N`; broad response spends one counter; redirected broad has one actual reduced damage instance.
- Expected state: counter changes once per actual boss response.
- Verify: compare raw/guard/Lament/Ward/Protocol journal fields or DB snapshot when available.

### 14. Last response and session cleanup

- Preconditions: Lament has one boss response remaining.
- User action: complete a round with a boss response, then finish/cancel the raid and create a new one.
- Expected bot response: last response is reduced, then expiry is journaled; new raid has no inherited song.
- Expected state: counter reaches zero exactly once; terminal/new-session cleanup is correct.
- Verify: replaying the terminal callback does not resurrect the effect.

### 15. Remort and source departure

- Preconditions: one recipient has Inspiration; another raid has committed Lament.
- User action: remort the Inspiration recipient; separately kill/remove/remort/change the source Bard after Lament activation.
- Expected bot response: recipient’s Inspiration disappears under reset rules; already committed Lament continues to expiry or raid end.
- Expected state: life-bound status cannot cross remort; raid snapshot remains independent of later source state.
- Verify: no stale payload is applied to the new life.

### 16. Visible remaining wait

- Preconditions: Bard used Lament or performed at Barrel and is still within the shared local availability.
- User action: attempt both a new performance and Lament at relevant surfaces.
- Expected bot response: durable card/message shows canonical remaining wait, not a vague blocker; stale callback alert agrees.
- Expected state: no second action/performance or cooldown extension.
- Verify: copy uses canonical `availableAt` and injected `now` in tests.

### 17. Big Barrel availability and production dev safety

- Preconditions: production-like config with `BIG_BARREL_BROTHER_RAID_ENABLED` disabled and `DEV_GRANT_COMMANDS_ENABLED` set both ways.
- User action: start a normal Bard performance, view raid surfaces and try forged Lament/dev callback/command data.
- Expected bot response: the performance grants Inspiration normally; Lament remains absent/rejected with the Big Barrel surface; the dev command is unavailable.
- Expected state: normal Inspiration writes are independent of payment and environment, while no disabled Big Barrel raid or dev-only mutation is created.
- Verify: command menu/help and handler registry omit the helper in production; an old Lament callback preserves the canonical active raid card instead of replacing it with the disabled test-boss card.

### 18. Exhausted release, remort live guard and stale item callback

- Preconditions: seed an active outside Inspiration plus matching exhausted frozen solo/Training, turn-duel or Big Barrel state; separately start a real unexpired performance, then remort the Bard at the same location.
- User action: inspect `/hero`, terminalize the combat, then restore the remorted Bard's new-life level/class/location eligibility and perform again.
- Expected bot response: `/hero` treats the exhausted combat snapshot as authoritative, release does not extend it, and the new-life performance starts normally.
- Expected state: terminal release deletes only the exhausted matching Inspiration; `Ситий` remains independent; remort expires the old performance live guard but retains performance and reaction audit rows.
- Verify: repeat terminal/release callbacks and an old item-menu callback after source Lament; no second pulse, cooldown, submenu, action replacement or audit-history deletion occurs.

### 19. Shared timed-status presentation

- Preconditions: place active Inspiration beside `Ситий`, Priest blessing, a timed Shynok drink, or equipment attunement on `/hero`; also freeze Inspiration in a durable combat.
- User action: open `/hero` and the relevant combat card/journal.
- Expected bot response: a lone Inspiration reads `✨ Стан: <b>Натхнення</b> ще <b>13 хв</b> — <b>+1</b> до влучання.`; combat uses the same hierarchy with turns. With several `/hero` states, one `<b>Стани:</b>` heading appears and individual rows omit repeated `Стан:`/`Баф:` labels.
- Verify: every line has its authored icon, bold name and duration, escaped dynamic names, and no old `<b>Натхнення</b>:` one-off form; availability/wait notices do not count as active states.

## High-risk regressions

- One status-specific release deletes `ActiveCombatLease` before the other status synchronizes.
- Performance transaction commits audience reactions but not Inspiration, or vice versa.
- Accuracy is added as `+5` probability rather than `+0.05`, bypasses clamps, leaks to crit/damage, or affects the wrong duel actor.
- Multi-target actions pulse the 13-minute clock once per target.
- A location-global performance lookup blocks unrelated raid sessions.
- A rejected second Bard loses the round or receives a cooldown.
- Lament subtracts before the 2.23 focus multiplier and becomes much stronger than displayed.
- Broad retaliation decrements once per target instead of once per boss response.
- An old raid JSON/parser fails rather than normalizing missing Bard state to `none`.
- The 0.3.14 branch silently loses PR #174’s actual-location fixes.

## Post-deploy smoke

After a deliberate isolated-bot refresh for manual QA:

1. Start one low-grade performance with listeners holding less than `1`, `3`, `5`, and `13` gold; verify free Inspiration and that each reaction keyboard hides only the unaffordable tip amounts.
2. Resolve one persistent combat turn and confirm one hybrid minute pulse.
3. Start a local/staging Barrel raid without Barrel-origin Inspiration, commit one Lament, and confirm one reduced boss response.
4. Repeat the callback and confirm no duplicate state.
5. Inspect error logs, active combat leases, malformed cooldown cleanup, and raid JSON parse warnings.

Do not run destructive production resets and do not use the non-production helper against production data.
