## Language split
- Codex-facing workflow docs, task docs, prompts, skills, PR text, commits, and test names should be English when practical.
- Player-facing Telegram copy, lore, item/monster names, news, and release flavor stay Ukrainian.
- Ukrainian copy uses `«»`, Holocene visible dates (`12026`; player-facing period labels/board dates/tournament keys/reward periods must convert Gregorian storage keys before display; release/news/changelog headings use `1YYYY-MM-DD`, e.g. `12026-06-20`, and should be rechecked against the current Kyiv release day and combined release scope before PR-ready handoff), `міт*` with `т`, and `соціяльн*` with `я` where applicable.

## Token-economy rules
- One versioned task per Codex thread.
- Prompts should be short and skill-based: `Use $skill` plus the task doc path.
- Do not paste long repeated instructions into prompts.
- Inspect changed/relevant files before broad scans.
- If a user names a PR, verify its live `base` and `head` before reviewing or continuing; do not assume the current checkout is the PR head.
- Next-task base checks must account for squash merges: fetch `origin/main`, verify expected version/content, and compare tree diffs before stopping on a non-ancestor branch.
- Codex prompt generation follows `docs/ai/CODEX_PROMPT_POLICY.md`: English, `$skill`-based, compact, target-branch aware, and no pasted long rules.
- Second Codex review defaults to `Review mode: short` and changed files only; use `default`/`deep` only for higher-risk PRs.
- Final Codex responses should be short: changed files, behavior changed, tests run, risks, completion status. No tutorial.
- After a versioned task closes, write a compact handoff and start the next task in a new Codex thread.
