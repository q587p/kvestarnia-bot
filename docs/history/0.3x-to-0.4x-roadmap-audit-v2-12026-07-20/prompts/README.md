# Codex prompt order

Use one file in one fresh Codex thread. Prompts are intentionally English and
skill-based.

Recommended order:

1. `raid-chat-delivery-state-hardening.md` on the live raid-chat PR.
2. `raid-chat-deep-review.md` in a separate read-only thread.
3. `docs-roadmap-delta-integration.md` after refreshing the live base.
4. `closed-alpha-closeout-implementation.md`, then its deep review.
5. `party-vs-many-proof-implementation.md`, then its deep review.
6. Continue with group-combat hardening, guild foundation, party expedition,
   and weekly goal only after each preceding acceptance/observation gate exists.
7. Use `old-altar-blessings-implementation.md`, then its deep review, for the
   first restored old promise.
8. Run `nearby-greeting-design-decision.md`, accept one result, update the task
   through `social-economy-task-activation.md`, then use its implementation and
   deep-review prompts.
9. Run the food-catalog and consumable-catalog decision prompts separately,
   activate each task docs-only, then use their implementation/review pairs.
10. Run the take-away prompt and its deep review only after accepted consumable
    uses. Run resale/review, then the recycling-algorithm decision, task
    activation, implementation and deep review.
11. Return to data-gated guild cosmetic progression after real weekly evidence;
    its later version number and dedicated deep review are intentional.
12. After every deep review, open a fresh main-Codex thread with
    `social-economy-review-followup.md` and paste only actionable findings.

Replace angle-bracket placeholders before use. Do not merge/deploy merely because
a prompt finishes; follow the repository workflow and human approval boundary.

Do not combine food, carried consumables, public resale and recycling in one
thread or PR. They have different persistence, balance and rollback boundaries.
