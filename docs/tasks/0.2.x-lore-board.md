# 0.2.x - Lore Board MVP

Draft future content/navigation task. Do not implement inside `0.2.17` Big Barrel Brother Raid MVP.

## Goal

Add a lightweight lore section from the existing `Дошка вістей` surface so players can read short in-world Kvestarnia texts between normal actions.

The feature should feel like tavern folklore and notice-board marginalia, not a heavy wiki.

- `docs/design/kvestarnia-lore-board.md`

- `docs/references/kvestarnia-lore-sources.md`

## Scope

- Inspect the existing notice/news board flow before designing new handlers.
- Add one visible lore entry point from `Дошка вістей`, with final button copy chosen from the task docs.
- Add static typed content for lore categories and entries using the seed docs as the starting set.
- Add render helpers for lore menu, category screen and entry screen.
- Add callback handlers for menu, category, entry, random entry, category-random and back-to-board navigation.
- Keep callback data within Telegram limits and use existing safe callback/edit patterns.
- Add validation for broken `entry.categoryId`, missing entries and random selection from empty lists.
- Add rewardless achievement hooks if lore reading becomes a durable player action; if deliberately out of scope, document why in the task doc and PR body before calling the implementation PR ready.
- Add concise docs for adding new categories and entries.

## Non-goals

- No production implementation in the current `0.2.17` PR.
- No Prisma schema change or migration for the MVP unless a later task explicitly chooses content storage.
- No admin UI, unlock/progress gating, WebView, separate app surface, market, ґільдії, matchmaking or monetization.
- No rewrite of the existing `Дошка вістей` flow.
- No changes to Big Barrel Brother, party/raid sessions, combat, rewards, XP/gold, loot, remort or passage search behavior.
- No exact future rewards, hidden odds or roadmap promises in player-facing copy.

## Acceptance Criteria

- The notice-board surface has a lore button and existing board buttons still work.
- Lore menu shows all categories from the content seed.
- Category screens list only entries from that category and offer category-random navigation.
- Entry screens show title, source, body, category position and safe navigation buttons.
- Random entry never returns `undefined` when content exists.
- Invalid category/entry callbacks do not throw and return a short in-world fallback.
- Callback data stays within 64 bytes.
- Player-facing copy follows `docs/CONTENT_STYLE_GUIDE.md`, including `Квестарня`, `соціяльн*`, `мітолог*`, `ґільдії`, Ukrainian `«»` quotes and no separate app-surface promise.
- Achievement handling is implemented or explicitly documented as intentionally deferred for this low-stakes reading surface.

## Focused Tests

- Content validation: every entry category exists, ids are unique, entry bodies are non-empty.
- Callback-data tests: every lore callback is at most 64 bytes.
- Presenter/keyboard tests for menu, category and entry screens.
- Board keyboard test proving the lore button is present without removing existing buttons.
- Handler tests for menu/category/entry/random/back flows and invalid ids.
- Achievement tests if the implementation records lore-reading milestones.

## Manual Telegram QA

1. Open `Дошка вістей`; verify the lore button appears and existing board navigation still works.
2. Open lore menu; verify the intro and all categories fit one mobile screen.
3. Open each category; verify entries belong to that category and back buttons work.
4. Open several entries; verify source/body/category position render safely.
5. Tap random lore several times; verify no empty or broken result.
6. Replay old/stale lore callbacks after a deploy; verify no crash or spinner hang.
7. Return to `Дошка вістей`; verify the original board card is restored through the existing flow.
8. If achievements are included, read the first lore entry and verify the rewardless achievement unlock/recalc path.
