# 0.2.7 — Player Abilities MVP

## Goal

Ship the first narrow player ability catalog: one class ability per active class, one race ability per active onboarding race, and combat runtime support for class and race actions in ordinary persistent fights, training and turn-based duels.

## Scope

- Add typed class/race ability definitions with stable ids, Ukrainian labels, target scopes, costs, cooldowns, recipes and tags.
- Add a distinct player `race` combat action alongside `skill`.
- Refresh selected class skills into group-ready abilities:
  - Mage, Varenyk-mancer, Bureaucramancer, Bard, Ranger and Kharakternyk affect all living enemies.
  - Varenyk-mancer, Bard and Priest carry ally/self support metadata with current solo fallback to the hero.
- Add active race abilities for every active onboarding race:
  - Людисько: `ability.race.practical-improvisation`
  - Гном: `ability.race.low-center-of-gravity`
  - Ельф: `ability.race.offended-precision`
  - Бісини: `ability.race.margin-note`
  - Дрантогор: `ability.race.step-through-the-border`
  - Домовик: `ability.race.under-stove-stash`
  - Русалка сухопутна: `ability.race.dry-tide`
  - Орк-інтелігент: `ability.race.peer-reviewed-smash`
  - Мольфарська душа: `ability.race.fog-amulet`
- Keep deprecated `race.kharakternyk` compatibility explicit: it has no race button; active characters rely on `class.kharakternyk`.
- Store ability source, target scopes and per-target enemy/ally results in combat summaries for replay.

## Non-goals

- No party/raid runtime.
- No quick-duel formula rewrite, wagers, ratings, tournaments or PvP reward-power expansion.
- Turn-based duels and training doppelganger player turns should reflect the current class/race action catalog; future title abilities should plug into the same visible action surfaces in a separate scoped slice.
- No new monsters, loot, economy, Yeger, item or remort systems.
- No schema migration; combat JSON remains backward compatible.
- No multi-skill loadout UI.

## Acceptance Criteria

- Race and class ability availability is server-authoritative.
- Unavailable class/race ability attempts are no-ops: no turn advance, mana spend, cooldown tick, monster response or reward/progress mutation.
- Class and race cooldowns use ability ids and do not collide; legacy `cooldowns.skill` remains readable for class skills.
- AoE abilities hit each living enemy once without double-hitting the primary enemy.
- Ally scopes degrade to the acting hero until party runtime exists.
- Persistent fight, training and turn-based duel keyboards show compact class and race ability buttons only when available.
- Telegram copy is compact Ukrainian and never exposes raw recipe keys.

## Focused Tests

- Catalog tests for class/race coverage, deprecated race behavior, duplicate ids, supported recipes, bounded costs/cooldowns and group-ready count requirements.
- Combat tests for race cooldown independence, support-only race fallback, all-enemies race damage and refreshed class cooldown/cost expectations.
- Callback tests for persistent fight, training and turn-based duel `race` turn actions.
- Keyboard/presenter tests for compact race buttons, refreshed class labels, distinct icons, cooldown names and replayed journal summaries.
- Simulator tests for separate class/race player ability usage, AoE enemy-hit counts, ally-support counts and aggressive race-action selection.

## Manual Telegram QA

1. Start Nyz fights for each active onboarding race and verify the race ability button label.
2. Use each race ability once; verify mana, cooldown and result copy.
3. Use each refreshed class ability and verify single/enemy-group/support behavior.
4. Try class and race abilities while on cooldown and without enough mana; verify the card refreshes without spending a turn.
5. Verify attack, defend and flee still work.
6. Use a two-enemy threat fight and verify AoE abilities hit each living enemy once.
7. Use support abilities in solo/training and verify they only claim hero fallback behavior.
8. Verify training doppelganger accepts player race ability.
9. Reopen old fight journals/results and verify they remain readable.
10. Verify turn-based duel screens expose class/race actions when available and hide them while mana/cooldown rules block them.
11. Verify quick duel remains instant and does not gain turn-action buttons.
