# 0.1.17 — Instant Duel Polish

Status: Implemented
Type: Versioned implementation task

## Goal

Polish the shipped quick duel into `⚡ Миттєва дуель` with better invite sharing, fairer progression normalization, canonical HP/mana sync, and replay-safe result snapshots.

## Scope

- Rename the player-facing quick duel mode to `⚡ Миттєва дуель` and explain that the result appears immediately after consent.
- Add 13 deterministic forwardable invite variants plus owner-only `🎲 Інший текст` rotation that keeps the same token, URL, expiry, mode and challenge state.
- Route duel create, rematch and accept resource checks through the canonical lazy resource sync path with persistence and optimistic conflict fallback.
- Add a small capped readiness penalty based on fresh HP/mana ratios so resource warnings matter mechanically without deciding the duel by themselves.
- Normalize only progression-derived level/remort budget for instant duel resolution while keeping each participant's race, class, title, equipment and manatky effects.
- Store compact participant snapshots, balance version and audit fields in `resultJson` for new resolved duels while keeping old result JSON readable.
- Prepare domain helpers for future `duel_turnbased_<token>` balance reuse without shipping turn-based duel runtime.

## Non-goals

- No tournaments, wagers, item loss, economy rewards, rating power or quest progress from duels.
- No full turn-based PvP runtime.
- No schema migration; result payload expansion stays inside existing JSON.
- No broad combat, equipment or remort refactor.

## Acceptance criteria

- The current duel is consistently called `⚡ Миттєва дуель` in relevant player-facing surfaces.
- A forwardable invite has one of 13 variants, the same deep link, a mode line and a qualitative fairness line.
- `🎲 Інший текст` changes only invite copy, is owner-only, does not repeat immediately and does not mutate challenge state or expiry.
- Freshly recovered players do not receive stale HP/mana warnings, and recipient warnings are based on the recipient's synced snapshot.
- Duel resource checks use and persist the canonical resource-sync path, including optimistic conflict fallback.
- Resource warnings correspond to a small capped readiness effect in instant-duel math.
- Level/remort progression is normalized temporarily while identity and equipment effects remain personal.
- Raw level/remort gaps cannot leak back into quick score after normalization.
- New results freeze replay-facing participant/balance snapshots; old results remain readable.
- `npm run check` passes or a concrete blocker is named.

## Manual Telegram QA

- Preconditions: two level 3+ characters, one with partial HP/mana and one fully recovered after passive regeneration.
- User action: create a duel invite from the Fighting Corner, forward the invite, press `🎲 Інший текст` as owner and as another user.
- Expected bot response: owner sees only invite copy change with the same link; bystander gets a short callback answer and no edit.
- User action: accept an invite with full resources and with partial resources.
- Expected bot response: full resources proceed to confirmation without warning; partial resources show the correct participant's warning and then resolve after explicit confirmation.
- User action: replay an old resolved card after renaming or changing equipment.
- Expected state: the displayed participant names/levels come from the stored result snapshot, not current character state.
