# 0.1.21 — Combat Action Foundation

Target version: `0.1.21`.

This task implements only the selected package slice from `tasks/combat-action-foundation.md`, adapted to the current `0.1.20` branch. The package was treated as a design proposal, not trusted production input.

Follow-up included in the same `0.1.21` branch by explicit human request: the contextual monster variants and combat barks package tasks now import the 93-monster roster proposal into the current `MonsterContent` shape and add runtime support, context profiles and authored barks for all 93 monsters.

## Goal

Create a narrow server-authoritative combat action foundation that can support more varied future abilities without forking combat formulas.

The shipped behavior should:

- keep current attack, class skill and flee behavior compatible;
- add a basic defend action to solo fights, training fights and turn-based duels;
- move class skill cooldown state toward ability-keyed cooldowns while loading legacy `cooldowns.skill`;
- ensure unavailable skills do not spend mana, advance turns, tick cooldowns, trigger monster actions or advance RNG;
- add a short persistent combat turn deadline so active solo/training battle screens do not wait forever.
- freeze a Kyiv-local combat context snapshot at persistent fight start and use it for small monster stat texture;
- add deterministic, replay-safe monster barks to persistent monster fights.

## Scope

- `src/domain/combat/` action registry, state shape, cooldown normalization and defend semantics.
- Existing PvE combat adapter and turn-based duel resolver.
- Persistent solo and training service turn handling, including 23-second lazy auto-attack when the player returns to the battle screen or presses an expired combat button.
- Telegram callback parsers, keyboards and presenters for the new defend action and no-op unavailable-skill copy.
- Focused tests for domain, bot callbacks/keyboards/presenters and services.
- Content/domain/presenter/service/repository coverage for contextual monster snapshots and bark replay.

## Non-goals

- No race ability catalog.
- No signature/title ability catalog.
- No monster ability catalog.
- No monster ability catalog or loadout extension; this slice imports the 93 monster identities/descriptions/tags plus context and bark data only.
- No consumable/item active ability system.
- No economy, reward, loot, quest, trading, wager, rating or tournament changes.
- No schema migration in this slice.
- No broad combat coefficient rewrite.

## Behavior decisions

- Ability callbacks remain compact and server-authoritative. Telegram sends only the action key; mana, cooldowns, damage and result stay server-side.
- Current class actions keep their current labels and approximate damage. Their cooldown is keyed by ability id and lasts for exactly one subsequent own committed action in this foundation slice.
- Legacy `cooldowns.skill` is accepted and normalized into the new ability-keyed cooldown map.
- `🛡 Захищатися` reduces incoming damage for the current round and may produce a small counter in PvE. Repeated defend attempts fatigue the stance so it cannot be the best infinite loop.
- In hidden-choice turn-based duels, defend applies a deterministic same-round incoming damage reduction. It does not expose hidden choices before the round resolves.
- Unavailable skill attempts are no-ops. The player sees a concise reason and keeps the same turn.
- Persistent solo/training combat stores `turnExpiresAt` inside combat state. If the player is on the battle screen or presses an expired combat callback after the deadline, the service first commits a basic auto-attack for the old turn and then returns the canonical current state. Side surfaces such as hero/inventory/manatky do not advance the combat turn by being opened.
- Persistent solo fights build and store a `Europe/Kyiv` context snapshot when the combat session starts. The snapshot is never recomputed on resume, turn callback or deadline catch-up.
- Context applies at most two authored traits and small capped stat modifiers. It never changes monster eligibility, Yeger matching, XP, gold, loot or authored monster level.
- Monster barks are selected from frozen deterministic state and stored by bark id in turn summaries. Replayed cards render the stored line; they do not reroll.

## Acceptance criteria

- Existing PvE and turn-based duel combat paths share the same primitive for attack/class skill resource/cooldown behavior.
- Attack, defend, class skill and flee parse safely in persistent and training callbacks.
- Turn-based duel callbacks support defend with payloads under Telegram limits.
- Unavailable skills do not mutate state or advance RNG.
- Old combat state with `cooldowns.skill` remains readable.
- Persistent solo/training fights get a 23-second turn deadline on new turns.
- Expired persistent/training turns auto-attack only when the player touches the battle surface, not when opening unrelated safe side surfaces.
- Player-facing copy stays Ukrainian and concise.
- The 93-monster content roster has a context profile and exactly five authored bark entries per monster: solo engage, party engage, early-turn, first-ability and hurt.

- Turn-based duel domain tests for unavailable skill queue rejection and defend mitigation in hidden rounds.
- Callback tests for defend action payloads.
- Keyboard/presenter tests for defend buttons and no-op skill copy.
- Service tests for persistent combat no-op unavailable skill and expired-turn auto-attack.
- Content/domain tests for current-roster context and five-bark coverage, Kyiv snapshot boundaries, starter flavor-only context and replay-safe bark emission.
- Repository/presenter/service tests for storing, restoring and rendering context and bark state without recomputation.

## Manual Telegram QA

1. Start `/fight`, wait past the deadline, press a combat action and verify the old turn resolves as a basic attack.
2. Start `/fight`, open `/hero` or manatky after the deadline and verify the turn does not advance from the side surface.
3. Press a class skill without mana or while on cooldown and verify the turn stays the same.
4. Use `🛡 Захищатися` in `/fight` and `/spar`; verify the battle continues and damage is reduced.
5. Use `🛡 Захищатися` in a turn-based duel; verify it is queued privately and resolved only with the round.
6. Start a persistent monster fight around different Kyiv day phases and verify the first card can show a short contextual cue while rewards/eligibility stay unchanged.
7. Let a monster take two actions and verify at least one short direct bark appears by the second action, then replay the old card and verify the same line stays stable.
