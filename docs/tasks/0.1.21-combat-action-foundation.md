# 0.1.21 — Combat Action Foundation

Target version: `0.1.21`.

This task implements only the selected package slice from `tasks/combat-action-foundation.md`, adapted to the current `0.1.20` branch. The package was treated as a design proposal, not trusted production input.

Follow-up included in the same `0.1.21` branch by explicit human request: the contextual monster variants and combat barks package tasks now import the 93-monster roster proposal into the current `MonsterContent` shape and add runtime support, context profiles and authored barks for all 93 monsters.

## Goal

Create a narrow server-authoritative combat action foundation that can support more varied future abilities without forking combat formulas.

The shipped behavior should:

- keep current attack, class skill and flee behavior compatible;
- add a basic defend action to solo fights, training fights and turn-based duels;
- move class skill cooldown state toward ability-keyed cooldowns while loading legacy `cooldowns.skill`;
- ensure unavailable skills do not spend mana, advance turns, tick cooldowns, trigger monster actions or advance RNG;
- add a short persistent combat turn deadline so active solo/training battle screens do not wait forever.
- freeze a Kyiv-local combat context snapshot at persistent fight start and use it for small monster stat texture;
- add deterministic, replay-safe monster barks to persistent monster fights.
- split persistent fight presentation into a one-time battle intro and a compact active turn card that visibly explains the turn timeout.

## Scope

- `src/domain/combat/` action registry, state shape, cooldown normalization and defend semantics.
- Existing PvE combat adapter and turn-based duel resolver.
- Persistent solo and training service turn handling, including 23-second scheduled timeout handling with active-card edit, restart/race-safe lazy catch-up when the player returns to the battle screen or presses an expired combat button, repeated scheduler auto-attacks and repeated skip-mode lazy catch-up.
- Persistent fight origin tracking for ordinary `Низ`, Adventure Choice handoff and Yeger handoff fights.
- Telegram callback parsers, keyboards and presenters for the new defend action and no-op unavailable-skill copy.
- Focused tests for domain, bot callbacks/keyboards/presenters and services.
- Content/domain/presenter/service/repository coverage for contextual monster snapshots and bark replay.

## Non-goals

- No race ability catalog.
- No signature/title ability catalog.
- No monster ability catalog.
- No monster ability catalog or loadout extension; this slice imports the 93 monster identities/descriptions/tags plus context and bark data only.
- No consumable/item active ability system.
- No economy, reward, loot, quest, trading, wager, rating or tournament changes.
- Combat action runtime state itself stays JSON-backed; the follow-up combat balance analytics slice adds narrow append-only Prisma analytics tables through `20260621100000_add_combat_balance_analytics`.
- No broad combat coefficient rewrite.

## Behavior decisions

- Ability callbacks remain compact and server-authoritative. Telegram sends only the action key; mana, cooldowns, damage and result stay server-side.
- Current class actions keep their current labels and approximate damage. Their cooldown is keyed by ability id and lasts for exactly one subsequent own committed action in this foundation slice.
- Legacy `cooldowns.skill` is accepted and normalized into the new ability-keyed cooldown map.
- `🛡 Захищатися` reduces incoming damage for the current round and may produce a small counter in PvE. Repeated defend attempts fatigue the stance so it cannot be the best infinite loop.
- In hidden-choice turn-based duels, defend applies a deterministic same-round incoming damage reduction. It does not expose hidden choices before the round resolves.
- Unavailable skill attempts are no-ops. The player sees a concise reason and keeps the same turn.
- Persistent solo/training combat stores `turnExpiresAt` inside combat state. Active battle cards also store a Telegram message reference in combat state, so an in-process scheduler can best-effort commit the canonical basic auto-attack after the deadline and edit the active card. If the scheduler misses the turn because of restart, delivery failure or a callback race, battle-surface restore/callback paths commit the same canonical action before returning the current state; skip-mode lazy catch-up keeps using the existing skipped hero action.
- Persistent solo fights build and store a `Europe/Kyiv` context snapshot when the combat session starts. The snapshot is never recomputed on resume, turn callback or deadline catch-up.
- Context applies at most two authored traits and small capped stat modifiers. It never changes monster eligibility, Yeger matching, XP, gold, loot or authored monster level.
- Monster barks are selected from frozen deterministic state and stored by bark id in turn summaries. Replayed cards render the stored line; they do not reroll.
- Persistent fight result navigation is based on the stored origin location. `Новий бій` is shown only for fights that started in `Низ`; non-Низ handoff fights return to their origin surface.
- Newly started persistent fights send a separate intro card with the character header, no-reward warning, optional tip and opponent. The active battle card below it is the only card with action buttons and updates each turn.
- Active persistent fight cards show the current `23` second turn rule directly. Monster barks render as Telegram blockquotes.
- Active persistent fight cards keep the timeout note visually separated, address the character by name before the action prompt and show a replay-safe notice when the previous overdue turn became an auto-attack or a skipped hero action.
- Older fight and hunt reward templates no longer append generic `Наступний крок` prompts.
- Follow-up hardening keeps current `CombatState` JSON lossless through Prisma mapping for origin, guard, cooldown, skip-summary, debug/equipment, context and bark fields; repeated turn-based duel defends use the next fatigue tier; failed flee monster responses advance deterministic bark state.
- Scheduler hardening keeps the persisted active-card message reference through resolver/service transitions, records a persisted timeout streak for solo/training fights, repeats scheduler auto-attacks or skip-mode lazy skips for unattended turns until combat ends or hard session expiry is reached, and never extends hard session expiry from scheduler/lazy timeout actions.
- Follow-up analytics adds opt-in `COMBAT_BALANCE_ANALYTICS_ENABLED` collection for completed PvE solo/training combats: one idempotent battle row plus ability usage rows for class/remort, monster/source and ability reports. It stores no Telegram ids/usernames/display names in reports, keeps manual and timeout action origins separate, defaults ability reports to manual choices, can include all committed actions on demand and never blocks combat completion.
- Training doppelganger scheduled/lazy timeout terminal wins and losses claim the same XP reward and recovery cooldown as manual terminal actions; replay remains idempotent and hard-expired sessions remain non-rewarding.

## Acceptance criteria

- Existing PvE and turn-based duel combat paths share the same primitive for attack/class skill resource/cooldown behavior.
- Attack, defend, class skill and flee parse safely in persistent and training callbacks.
- Turn-based duel callbacks support defend with payloads under Telegram limits.
- Unavailable skills do not mutate state or advance RNG.
- Old combat state with `cooldowns.skill` remains readable.
- Persistent solo/training fights get a 23-second turn deadline on new turns.
- Expired persistent/training turns are processed by an in-process timeout scheduler that edits the active card when Telegram delivery succeeds.
- Battle-surface restore/callback paths remain a lazy fallback for restart/delivery/race cases; safe side-surface redirects after the deadline use the same overdue-turn CAS path and do not duplicate an old turn.
- Player-facing copy stays Ukrainian and concise.
- The 93-monster content roster has a context profile and exactly five authored bark entries per monster: solo engage, party engage, early-turn, first-ability and hurt.
- Fight handoffs remember their origin location and terminal cards route back there instead of always pointing to `Низ`.
- Started persistent fights produce a separate non-interactive intro plus one active battle card with buttons, visible timeout copy and blockquoted monster barks.
- Active follow-up cards make timeout outcomes visible: overdue catch-up says whether the previous unattended turn became a basic attack or a skipped hero action.
- Fight/hunt result templates do not append generic next-step command prompts.
- Current-version combat JSON fields survive repository create/update/read mapping without unsafe blanket casts, while legacy `cooldowns.skill` rows remain readable.
- Completed PvE combat analytics writes are idempotent by combat id, include class/level/remort, monster/source/outcome/action totals and ability usage slices, and skip old in-flight combats without a frozen analytics snapshot rather than guessing historical totals.
- Combat balance analytics schema v1 is backed by the `combat_balance_battles` and `combat_balance_ability_usages` tables. Collection is disabled unless `COMBAT_BALANCE_ANALYTICS_ENABLED` is truthy.
- Combat balance reports separate manual actions from `timeout-auto-attack` and `timeout-skip`; default ability usage reports are manual-only so automatic basic attacks do not look like player-selected attacks.
- Repeated unattended solo/training turns keep resolving the existing canonical auto-action until combat ends or hard session expiry is reached. Auto-resolved victories can grant normal rewards.
- Repeated hidden-round duel defends progress through fatigue tiers and non-defend duel actions clear the streak.
- Failed flee responses count as monster actions for mandatory early bark state; successful flee does not.

## Manual Telegram QA

1. Start `/fight`, wait past the deadline on the active battle card without pressing anything, and verify the bot updates the card after the timeout with a basic auto-attack result.
2. Press an old combat action after the scheduled update and verify it shows the current state without applying a second old-turn action.
3. Start `/fight`, open `/hero` or manatky after the deadline and verify that if the safe side-surface redirect catches the overdue turn first, it commits the intended skipped hero action and does not duplicate the old turn.
4. Press a class skill without mana or while on cooldown and verify the turn stays the same.
5. Use `🛡 Захищатися` in `/fight` and `/spar`; verify the battle continues and damage is reduced.
6. Use `🛡 Захищатися` in a turn-based duel; verify it is queued privately and resolved only with the round.
7. Start a persistent monster fight around different Kyiv day phases and verify the first card can show a short contextual cue while rewards/eligibility stay unchanged.
8. Let a monster take two actions and verify at least one short direct bark appears by the second action, then replay the old card and verify the same line stays stable.
9. Trigger an Adventure Choice complication fight and verify the terminal card returns to the quest table without a `Новий бій` button; finish a `Низ` fight and verify `Новий бій` is still present.
10. Start a fresh persistent fight and verify Telegram shows two messages: a static intro without buttons and an active battle card with buttons, HP/mana, turn number and the visible timeout note.
11. Let one solo or training fight miss three consecutive scheduled turns and verify each overdue turn remains an auto-attack unless the hard session expiry has already passed.
