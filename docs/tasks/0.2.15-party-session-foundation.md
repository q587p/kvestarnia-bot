# 0.2.15 - Party Session Foundation

## Goal

Ship a restart-safe, concurrency-safe temporary party recruiting foundation that later party combat and raids can reuse, while production Barrel, rewards and solo combat remain unchanged.

## Scope

- Add relational `PartySession` and `PartyParticipant` persistence with one opaque invite token.
- Support one leader, up to seven joiners, capacity `8` and minimum participant metadata `1`.
- Support create, deep-link join/rejoin, nearby private invite, leave, leader cancel, passive expiry and deterministic leader transfer.
- Keep one live recruiting session per leader and one live membership per character through nullable unique live keys.
- Add a disabled-by-default/dev entry point and `PARTY_SESSION_FOUNDATION_ENABLED` feature flag, with dev/manual helpers gated separately from production smoke enablement.
- Add compact `v1:party:` callbacks and `/start party_<token>` support with token-only payloads.
- Add remort cleanup so live party membership is left, transferred or cancelled without orphan live keys.

## Non-goals

- No boss combat, active rounds, HP/mana mutation, combat leases, ready checks, kick, rewards, XP, gold, items, achievements or Senior Barrel Brother content.
- No production level-8 Barrel route and no change to existing solo Barrel behavior.
- No permanent parties, guilds, matchmaking, public roster, group chat requirement, Redis/BullMQ, market or trade.

## Acceptance criteria

- Dev/flagged create returns the canonical live recruiting session and leader membership.
- Copied `/start` deep links join the exact session and replay without duplicate rows.
- Nearby private invites are best-effort and do not roll back the canonical party state.
- Duplicate create/join/leave/cancel and stale buttons replay canonical state.
- Concurrent final-slot joins cannot exceed `8`.
- Leader leave/remort transfers to the earliest joined remaining participant; last participant leave/remort cancels.
- Expiry clears live keys and old links/buttons cannot revive a session.
- Production Barrel rewards, beer access, solo combat and economy remain unchanged.

## Manual Telegram QA

1. Enable dev mode or `PARTY_SESSION_FOUNDATION_ENABLED=true`.
2. Create a party session as account A with `/dev_party`.
3. Copy the `/start` deep link and join as account B.
4. Replay the same link as B; verify no duplicate member.
5. Open `👀 Хто поруч` as A, invite C privately and accept as C.
6. Verify roster shows names, not ids or exact locations.
7. Leave as B; rejoin.
8. Leader A leaves; verify deterministic new leader.
9. Fill to eight accounts or seeded/dev accounts; attempt a ninth join.
10. Restart bot while recruiting; refresh cards.
11. In dev-helper mode, expire through the dev button; replay old links/buttons. With only production smoke enablement, verify that the dev expiry button is not shown and old dev-expiry callbacks do not mutate the party.
12. Disable the flag/dev command; verify normal players cannot create new sessions.
13. Run ordinary Barrel start/complete and beer access smoke.
