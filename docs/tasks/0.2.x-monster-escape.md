# Future Task — Monster Escape Attempts

## Goal

Give selected PvE monsters a bounded ability to attempt escape during combat, so a low-HP or specially authored enemy can leave instead of always fighting to zero. The result must remain explicit, deterministic and readable in the live fight, stored journal and Chronicles.

This is a monster-side combat outcome, not a change to the player's flee action. It should follow the 3+ enemy combat foundation and remain compatible with encounters containing several enemies.

## Scope

- Add an authored/content-level escape capability and a deterministic resolver with injected RNG for tests.
- Define bounded trigger rules, such as an eligible HP band, a per-fight attempt limit/cooldown and monster-specific eligibility; exact values require balance simulation.
- A failed attempt consumes the monster response, records the attempt and leaves the fight active.
- A successful single-enemy escape ends the fight with an explicit monster-escaped reason, not a player win or loss. A multi-enemy escape removes only that enemy; the encounter continues while another enemy remains alive.
- If the last living enemy escapes, settle the fight once as a non-win terminal outcome with no ordinary victory reward.
- Preserve the actor and reason in the live card, stored replay, turn journal and Chronicles so monster escape is not presented as player flee, defeat or timeout.
- Keep rewards, quests and achievements win-safe: no XP, gold, loot or win milestone is granted automatically for an escaped monster unless a later balance/content decision explicitly adds a bounded consolation result.
- Make stale/replayed escape callbacks and settlement idempotent; no escape attempt may run after the fight is terminal.

## Non-goals

- no change to the player's flee chance or flee copy;
- no arbitrary escape for every monster and no unbounded repeated attempts;
- no escape route/overworld chase system;
- no PvP, party or Big Barrel raid escape behavior;
- no automatic partial reward or guaranteed replacement encounter;
- no hidden removal of an enemy from the UI or journal.

## Acceptance criteria

- Existing one-/two-enemy fights without escape capability behave exactly as before.
- Deterministic tests cover eligible/ineligible monsters, trigger threshold, failed attempt, successful single-enemy escape and per-enemy multi-enemy escape.
- A successful last-enemy escape cannot be mistaken for a win, player flee, loss or timeout, and reward settlement remains exactly once.
- A multi-enemy fight can continue after one enemy escapes and ends only when all enemies are defeated or escaped, according to the chosen terminal contract.
- Live combat, stored journal, replay and Chronicles preserve the escaped monster name and outcome reason without exceeding Telegram message limits.
- Balance simulation covers escape frequency, fight length, reward denial and the effect on 3+ enemy pressure before production exposure.
- Any new timer or cooldown has a narrow non-production manual-QA helper and production-registration tests.

## Focused tests

- pure resolver tests with injected RNG and per-fight attempt limits;
- one-enemy and 3+ enemy state/reducer tests for partial and final escape;
- stale callback, terminal replay and reward idempotency tests;
- presenter/journal/Chronicles tests distinguishing monster escape from player flee and timeout;
- regression tests for monsters without the capability and for ordinary wins/losses;
- deterministic balance simulation for escape rate and encounter pressure.

## Manual Telegram QA

- Exercise an eligible monster below its trigger band and observe a failed then successful attempt with controlled QA inputs.
- Confirm a successful single-enemy escape is not rendered as a victory and grants no ordinary win reward.
- In a 3+ encounter, let one monster escape and continue fighting the remaining targets; then test the last-enemy escape.
- Reload the fight and replay stale action/escape callbacks; verify the same terminal result and no duplicate settlement.
- Check live card, stored journal and Chronicles wording for player flee, monster escape and timeout.
