# 0.3.x — Mantok Chest Rarity Distribution

Status: integrated as a retained non-core fix in the active [`0.3.6` release-candidate task](../0.3.6-bureaucramancer-personal-protocol-13b.md). This archived contract is not a separate implementation task.

## Goal

Keep `Дружня Скриня` exciting without allowing a mixed or low-rarity five-item batch to produce high-rarity output too often.

## Contract

- The output still must be strictly better than the five-item input average by Mantok Chest score, must avoid protected items, and must prefer a non-input item when one exists.
- Five inputs with the same `epic` rarity target `epic` output only; they do not promote to `legendary`. A fully `legendary` batch may still target `legendary`.
- A mixed batch uses the average rarity rank of its five units. The fractional part is the base chance of the next rank; current LUCK can add at most five percentage points to that upper-rank chance.
- A uniform `common`, `uncommon` or `rare` batch has a small first-upgrade chance of `8%`, `6%` or `4%`, respectively, plus one percentage point per LUCK above `5`, capped at `25%` total. Uniform common and uncommon batches also retain a separate `0.5%`-scale second-upgrade chance, still bounded below `1%`.
- The selected target rarity is a hard upper bound. If no better-than-average item exists at that target rarity, the selector may fall back only to a lower eligible rarity; it never falls upward into an unrolled higher rarity.
- LUCK is read from the current character snapshot at confirmation time. Completed runs replay their stored output and do not reroll from current luck.
- Authored Charkokovalnia `.plus-1…5` variants now receive a monotonic gold-value calculation from both their resulting rarity and enhancement level. The calculation has a bounded economy envelope, so a common 5-gold base can become a valuable epic `+5` without producing five-digit values; generated Loot Expansion v1 pricing remains source-pack-owned and unchanged.

## Scope and verification

No schema or migration is required. The domain rarity selector, service confirmation path, repository luck snapshot, and replay behavior are covered by focused tests. Run `npm run check` before release handoff.
