# 0.2.x - Lore Board Expansion Backlog

Historical draft for the Lore Board MVP plus future expansion backlog. The runtime MVP shipped in `0.2.18`; do not treat this file as the active implementation prompt.

## Goal

Expand `📖 Перекази` after the MVP so players can read richer in-world Kvestarnia texts about current locations, races, classes, manatky, customs and the wider world around the Korchma without turning the feature into a wiki or reward path.

This is not a wiki, reward path or gameplay requirement. It should feel like tavern folklore and notice-board marginalia.

## Scope

- Preserve the existing `📖 Перекази` entry point, compact callbacks and board return navigation.
- Expand existing short race/class/location entries into fuller lore only when the text still fits Telegram.
- Add a separate future category or entries for the world around Kvestarnia only after the current runtime has matching source-of-truth docs/content.
- Keep the Bestiary as its own runtime surface; do not rebuild a second monster encyclopedia inside Lore Board.
- Add static typed lore content seeded from current lore docs or a new approved source pack.
- Keep source-of-truth references aligned with live content arrays where practical:
  - `src/content/races.ts`
  - `src/content/classes.ts`
  - `src/content/monsters.ts`
  - `src/services/presenceService.ts`
- Add render helpers for lore menu, category screen, entry screen, random entry, empty state and error state.
- Add versioned callback parsing/handlers under `v1:lore:*`.
- Keep callback data within Telegram's 64-byte limit and use existing safe callback/edit patterns.
- Add validation for broken category ids, duplicate ids, canonical refs, missing entries and random selection from empty categories.
- Add concise docs for adding new lore entries and maintaining `canonicalRefs`.

## Achievement Decision

Default: do not add XP, gold, items, combat power or achievement rewards for simply reading lore in the MVP.

Before the implementation PR is called ready, explicitly document this no-achievement decision in its PR body. If a durable rewardless first-read achievement is later desired, add it with normal achievement hooks and tests instead of making lore a hidden reward faucet.

## Non-goals

- No production implementation in the current Lore Board MVP follow-up PR.
- No Prisma schema change or migration for the MVP unless a later task explicitly chooses content storage.
- No admin UI, unlock/progress gating, WebView, separate app surface, market, ґільдії, matchmaking or monetization.
- No rewrite of the existing news-corner or `/news` flow.
- No changes to Big Barrel Brother, party/raid sessions, combat, rewards, XP/gold, loot, remort or passage search behavior.
- No exact future rewards, hidden odds, hidden path ids or combat/drop formulas in player-facing copy.
- No invented playable race/class names outside current runtime content.
- No promise that wider-world lore is playable geography until a future explicit gameplay/content task ships it.

## Acceptance Criteria

- `Дошка корчми` has a `📖 Перекази` button and existing board/news buttons still work.
- Lore menu shows all seed categories:
  - `🏚 Про Квестарню`
  - `🪧 Місцини корчми`
  - `🧝 Раси пригодників`
  - `⚔️ Класи пригодників`
  - `🧌 Бестіарій`
  - `🎒 Манатки`
  - `📜 Звичаї й чутки`
- Category screens list only entries from that category and offer category-random navigation.
- Entry screens show title, source, body, category position and safe navigation buttons.
- `canonicalRefs` validate against current race/class/monster/location/item ids where those registries exist.
- Random entry never returns `undefined` when content exists and empty categories have a safe fallback.
- Invalid lore callbacks do not throw and answer callback queries without spinner hangs.
- Callback data stays within 64 bytes.
- Player-facing copy follows `docs/design/content-style-guide.md`, including `Квестарня`, `соціяльн*`, `мітолог*`, `ґільдії`, Ukrainian `«»` quotes and no separate app-surface promise.

## Focused Tests

- Content validation: category ids exist, entry ids are unique, entry bodies are non-empty.
- Canon validation: `canonicalRefs` match known runtime ids where practical.
- Callback-data tests: every lore callback is at most 64 bytes and uses `v1:lore:*`.
- Presenter/keyboard tests for menu, category, entry, empty and error screens with HTML escaping.
- Board/news-corner keyboard test proving the `📖 Перекази` button is present without removing existing buttons.
- Handler tests for menu/category/entry/random/back flows and invalid ids.
- Regression tests proving `/news` and the news archive still work.

## Manual Telegram QA

1. Open `Дошка корчми`; verify `📖 Перекази` appears and existing board/news navigation still works.
2. Open lore menu; verify intro and categories fit a mobile screen.
3. Open each category; verify entries belong to that category and back buttons work.
4. Open several entries; verify source/body/category position render safely with Telegram HTML.
5. Tap random lore and category-random several times; verify no empty or broken result.
6. Replay old/stale lore callbacks after a restart/deploy; verify no crash or spinner hang.
7. Return to `Дошка корчми`; verify the original board card is restored through the existing flow.
8. Confirm lore reading grants no XP, gold, items, combat power or hidden achievement unless the implementation task explicitly changes the achievement decision.
