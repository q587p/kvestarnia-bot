# 0.2.x - Nearby Greeting Buff

## Goal

Add a tiny opt-in `Хто поруч` social gesture: one adventurer can greet another nearby adventurer and give a small, temporary, low-abuse support bonus.

The intended feel is warm and lightweight: "I saw you, good luck out there", not a new economy faucet or a mandatory buff rotation.

## Scope

- Add a `Хто поруч` action for active same-location adventurers, tentatively `👋 Привітатися`.
- Let the actor choose one visible nearby target and confirm the greeting.
- Apply one small non-combat-breaking target benefit. First candidate to evaluate:
  - recovery-flavored support, e.g. short `+13%` HP regeneration / recovery speed while out of combat.
- Alternative candidates to compare during implementation planning:
  - tiny next-fight morale bonus with no stacking;
  - tiny XP/gold bonus on the next completed ordinary fight, with strict caps;
  - one short luck-style social blessing that is weaker than Priest blessing and cannot stack with it.
- Notify the target privately after durable success.
- Add visible target/actor cooldown rows so players understand why the same greeting is unavailable.

## Guardrails

- Same actor -> same target repeat wait: start from `93 minutes` unless balance review finds a better limit.
- Prefer no direct XP/gold faucet. If XP/gold is chosen, it must be one-shot, capped, non-stackable and excluded from raids, table games, quests and replay rewards.
- No stacking from multiple greeters unless explicitly designed with a very small cap.
- No self-targeting.
- No effect while the target is in active combat, raid, duel, passage search or another blocking flow unless the final design deliberately makes the effect purely out-of-combat.
- No public shame, pressure or social feed spam.
- No requirement to be friends, but use only the existing exact-normalized same-location `Хто поруч` visibility rules.
- No paid power, item movement, gold transfer, quest progress, raid contribution or achievement reward.

## Non-goals

- No new class ability family.
- No replacement for Priest healing/blessing, Bard performance, Rogue interactions or beer rounds.
- No broad reputation/friendship system.
- No guild, party, market, shop, crafting or economy loop.
- No persistent relationship graph beyond the minimum cooldown/status ledger needed for replay safety.

## Acceptance criteria

- Fresh greeting applies exactly one target benefit and one cooldown record.
- Duplicate/replayed/stale callbacks do not duplicate the benefit, cooldown, achievement event or notification.
- Same actor cannot greet the same target again until the repeat wait expires.
- Busy/invalid/no-longer-nearby targets fail with short truthful copy and no mutation.
- Target receives one private notification for fresh success.
- Active `/hero` or relevant status surfaces show the benefit while it is active, if the chosen benefit affects visible stats or recovery.
- Recalculation/achievement coverage includes a rewardless first-greeting achievement decision, or the PR explicitly documents why achievements are deferred.
- `📖 Перекази` is reviewed if the feature changes current social custom lore.

## Focused tests

- Callback parser tests for greeting target/confirm/cancel payloads and Telegram callback limits.
- Service tests for fresh success, duplicate replay, stale target, no-longer-nearby target, self-target block and same actor-target repeat wait.
- Recovery/stat tests if the chosen benefit affects HP regeneration or effective summaries.
- Bot command tests for `Хто поруч` visibility, busy-flow blocking and private target notification.
- Achievement tests for first successful greeting if shipped.
- Production/dev-helper tests if a local `/dev_*` cooldown/status reset helper is added.

## Manual Telegram QA

- With two accounts in the same location, open `👀 Хто поруч`, greet the other account and verify the target receives one private notification.
- Press the same confirm callback twice; verify no duplicate benefit or notification.
- Try greeting the same target again before the wait expires; verify the blocked copy names the wait clearly.
- Move the target away before confirm; verify the stale/no-longer-nearby card does not mutate state.
- Put the target in active combat/raid/duel/search; verify the chosen blocking behavior.
- Verify `/hero` or the relevant card shows and later drops the benefit if it is visible.
