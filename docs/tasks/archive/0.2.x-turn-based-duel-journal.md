# 0.2.x - Turn-Based Duel Journal

Status: draft follow-up, not active. Do not implement this inside `0.2.31`.

## Goal

Add a replay-safe `📜 Журнал дуелі` for turn-based duels so players can review each resolved round after it happens, similar to ordinary fight and Big Barrel Brother raid journals.

## Context

Turn-based duels already store the latest resolved round for active/result cards, but they do not expose a paginated journal route. A proper journal needs its own callbacks, presenter and keyboard rules so old cards, terminal duels and refreshed private cards can replay stored rounds without leaking unresolved private choices.

## Scope

- Persist or expose enough resolved-round history for turn-based duels to page through every completed round.
- Add compact duel-journal callbacks with token, page and version/state safety.
- Add `📜 Журнал дуелі` buttons to active/result turn-based duel cards when at least one round is resolved.
- Render one round per page with participant names, action labels, damage/support/healing, fumbles, surrender and terminal outcome lines.
- Keep unread/unresolved pending choices private: never show the other participant's queued action before the round resolves.
- Support stale/result replay from old Telegram duel cards without advancing turns or mutating duel state.
- Keep quick duels instant and without journals unless a later task explicitly designs a separate result archive.
- Use existing combat action/effect presenter helpers where practical so gear-action names stay readable.

## Non-goals

- No tournament rewards.
- No duel rebalance.
- No wagers, item loss, loot, gold faucet or player-funded rewards.
- No new combat actions or Mantok ability families.
- No schema migration unless the activated implementation proves stored state cannot retain historical rounds safely.
- No public feed of duel round details.

## Acceptance criteria

- Every resolved turn-based duel round can be opened from the journal in order.
- Active duels show only resolved past rounds; current hidden choices stay hidden.
- Terminal turn-based duels keep their journal accessible from the result card.
- Old/stale journal callbacks replay canonical stored data and do not mutate HP, mana, cooldowns, RNG, achievements or turn state.
- Journal pages remain short enough for Telegram mobile reading.
- Quick duel behavior remains unchanged.

## Focused tests when activated

- Domain/service tests prove resolved round history is stored/replayed in order.
- Callback tests cover compact journal payload parsing and invalid/stale tokens.
- Presenter tests cover attack, defend, class/race action, gear action, support/heal, fumble, surrender and terminal pages.
- Command tests cover active-card and result-card journal buttons.
- Privacy tests prove pending unresolved choices are not shown to the other participant or spectators.
- `npm run typecheck`
- `npm run check`

## Manual Telegram QA when activated

- Start a turn-based duel between two accounts.
- Resolve at least three rounds using attack, defend and one class/race or gear action.
- Open `📜 Журнал дуелі` from both participants' cards and verify each page matches the visible resolved history.
- During a round where only one participant has acted, verify the journal does not reveal the queued action.
- Finish the duel and verify the result card still opens the same journal.
- Press old journal page callbacks after more rounds resolve and after terminal result; verify pages replay without advancing the duel.
