# 0.3.x - Rogue Reputation and Location Risk

## Goal

Give bounded Rogue theft a durable social cost without adding public shame or item theft.

## Scope

- Add a small reputation / rumor ledger for Rogue pickpocket consequences.
- Apply reputation loss only on fresh Rogue attempts, not replay.
- Scale consequences by outcome:
  - noticed success;
  - noticed failure;
  - caught badly.
- Scale by location exposure:
  - high: public Korchma social hubs;
  - medium: ordinary Korchma side spaces;
  - low: Nyz, passages, yard/outside edges.
- Show private player-facing copy that reputation changed because people noticed or rumors spread.
- Keep exact math out of pre-commit copy.
- Decide remort behavior explicitly.

## Non-goals

- No item theft.
- No public shame feed.
- No guard/jail system.
- No automatic PvP retaliation expansion.
- No market/trade reputation integration yet.

## Acceptance criteria

- Reputation mutation is durable and replay-safe.
- Duplicate Rogue callbacks do not apply reputation twice.
- Location exposure is based on canonical location ids.
- Public places hurt more than low-witness spaces.
- Remort behavior is tested and documented.

## Focused tests

- repository/service tests for each outcome tier;
- location exposure tests;
- duplicate replay tests;
- remort/reset behavior tests;
- presenter copy tests;
- `npm run check`.

## Manual Telegram QA

- Try Rogue theft in Shynok/hall.
- Try Rogue theft in lower-exposure location if available.
- Verify private consequence copy.
- Verify no public feed row.
