# 0.2.x - Raid In-Game Chat

Status: superseded by the active [`0.3.15` task](../0.3.15-raid-chat-mvp.md). Do not implement this draft.

## Goal

Add a small in-game coordination chat for active raid participants so a player can write one short message to the raid party and other joined participants can answer from inside the bot flow.

This is for raid coordination and table-talk flavor, not a global chat system.

## Player-facing shape

- Active raid cards can expose a compact `💬 Чат рейду` / `💬 Написати` surface for joined participants.
- A participant can send a short message that is delivered to the other current raid participants through bot messages or refreshed raid chat cards.
- Participants can reply in the same raid context without leaving the game flow.
- The latest few messages can be reopened from the raid card, with author display names and timestamps.
- Non-participants opening a raid link can see the raid result/state but cannot read or write raid chat.

## Scope

- Big Barrel Brother is the first target surface.
- Store messages durably enough to survive bot restart and replay current raid chat history.
- Limit message length, message count shown per page, and send frequency.
- Use existing character display names, not Telegram usernames or raw user ids.
- Keep chat scoped to one `PartySession` / `PartyBossSession` lineage.
- Expire or archive chat with the raid; result cards may show a short final transcript link only if privacy rules are satisfied.
- Add focused command/callback/presenter/repository tests.

## Non-goals

- No global Kvestarnia chat.
- No cross-raid chat, guild chat, markets, trading, matchmaking or public channels.
- No arbitrary Telegram group bridging.
- No anonymous posting.
- No image, file, voice, sticker or external link handling in the first slice.
- No moderation dashboard beyond simple abuse guards and operator-readable logs already available.
- No gameplay rewards, achievements, XP, gold, loot, manatky or raid contribution for sending messages.

## Safety and privacy invariants

- Only joined raid participants can read or write active raid chat.
- A stale participant who left, remorted out, failed eligibility, or is no longer in the raid cannot keep posting from old buttons.
- Chat messages must not expose Telegram ids, chat ids, private usernames, invite tokens or callback payloads.
- Rate limits must be per character and per raid, with a clear cooldown message.
- Messages must be HTML-escaped and length-limited before storage/presentation.
- Deleted/expired/terminal raid links must not reveal chat history to unrelated viewers.
- Chat callbacks must be replay-safe and non-mutating when stale.
- Bot restarts must not duplicate sent chat messages.

## Implementation notes

- Prefer a dedicated repository boundary for raid chat messages instead of embedding mutable chat arrays in the boss state JSON.
- Keep Telegram adapter logic in `src/bot/`; domain/service code should work with plain message records.
- Consider whether delivery should be pull-only (`💬 Чат рейду`) at first, or also push private notifications to participants.
- If push delivery ships, dedupe delivery per message and participant.
- Add a non-production `/dev_*` helper only if the final implementation introduces a timer, cooldown, pending input session or other manual-QA gate that needs acceleration.

## Focused tests

- Participant can open chat and send a short message to the current raid.
- Other participants can read the message and reply.
- Non-participant cannot read or write chat from a raid link.
- Former participant / stale callback cannot write after leaving, remort cleanup or terminal settlement.
- Rate limit blocks mutation and returns clear copy.
- Long/HTML-looking messages are escaped and clipped safely.
- Restart/replay does not duplicate delivered messages.
- Terminal result cards keep chat access consistent with privacy rules.

## Manual Telegram QA

1. Start a Big Barrel Brother raid with at least two accounts.
2. Account A sends a short raid-chat message.
3. Account B opens chat, sees Account A's character display name and message, and replies.
4. Account C who is not in the raid opens the raid link and cannot read or write chat.
5. Try stale buttons after the raid ends and after a participant leaves; verify no mutation.
6. Try a long message and HTML-looking text; verify it renders safely and compactly.
