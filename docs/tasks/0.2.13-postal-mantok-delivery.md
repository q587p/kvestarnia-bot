# 0.2.13 - Postal Manatka Delivery MVP

## Goal

Ship `📮 Пошта Квестарні`: a narrow paid courier delivery that lets a sender offer a bounded package of eligible manatky to a known recipient without requiring same-location presence. The recipient must explicitly accept before items move.

## Scope

- Known recipients come from previous completed item-transfer history, accepted/active/resolved duel history, or explicit Bard performance reactions (`applauded`/`tipped`) in either direction.
- A postal package may contain 1 to 5 distinct `itemId` stack types.
- Each selected type may contain 1 to 93 units, capped by currently owned, eligible, unreserved quantity.
- Package editing uses server-owned draft tokens; callback data never encodes item lists.
- Confirm turns a draft into one live pending postal reservation per sender, reserving every selected `itemId`.
- Acceptance is all-or-nothing and replay-safe: every line moves once, or none moves.
- Delivery fee is charged only when the recipient accepts, in the same transaction as item movement.
- Fee formula is internal and tested: `13 + 3 * selected type count + selected unit count`.
- Decline, cancel, expiry and stale callbacks release or replay the canonical postal state.
- Existing one-unit same-location Safe Gifting keeps its old flow.

## Non-goals

- No item-for-item trade.
- No gold transfer between players.
- No market, auction, buyback, resale, royalties or dynamic pricing.
- No anonymous inbox, public recipient search, exact-location disclosure or online-status leak.
- No package larger than 5 distinct manatka types.
- No per-type quantity above 93.
- No unbounded cart, bulk dump or send-all shortcut.
- No XP, quest progress, power bonus, achievement reward, donor perk, party/raid/guild/combat work or Mini App UI.

## Acceptance criteria

- Sender opens `📮 Пошта Квестарні`, sees known recipients from explicit social history, and recipient rows do not reveal current location or online status.
- Sender can select 1..5 eligible owned manatka types and 1..93 units per selected type.
- Preview shows recipient, each line, selected quantity, exact delivery fee and expiry.
- Confirm rejects empty packages, duplicate item ids, more than 5 types, quantity 0/94, over-owned quantity, reserved, equipped, protected, priceless, story/memory/sentimental/soulbound/trade-blocked or drifted stacks.
- Recipient sees full package summary and accepts or declines explicitly.
- Accept charges the sender fee and moves all package lines exactly once.
- If sender lacks fee gold at acceptance time, no item moves and no fee is charged.
- Partial movement is impossible when any line is stale, missing, under-quantity, newly equipped/protected, tag-drifted or reserved.
- Safe Gifting, Shynok sale, Mantok Chest, level barter, item use and remort cleanup respect live postal reservations.

## Achievement note

Postal delivery completion currently reuses the durable `item_transfers` ledger but does not add separate postal-specific achievement triggers in this slice. The existing gift sent/received achievements remain valid for Safe Gifting; separate first postal sent/received achievements are deferred until achievement recalculation has explicit postal trigger keys rather than overloading gift counters.
