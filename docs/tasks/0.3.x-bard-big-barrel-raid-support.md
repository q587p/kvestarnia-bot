# 0.3.x - Bard Big Barrel Raid Support

## Goal

Turn the existing Bard Big Barrel Brother prep hint into one narrow, visible raid role. A living joined `class.bard` participant should be able to support the party or disrupt the boss with a bounded buff/debuff action instead of the current hint promising raid magic that does not exist yet.

This is a future implementation task. The current `raid.prep-hint` line remains flavor-only until this task ships.

## Source promise

The source hint is `barrel.raid-hint.class.bard` in `src/content/characterFlavor.ts`:

> Бардам у повному рейді дадуть бафи, дебафи й відповідальність за моральний стан табуретів.

The Big Barrel MVP already exposes ordinary class/race ability labels and self-use medical manatky. It does not yet provide a Bard-specific party buff or Big Barrel Brother debuff.

## Scope

- Add one raid-only queued action with a stable technical id such as `raid.class.bard.chorus`.
- Make it available only to a living, joined Bard in an active Big Barrel Brother fight.
- Choose one bounded first-slice effect during implementation: either a short party-support buff or a short boss debuff. Do not introduce a general status-effect engine or ship both effect families accidentally.
- Resolve the action through the existing one-action-per-round and latest-valid-choice-wins semantics.
- Freeze the effect in the stored round result so active cards, terminal results and journal replay agree after refreshes, retries and concurrent resolution.
- Give the action a deterministic duration/limit and cooldown or resource cost that are balance-tested against the current Big Barrel win-rate matrix.
- Use a distinct music/ability icon and inspect it together with every active-card, button, result-line and journal presenter under the strengthened icon rule.
- Keep player-facing pre-commit copy qualitative; exact effect amounts and hidden odds belong in results, tests and internal docs.

## Non-goals

- No ordinary PvE, training, duel or quick-duel Bard buff/debuff.
- No generic party-role, threat, morale or status-effect framework.
- No stacking, permanent character bonuses, loot, gold, XP or reward multiplier.
- No automatic effect from merely joining a raid.
- No changes to the current prep hint until the mechanic is implemented and verified.

## Acceptance criteria

- Only an eligible living joined Bard sees the raid support action.
- The action is replaceable before round resolution and only the latest valid choice can activate it.
- Stale, duplicate, invalid, knocked-out and concurrent callbacks fail closed without spending the action, resource or cooldown twice.
- The effect applies at one documented point in the round, has an exact tested duration, and cannot stack with itself unless a later balance decision explicitly allows it.
- Active card, round summary, terminal result and paginated journal use the same stored effect outcome.
- The effect does not leak into ordinary fights, training, duels or quick duels.
- Balance probes cover a full same-level party with and without a Bard and verify that the Bard does not turn the raid into a guaranteed win.
- Achievement and Lore Board decisions are documented before implementation is called complete; prefer a rewardless first-use achievement if the existing raid ledger can support it.

## Raid prep-hint audit

- Warrior “stand between the Barrel and bad decisions” is already tracked by [0.3.x-warrior-raid-taunt.md](0.3.x-warrior-raid-taunt.md).
- Bureaucramancer Protocol 13-B and Kharakternyk ward signs are shipped narrow exceptions, not future work.
- Mage, Rogue and Ranger hints currently describe the ordinary class/race action surface already available in raids; no separate raid-only effect is promised by their current wording.
- Priest “heal allies” is a real future role promise. Add a bounded party-boss healing action as a separate follow-up; the Big Barrel MVP explicitly excluded a healing role.
- Varenyk-mancer “dough is control” and Bisyny “crowd control” are future control-effect follow-ups. Keep them separate from the Bard slice and avoid inventing a shared control framework prematurely.
- Drantohor “excellent tank” is a future race-specific tank/positioning follow-up; it is not covered by the class-only Warrior taunt.
- The remaining race and race/class combination lines are flavor unless a future task names a concrete mechanical promise. Do not convert every joke into a combat system.

## Focused tests

- Domain tests for the selected Bard effect, exact duration/limit and cooldown/resource behavior.
- Eligibility tests for Bard versus non-Bard, living versus unable participants and active versus non-raid combat.
- Latest-choice, stale callback, duplicate callback and concurrent-resolution tests.
- Presenter/keyboard tests for the distinct Bard icon, active effect, expiry and journal replay.
- Balance simulation comparing equivalent parties with and without a Bard.
- `npm run check`.

## Manual Telegram QA

Manual QA status: not run in this planning package.
