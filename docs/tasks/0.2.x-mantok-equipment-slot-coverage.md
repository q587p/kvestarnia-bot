# 0.2.x - Mantok Equipment Slot Coverage

## Goal

Fill the canonical equipment-slot content gaps for manatky without touching shops, reward tables, transfer sinks, Prisma schema or combat formulas.

This is a parallel mantok-content/equipment slice. It stays separate from the ongoing dice/Shynok table-games work.

## Scope

- Add authored manatky coverage for every canonical equipment slot: `weapon`, `offhand`, `head`, `chest`, `legs`, `accessory` and `tool`.
- Add a small authored equipment requirement contract for class, race and title gates.
- Enforce authored equipment gates in both item-detail preview and actual equip.
- Route generated Loot Expansion v1 head and leg gear to logical body slots while keeping generated ids and counts stable.
- Tag generated logical offhand and twohand weapons during materialization.
- Keep Loot Expansion v1 data-pack source rows generated/stable; adapt only the adapter/materialization logic.

## Non-goals

- No package version bump.
- No Prisma migration.
- No shops, reward tables, Mantok Chest, transfer sinks, remort, combat formula or item-instance changes.
- No Shynok, table-games, dice poker, Kosti/Tavlei, leaderboard or social-game refactors.
- No new achievements, cooldowns, timers or `/dev_*` helpers; this slice adds content and equip validation only.

## Acceptance criteria

- Authored non-generated manatky cover every canonical equipment slot.
- Authored equipment requirements can gate by current class, race and combo/cosmetic title label.
- Item equip preview and equip return the same requirement-denied state for authored gates.
- Generated Loot Expansion v1 variant count remains stable.
- Generated armor head/face families materialize to `head`; foot/leg families stay `legs`; utility families stay `tool`.
- Logical generated offhand/twohand weapon tags are materialized from source metadata without hand-editing `lootExpansionV1Data.ts`.
