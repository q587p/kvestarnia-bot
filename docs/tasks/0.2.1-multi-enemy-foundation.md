# 0.2.1 - Multi-Enemy Foundation

## Goal

Add a backward-compatible persistent-combat foundation that can represent and resolve exactly two enemies, while all existing production fight entry points remain one-enemy by default.

## Scope

- Exactly one or two enemies in persistent PvE solo combat state.
- Legacy `monster` and `solo_combat_sessions.monsterId` remain the primary enemy/repository boundary.
- New JSON uses optional `enemies`, ordered by deterministic primary-target order.
- Attack and class skill target the first living enemy.
- Defend and flee remain encounter-level actions.
- Each living enemy resolves one enemy-phase action.
- Win is terminal only after every enemy is defeated.
- Loss, flee and expiry remain encounter-level terminal states.
- Rewards remain the existing single-encounter contract; no per-enemy XP, gold or loot multiplication.
- `/dev_two_enemies` is the only shipped way to start a two-enemy ordinary persistent fight in this slice.

## Compatibility Shape

Legacy rows stay valid:

```json
{
  "monster": { "id": "monster.deadline-spider", "hp": 12, "hpMax": 12 }
}
```

New rows may add:

```json
{
  "monster": { "id": "monster.deadline-spider", "hp": 12, "hpMax": 12 },
  "enemies": [
    { "enemyId": "enemy:1", "id": "monster.deadline-spider", "hp": 12, "hpMax": 12 },
    { "enemyId": "enemy:2", "id": "monster.complaint-lantern", "hp": 10, "hpMax": 10 }
  ]
}
```

Parser rules:

- Missing `enemies` means legacy one-enemy combat.
- `enemies` must contain one or two entries.
- `enemyId` values must be unique and stable.
- The first enemy must mirror the legacy `monster` identity and HP fields.
- Malformed enemy arrays parse as invalid combat state rather than partially restoring.

## Implementation Notes

- `CombatState.monster` remains the current primary living enemy mirror.
- `CombatState.enemies` is omitted for normal one-enemy starts to keep old state shape stable where practical.
- Per-enemy runtime state lives on each enemy entry as `monsterRuntime`.
- `normalizeCombatEnemies()` is the canonical helper for legacy-to-encounter view.
- `syncPrimaryCombatEnemy()` advances the primary mirror after the current primary dies.
- Turn logs can include per-enemy HP snapshots and per-enemy action summaries.
- Timeout and stale callback recovery rebuild enemy combat stats from stored JSON before resolving.

## Production Exposure

Unchanged one-enemy production starts:

- ordinary `/fight` / Nyz passage fights;
- Yeger fights;
- Adventure complication fights;
- starter combat;
- training doppelganger;
- quick and turn-based duels.

Dev-only exposure:

- `/dev_two_enemies` is available only when dev reset commands are enabled.
- It starts a controlled ordinary persistent fight with two enemies.
- It grants no direct reward and uses the ordinary settlement path if the player later wins.

## Manual Telegram QA

Not run in this thread.

Recommended local pass:

1. Enable dev commands locally.
2. Start `/dev_two_enemies`.
3. Confirm two enemy HP rows are visible.
4. Attack until the primary falls; confirm the second enemy becomes primary.
5. Confirm each living enemy produces a separate action line.
6. Confirm dead enemies do not act.
7. Win and replay old buttons; reward/settlement should occur once.
8. Flee and test timeout behavior.
9. Restart during the fight and verify restore.
10. Start ordinary/Yeger/Adventure/training/duel routes and verify they remain one-enemy.
11. Disable dev commands and verify `/dev_two_enemies` is unavailable from `/dev_help`.

## Non-Goals

- No threat streaks or de-escalation.
- No Yeger integration.
- No location encounter pools.
- No authored escalation-line pool.
- No target-selection UI.
- No three-or-more enemies.
- No reward scaling.
- No loot-table or economy rebalance.
- No item tags, consumables or equipment work.
- No Prisma migration.
