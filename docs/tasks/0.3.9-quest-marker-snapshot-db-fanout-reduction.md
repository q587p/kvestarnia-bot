# 0.3.9 — Quest Marker Snapshot DB Fan-out Reduction

## Goal

Reduce the measured database-dominated latency of `main-menu.quest-markers` by removing repeated Adventure and Fight reads while preserving every existing quest-marker state, route, keyboard and fail-soft result.

## Evidence

The sanitized 0.3.8 combined dataset contains 506 complete records. `main-menu.quest-markers` has `N=224`, a `47.3%` slow rate, `341 ms` p50, `626.9 ms` p95 and `37.8%` of measured total latency; its measured time is effectively all `dbMs`. The current snapshot starts up to ten optional service lookups in one primary `Promise.all`. `fight.turn` is separately slow and remains a documented follow-up rather than part of this release.

## Scope

- Add shared Adventure and Fight quest-marker snapshot methods that retain the existing source-specific result types.
- Reuse one Adventure character/equipment read for the regular and starter Adventure markers.
- Reuse one Fight character read for the fight-overview and problem-quest markers.
- Prefer the grouped methods from the main-menu snapshot, reducing its primary service-source fan-out from ten to eight; keep the existing legacy fallback for compatible test/adaptor implementations.
- Preserve per-result fail-soft handling with settled grouped results, so one Adventure or Fight sub-result can fail without discarding its sibling or unrelated markers.
- Emit only bounded `questMarkerSourceCount`, allowlisted `questMarkerSlowestSource` and timing attribution on the existing privacy-safe performance record.
- Add focused marker-state, fail-soft, source-call and repository-read count coverage.

## Non-goals

- No cache, speculative precomputation, broad quest rewrite, schema, migration, dependency, reward, balance, timer, cooldown, route, keyboard or player-visible behavior change.
- No raw production log, SQL parameter, player state, Telegram id or dynamic source label.
- No `fight.turn` optimization; its DB/Telegram critical path is a separate measured follow-up.
- No achievement: the release adds no visible action, milestone or gameplay outcome.
- No lore or quest-overview update: the in-world behavior, quest states and guidance are unchanged.
- No rollout flag: the read reduction preserves the existing output contract and has direct fallback coverage.
- No `/dev_*` helper: the release adds no runtime gate, timer, random offer, pending session, retry or mutation to accelerate.

## Acceptance criteria

- The production snapshot uses one grouped Adventure source and one grouped Fight source instead of four independent top-level sources.
- Adventure performs one fewer character read and one fewer equipment read than the equivalent separate marker calls; Fight performs one fewer character read.
- A rejected grouped sub-result still preserves its successful sibling and all unrelated marker sources.
- Existing marker states, optional no-character behavior, route guidance and keyboard labels remain unchanged.
- Performance payloads expose the actual bounded source count and one allowlisted slowest-source label without raw data.
- Focused tests and `npm run check` pass.
