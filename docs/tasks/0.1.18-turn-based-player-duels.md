# 0.1.18 — Turn-Based Player Duels

## Goal

Add `♟️ Покрокова дуель` as a second safe duel mode beside rewardless `⚡ Миттєва дуель`, using the existing invite/rematch ledger and a shared combat-domain primitive.

## Scope

- Persist server-authoritative duel mode on `DuelChallenge`.
- Add persistent two-player turn-based duel sessions, action audit rows and active combat leases.
- Freeze both participant snapshots at accept time after canonical resource sync and progression-only duel normalization.
- Queue player actions privately, then resolve the round through shared actor-vs-defender combat logic when both participants have chosen or the timeout fills missing choices, with attack, class skill and surrender.
- Add a location-scoped `👀 Хто поруч` entry point: page active players in the same current location, choose a target, choose quick or turn-based mode and send an in-game targeted invite through the same duel ledger.
- Store initiative, turn, optimistic version, terminal result, rules version and balance version.
- Add durable 23-second turn deadlines with idempotent timeout auto-attacks and startup polling.
- Render recoverable battle cards for both participants and extend the central combat lock.
- Harden terminal replay, same-round optimistic races, Telegram edit/send fallback, active-duel restart/remort blocking and explicit terminal result reasons before merge.
- Grant small replay-safe XP for completed turn-based duels only: `1 XP` for a loss, `2-5 XP` for a draw and `4-8 XP` for a win with a bounded luck influence.

## Non-goals

- No gold, items, quest progress, wagers, item loss, rating power, tournaments, spectator betting, cross-location player search or broad social discovery.
- No manatka/gold trading in this slice; nearby exchange belongs to a later social-economy task.
- No event-sourced rewrite of combat.
- No change to quick duel rewardlessness or pair-limit semantics.

## Acceptance Criteria

- Fighting Corner offers both duel modes with concise copy.
- Quick links remain `duel_<token>`; turn-based links use `duel_turnbased_<token>`.
- Stored mode is authoritative and crafted prefixes cannot switch a challenge.
- Accepting a turn-based invite atomically creates one active session and active leases.
- Only participants can queue one choice per round; duplicate, stale or non-participant callbacks cannot resolve a round twice.
- Duplicate, stale, wrong-player and terminal callbacks replay current state without rerolling.
- Timeout processing and callbacks race safely through optimistic session updates.
- Terminal resolution releases leases idempotently and writes one stored result.
- Terminal turn-based paths set the parent challenge to `resolved`, including surrender, and replay the result card rather than an active board.
- Terminal turn-based results store and grant one small XP reward per participant exactly once; stale, duplicate and replay paths do not grant XP again.
- Same-round optimistic update conflicts retry once only when the actor has not chosen and the round has not advanced.
- Active turn-based keyboards use the shared combat availability rules, so class actions hide while mana/cooldown rules make them unavailable and stale callbacks still resolve as failed turns without damage.
- Rematches preserve the original mode.
- `👀 Хто поруч` offers `Кинути виклик присутнім`, paginates active same-location targets, creates a targeted quick or turn-based invite and sends the target an in-game opt-in notification best-effort.
- Targeted invite recipients receive a best-effort cancellation notice when the challenger cancels before acceptance.
- Quick duel participants receive a best-effort result notification immediately after the other side accepts.
- Pending duel cards re-rendered from decline/refresh paths preserve configured invite-link state and do not show a false missing-bot-username warning.
- Active turn-based duel cards do not show Fighting Corner navigation while the active combat lock would block it.
- Duel result cards return to the Fighting Corner instead of quest-table or hall navigation.
- Old quick result JSON remains readable.

## Manual Telegram QA

- Create quick and turn-based challenges from the Fighting Corner.
- Open `👀 Хто поруч`, press `Кинути виклик присутнім`, choose an active same-location player, choose quick and turn-based modes and verify the target receives an in-game invite.
- Accept a turn-based deep link from a second account.
- Verify a participant who has already chosen sees only their recorded choice/status, while the other participant can still choose without seeing the hidden action or damage.
- Press stale/duplicate turn buttons.
- Let one turn expire and verify the automatic basic attack.
- Finish by defeat and by surrender.
- Verify terminal XP appears on the result card and is not duplicated by old buttons or replay links.
- Reopen from the original deep link, Fighting Corner redirect and rematch result card.
