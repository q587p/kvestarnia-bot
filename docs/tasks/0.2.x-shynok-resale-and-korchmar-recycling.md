# 0.2.x - Shynok Resale and Korchmar Recycling

Draft future economy task. Do not implement inside `0.2.0` Safe Gifting.

## Goal

Turn Shynok manatka sales into a safer economy loop:

- high-value manatky sold by players can be bought by other players for full value;
- low-value sold manatky become Korchmar recycling fodder through the existing Friendly Chest-style output logic.

## Scope

- When a player sells a manatka with `goldValue >= 93`, keep that sold unit in a public Shynok resale list instead of deleting it from the economy.
- Any eligible player can buy a listed unit for its full current value.
- Buying is transactional and replay-safe: gold is spent once, the buyer receives exactly one unit, and the listing quantity is reduced exactly once.
- Cheaper sold manatky go into a Korchmar recycling pool.
- When the recycling pool has at least 5 eligible units, Korchmar can feed 5 units into the existing Friendly Chest-style generation rules.
- If the generated manatka has `goldValue >= 93`, add it to the resale list.
- If the generated manatka is cheaper and there are at least 4 other eligible recycling units left, it can join the next 5-unit recycling batch.
- Add a deterministic processing limit per sale/worker tick so recycling cannot loop forever.
- Keep the loop server-owned: sellers receive only the original sale payout, not future resale proceeds.

## Non-goals

- No player-to-player market pricing.
- No auctions, bids, offers, fees or seller royalties.
- No gold transfer between players.
- No item-for-item trade.
- No item-instance refactor unless a separate task explicitly requires it.
- No change to combat, loot drop, quest reward or manatka stat formulas.
- No consumables, food, coffee, raids, tournaments or broad shop work.

## Acceptance Criteria

- Selling a `goldValue > 93` eligible manatka creates or increments a resale listing.
- Selling a cheaper eligible manatka adds it to a recycling pool instead of making it buyable directly.
- Buying a listed manatka costs full value and grants exactly one unit once, even under duplicate callbacks.
- A stale listing buy fails without spending gold if the listing is gone, the buyer lacks gold, or item content changed unsafely.
- Recycling consumes exactly 5 eligible low-value units per batch.
- A recycled output with `goldValue >= 93` becomes a resale listing.
- A recycled output below `93` can be reused only as part of a later 5-unit batch, with a bounded loop.
- Existing Shynok sale payout remains unchanged unless the task explicitly revises it.
- Player-facing copy makes this look like Korchmar/Shynok resale, not a free player market.

## Focused Tests

- Domain tests for resale/recycling thresholds: direct sale `>= 93`, recycled output `>= 93`.
- Repository tests for listing creation, listing purchase, duplicate purchase replay and stale listing failure.
- Repository/service tests for recycling 5 low-value units into either a resale listing or a bounded next batch.
- Transaction tests for buyer gold decrement plus item grant exactly once.
- Presenter/callback tests for Shynok resale list, buy confirmation, insufficient gold and stale listing states.
- Regression tests proving existing Shynok sale payout and Safe Gifting reservations still hold.

## Manual Telegram QA

1. Sell a manatka worth at least `93` gold; verify it appears in Shynok resale at full value.
2. Buy that listed manatka from another character; verify buyer gold decreases once and buyer gains one unit.
3. Replay the buy button; verify no second spend or grant.
4. Try buying without enough gold; verify no mutation.
5. Sell 5 cheap eligible manatky; verify Korchmar recycling creates a deterministic outcome.
6. If recycling output is `>= 93`, verify it appears in resale.
7. If recycling output is below `93` and 4 other cheap units remain, verify the next bounded batch can use it.
8. Try equipped/protected/story/reserved items; verify they do not enter resale or recycling.
