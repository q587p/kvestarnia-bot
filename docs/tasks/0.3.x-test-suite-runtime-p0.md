# 0.3.x — Test-Suite Runtime P0

## Goal

Reduce same-machine full validation wall time by at least 30% without skipping tests, shrinking the exhaustive Adventure matrix or combat simulations, weakening assertions, disabling isolation, hiding failures or raising test-level timeouts.

## Baseline environment and evidence

Recorded from clean `origin/main` commit `da4146f280d8650af806bad7fbf81981baf6b233` after PR #176 merged, on Windows 10.0.19045 x64, Node v24.15.0, 12 logical CPUs and `availableParallelism=12`.

| Baseline phase | Files / tests | Wall time |
| --- | ---: | ---: |
| Prisma generation | — | 16.906s |
| Typed source/test lint | — | 52.751s |
| Maintenance-script typecheck | — | 3.916s |
| Strict source build | — | 12.538s |
| Unit suite | 301 / 3,796 | 45.061s |
| Sequential integration suite | 22 / 501 | 58.157s |
| Authoritative `npm run check` | 323 / 4,297 | 125.363s |

Focused unchanged-main medians:

- Adventure content: 30.963s wall time across three runs; Vitest test-body times were 28.114s, 27.899s and 27.973s, with the exhaustive 238 × 9 × 9 matrix accounting for about 24.7s per focused warm run.
- Duel tournament domain/service: 7.638s wall time across three runs; service test-body times were 5.350s, 5.197s and 5.176s.
- Two-worker integration probe: three consecutive passes at 37.415s, 37.569s and 38.138s (37.569s median, 35.4% faster than sequential). A shuffled file-order run with seed 587 passed in 39.156s.

## Final evidence

| Optimized phase | Files / tests | Wall time / result |
| --- | ---: | ---: |
| Adventure focused suite, three-run median | 4 / 32 | 10.083s; 67.4% faster |
| Duel service test body, three-run median | 1 / 6 | 0.381s; 92.7% faster |
| Bounded integration suite, three-run median | 22 / 501 | 37.491s; 35.5% faster |
| Shuffled integration suite, seed 587 | 22 / 501 | 37.607s; passed |
| Authoritative `npm run check` | 326 / 4,301 | 79.878s; 36.3% faster; exit 0 |

The final count is 304 unit files / 3,800 unit tests plus 22 integration files / 501 integration tests. The three Adventure matrix shards replace one original matrix test with three tests, one independent-container regression test was added, and one duel boundary regression test was added: three additional files and four additional tests, with no baseline test removed. The matrix still covers all 238 × 9 × 9 combinations and every original invariant.

The guarded incremental source build was verified from a missing `dist`: it emitted all 470 expected files and their SHA-256 hashes matched a clean non-incremental build. Removing one nested output also forced a correct rebuild and restored the same hash. CI does not restore TypeScript build info.

## Scope

- Hoist immutable generated Adventure scene seeds, native top-up methods and technique identity beats; compute profile/signature identity data once per scene build while keeping returned scene and method containers independent.
- Preserve the exhaustive Adventure matrix and aggregate its invariant failures to avoid per-combination matcher overhead.
- Reuse one immutable Kyiv `Intl.DateTimeFormat` in duel tournament calculations and cover winter, summer, DST, ISO-week and month boundaries.
- Enable integration file parallelism with `minWorkers: 1`, `maxWorkers: 2`, per-file isolation unchanged, independent temporary SQLite databases and retry-safe Windows cleanup.
- Add canonical `check:static`, `check:unit` and `check:integration` phases; keep `npm run check` authoritative with one Prisma generation, one unified typed ESLint process, script typechecking, one strict source build and every unit/integration test.
- Align the required CI check `Foundation checks` with those phases, cancel superseded runs and persist only ESLint's content cache.
- Record the long-command observation contract in `$kvestarnia-version-task`.

## Non-goals

- No dependency, schema, migration, generated-file, gameplay, balance, reward, player-copy, isolated-bot, deploy or release-version change.
- No unit-pool, unit-worker, isolation or test-level timeout change.
- No integration test concurrency within a file and no more than two integration files at once.
- No combat-simulation scenario or `runsPerMatchup` reduction.
- No CI-persisted TypeScript build-info cache. Local per-config build info is retained only behind a guard that forces a clean source emit whenever `dist/bot.js` is absent.
- No detached validation framework, result receipt cache, CI sharding, player news, changelog entry or package-version bump.

## Acceptance criteria

- Unit and integration file/test counts do not decrease from 301 / 3,796 and 22 / 501; legitimate regression-test additions are explained.
- All 238 Adventure problems, 9 races, 9 classes and 19,278 combinations keep every current invariant.
- Adventure focused wall time improves by at least 50% and duel service test-body time by at least 70%, or the measured miss is reported.
- Bounded integration parallelism passes three consecutive Windows runs plus a shuffled run and is at least 25% faster than sequential; Linux is validated by CI.
- Same-machine `npm run check` improves by at least 30%, keeps all required phases and returns a confirmed exit code 0.
- `git diff --check` passes.
