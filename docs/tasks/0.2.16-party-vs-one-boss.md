# 0.2.16 - Party Vs One Boss MVP

## Goal

Ship the first production-proof bridge from temporary party recruiting to real raids: one existing party, one shared boss-like target, short deterministic rounds, durable state, stale callback safety and no production Senior Barrel Brother content.

## Scope

- Reuse `PartySession` / `PartyParticipant` as the recruiting and roster source.
- Start the proof only from a valid recruiting party through a dev/flag-gated control.
- Freeze the roster at start and acquire one `ActiveCombatLease(kind = "party-boss")` per active participant.
- Persist active one-boss state in `party_boss_sessions` and per-turn actions in `party_boss_actions`.
- Allow each active participant to submit one compact action per turn: attack, defend, class skill or race action.
- Resolve all submitted actions immediately when everyone has acted; otherwise dev/manual timeout resolves missing actions as deterministic defend.
- Terminalize once, store the result, release leases and clear live party keys.

## Non-goals

- No Senior Barrel Brother production route.
- No level-8 Barrel replacement.
- No serious raid rewards, trophies, affinity spotlight, loot table, beer success gate or scheduler.
- No targetable adds, target switching, watcher stacks, marks, enrage or party-vs-many runtime.
- No permanent party, guild, matchmaking, public roster, group-chat requirement, Mini App, market, trade or crafting.
- No broad combat engine rewrite.

## Acceptance Criteria

- A recruiting temporary party can start one one-boss proof under the dev/flag path.
- Roster, participant resources and boss state persist in database rows.
- Each participant can submit at most one action per turn.
- Duplicate and stale callbacks replay canonical state without double mana, cooldown, RNG or contribution mutation.
- Timeout fallback deterministically fills missing actions with defend.
- Boss HP and terminal state survive restart through `state_json` / `result_json`.
- Terminal settlement is exactly-once and releases `party-boss` leases.
- Remort during recruiting or active proof leaves no live membership or combat lease orphan; active proof remort cancels the proof without rewards.
- Existing solo combat, duel, postal, Shynok, Adventure, Daily Korchma, Barrel legacy and party recruiting behavior remain preserved.

## Manual Telegram QA

1. Enable local/dev party helpers (`PARTY_SESSION_DEV_HELPERS_ENABLED=true`) or run non-production.
2. Create a party with two or three accounts through `/dev_party`.
3. Join from another account through the deep link or private invite.
4. From the leader card, tap `🧪 Dev: бос-проба`.
5. Submit one action from one participant and let another participant time out.
6. Tap old action buttons and verify canonical replay without extra damage or mana spend.
7. Use `⏱️ Dev: добити хід` to resolve missing actions.
8. Finish the encounter and replay result cards.
9. Try remort/cancel/leave edge smoke where the local setup supports it.
10. Verify normal solo fight, duel, postal, Shynok and ordinary Barrel still work afterward.
