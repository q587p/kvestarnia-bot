# 0.2.5 — Bard Performance MVP

Status: implemented in `0.2.5` after `0.2.4` was already claimed.

Canonical planning doc: [../design/noncombat-techniques.md](../design/noncombat-techniques.md).

## Goal

Ship one narrow non-combat social activity:

> A level 3+ Bard can perform in Shynok even without a live audience, or in any other current location with at least one other active same-location character. Shynok performances may receive a small daily-capped tavern payout, and active same-location players may applaud for free or explicitly tip small gold during a short response window.

This proves the first non-combat technique pattern without creating a universal profession engine.

## Scope

- Eligible Bards can start from `🍻 Шинок` even when nobody else is nearby.
- Eligible Bards can start from `👀 Хто поруч` in any non-Shynok current location only when another active same-location character is present.
- Stable technique id: `technique.class.bard.shynok-performance`.
- Level gate: 3+.
- Cooldown: `93` minutes per Bard and location.
- Live audience window: `13` minutes.
- Freeze canonical effective CHA/LUCK/level and injected RNG result at start.
- House payout is Shynok-only, small, replay-safe and capped at `23` gold per Bard per Kyiv day.
- Audience can respond once with free applause, decline or a voluntary tip of `1 / 3 / 5 / 13` gold.
- Tip debit/credit and response completion are one transaction.
- Telegram notifications are best effort and never gameplay authority.
- Local `/dev_reset_bard_performance` speeds manual cooldown/day-cap QA.

## Non-Goals

- No universal non-combat/profession engine.
- No XP, items, buffs, achievements, quest progress, forced charges, instruments, crafting or title-powered mechanics.
- No Priest, Rogue, Mage, Yeger or race technique runtime.
- No public feed or generated song text.

## Acceptance Criteria

- `🍻 Шинок` shows a Bard performance action for eligible Bards in a valid state even without another active character in the same location.
- `👀 Хто поруч` shows a Bard performance action only for eligible Bards in a valid non-Shynok location with another active character in the same location.
- Active combat, pending Barrel raid, remort-life drift and wrong-location states block mutation.
- Start freezes stats, grade, house payout, `roleActionXp: 0`, cooldown and audience snapshot.
- Non-Shynok start without an active same-location audience returns a short no-audience result and creates no performance; Shynok start can create a zero-audience performance.
- Start/live cards label audience as the start snapshot and show the remaining response window separately from the cooldown.
- Refresh/replay never rerolls grade or gold.
- Concurrent start callbacks for the same Bard and location create at most one live performance and one house payout.
- Shynok house payout clips by Kyiv date and may become `0` after the daily cap; non-Shynok performances have no house payout.
- Tips debit audience and credit performer atomically.
- Insufficient-gold tip attempts report the requested tip amount while leaving the stored offered reaction unchanged.
- Audience responses re-check the performer character before mutation: same remort life, still at the performance location, no active combat and no pending Barrel raid.
- One audience character can respond at most once per performance.
- Duplicate/stale/expired/remorted/location-mismatch callbacks replay or fail safely without mutation.
- Performer feedback notifications happen only after a real new applause/tip transition.
- Telegram copy is short, Ukrainian and does not expose exact chance math before commitment.

## Focused Tests

- Domain: deterministic grade, thresholds, payout, daily cap clipping, constants and tip validation.
- Service/repository: class/level/location/combat/raid/remort gates, per-location cooldown, one live performance per location, concurrent start replay, frozen snapshot, Shynok daily cap, Shynok zero-audience start, non-Shynok no-audience start, audience filtering, applause, tips, insufficient gold, expiry, duplicate replay and transactional response safety.
- Bot: callback parser limits, Shynok/nearby button visibility, dev command catalog/help/presence routes and Ukrainian presenter surfaces.

## Manual Telegram QA

Use two accounts in Shynok and one non-Shynok location:

1. Eligible Bard opens `🍻 Шинок` alone, sees the performance button and starts a zero-audience performance with Shynok-only copy.
2. Eligible Bard opens `👀 Хто поруч` in a non-Shynok location without another active character and sees no performance button / no-audience guard.
3. Eligible Bard opens `👀 Хто поруч` in a location with another active character and starts a performance.
4. Same-location player receives one private prompt.
5. Player applauds for free.
6. New test performance: player tips `3` gold.
7. Verify both wallets.
8. Repeat the same callback: no second gold mutation.
9. Try a `13` gold tip with too little gold: copy names the selected amount and lets the audience choose again.
10. Move audience away before response: controlled stale state.
11. Move Bard away, start Bard combat, put Bard into pending Barrel raid or remort Bard before response: mutation blocked.
12. Reopen the Bard performance card while live: it shows response time left, start-snapshot audience and next-performance cooldown.
13. Check cooldown independently in two locations.
14. Check Shynok daily house cap and verify non-Shynok performances have no house payout.
15. Simulate blocked DM/notification failure: stored performance remains valid.
