# 0.3.7 - Warrior Raid Taunt

## Goal

Give `class.warrior` a distinct Big Barrel Brother raid role without changing ordinary PvE, training, duels, quick duels, class/race combat ability catalogs, rewards, loot or economy.

A Warrior can call the Big Barrel Brother's attention onto themselves. For a few boss turns, every boss attack goes into that Warrior instead of the party.

This is a narrow tank/taunt action, not a generic threat system.

## Scope

- Add one explicit active party-boss action with suggested technical id `raid.class.warrior.taunt`.
- Suggested player-facing label: `🛡️ На мене!`.
- Available only to living joined `class.warrior` participants in active Big Barrel Brother / party-boss fights.
- No extra level gate beyond raid eligibility.
- No mana, gold, item, HP or XP cost.
- Consumes the Warrior's queued raid action for the round.
- Follow existing queued-action semantics: a later valid action from the same participant before resolution replaces the taunt; replaced taunts do not activate or start cooldown.
- On round resolution, apply the latest queued Taunt before the boss response in that same round.
- Duration: exactly `3` boss attack resolutions, starting with the boss response in the activation round.
- Cooldown: `5` boss turns / round resolutions from activation. If Taunt activates on round `N`, that Warrior can taunt again on round `N + 5`.
- Cooldown starts only after a committed Taunt activates.
- If the taunting Warrior becomes unable to continue before boss target selection, the taunt expires before that boss attack resolves.
- While active, Taunt overrides Big Barrel Brother target selection after the boss action is chosen.
- Single-target/personal boss attacks target only the taunting Warrior.
- Broad/area/all-party boss attacks also target only the taunting Warrior while Taunt is active.
- Redirected broad attacks become one normal per-target damage instance against the Warrior, not party-size-stacked damage.
- Existing mitigation, guard, equipment and status logic should apply to the taunting Warrior through the current damage pipeline.
- Active raid cards show a compact effect row such as `🛡️ Увага Бочки: <WarriorName>, ще N ходи`.
- Round summaries and terminal journals show Taunt activation, redirected attacks and expiry.

## Non-goals

- No ordinary solo-combat Warrior taunt.
- No duel, training or quick-duel taunt.
- No new location.
- No new rewards, loot, gold, XP, quests or economy changes.
- No broad threat table, aggro meter, tank-role framework or party-role engine.
- No new boss abilities unless a tiny test fixture needs one.
- No exact hidden odds, target-selection internals or raw formulas in player-facing copy.
- No implementation of Kharakternyk, Bureaucramancer or other future class raid systems in this task.

## Acceptance criteria

- Only eligible living joined Warriors can see/use `🛡️ На мене!` in active Big Barrel Brother fights.
- Ineligible/stale callbacks fail closed with short Ukrainian copy.
- Queued Taunt is replaceable before resolution and only the latest valid queued action commits.
- Committed Taunt activates before the boss response for that round.
- Taunt lasts exactly 3 boss attack resolutions.
- Warrior cooldown lasts exactly 5 boss turns / round resolutions from activation.
- Stale callbacks, overwritten queued actions, invalid actors and blocked active-taunt attempts do not start cooldown.
- If the taunting Warrior is unable before target selection, Taunt expires before redirecting that boss attack.
- Personal boss attacks redirect only to the taunting Warrior.
- Broad/all-party attacks redirect to one normal hit on the taunting Warrior; other participants take no immediate HP/mana damage from that redirected boss attack.
- Only one active taunt controls the boss at a time.
- Same-round multi-Warrior conflicts resolve deterministically: exactly one Taunt activates, the rest no-op/fail closed without cooldown.
- Active cards, round summaries and journals explain activation, redirection, broad-attack redirection and expiry compactly.
- Ordinary PvE, training, quick duels and turn-based duels do not gain this raid action.
- Achievement decision is documented explicitly; prefer rewardless achievement coverage if current policy requires it.

## Implementation decisions

- Runtime id: `raid.class.warrior.taunt`; the persisted party-boss action key is the narrow `taunt` discriminator.
- Taunt state lives only inside the frozen party-boss JSON state. It stores one optional active Warrior plus per-Warrior `availableTurn` values; there is no threat table, schema change, migration, character-level cooldown row, reward, or economy state.
- Frozen participant order breaks same-round multi-Warrior conflicts. Only the first valid committed action activates and emits cooldown/achievement state; later Taunts resolve as recorded no-ops.
- Every committed Taunt action clears prior Defend/equipment guard, including a deterministic same-round conflict loser. This is action-local cleanup, not a generic queued-action concurrency rewrite.
- Victory before the boss response and Warrior knockout make expiry authoritative: active state is cleared and a stored round never carries both remaining duration and expiry.
- Stored journal next-focus copy derives active Taunt from the committed round summary; live cards render the current active row once. Exact Taunt cooldown remains a live-card contract, not a historical journal snapshot contract.
- Added rewardless `achievement.warrior.raid-taunt.activated` for the first committed activation. Overwrites, duplicates, stale callbacks, blocked actions, and conflict losers emit no event.
- Achievement recalculation derives successful activation dates from durable canonical Big Barrel action summaries, and background timeout delivery preserves fresh unlock notifications.
- Remort/reset needs no separate cleanup: Taunt exists only in the already-frozen temporary raid state and cannot survive that fight.
- No new `/dev_*` command is needed. Existing local `⏱️ Dev: добити хід` / forced raid-turn resolution advances the exact boss-turn duration and cooldown gate without weakening production behavior.
- `🗺️ Квести` is unchanged because this task adds no quest or route state. `📖 Перекази` Warrior copy is updated because the shipped action is class- and lore-visible.

## Focused tests

- Domain tests for Taunt activation, exact 3 boss attack duration and 5-turn cooldown.
- Target override tests for personal boss attacks.
- Target override tests for broad/all-party attacks: only the Warrior takes one normal per-target damage instance, other participants take zero.
- Taunting Warrior unable/dead before boss response expires Taunt before redirect.
- Overwritten queued Taunt does not activate and does not start cooldown.
- Stale/duplicate callback replay does not double-activate or extend duration.
- Multiple-Warrior conflict activates at most one Taunt deterministically.

## Manual Telegram QA

Manual QA status: not run. Automated domain, repository, service, callback, keyboard, presenter, and achievement coverage is complete; the Telegram checklist remains for the refreshed isolated runtime.

Canonical checklist: [`docs/qa/warrior-raid-taunt-qa.md`](../qa/warrior-raid-taunt-qa.md).

Checklist:

1. Start a Big Barrel Brother raid with at least one Warrior and one non-Warrior.
2. Verify only the Warrior sees `🛡️ На мене!` while available.
3. Queue Taunt and resolve the round; verify the boss response targets the Warrior.
4. Resolve a broad attack while Taunt is active; verify only the Warrior takes one hit and the party avoids that hit.
5. Verify the effect lasts exactly 3 boss responses.
6. Verify the Warrior cannot Taunt again until the 5-turn cooldown expires.
7. With two Warriors, verify only one active Taunt controls the boss.
8. Verify stale/duplicate callbacks do not extend duration or reset cooldown.
