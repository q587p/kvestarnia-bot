# 0.2.x - Consumable Manatka Uses

Status: draft follow-up, not active. Do not implement this inside `0.2.31`.

## Goal

Give non-medical consumable manatky real, replay-safe uses, make useful consumables discoverable from the existing one-use / `Разові` surfaces, and allow a narrow drink-container loop: drink immediately, buy a sealed bottle for later, return an empty take-away bottle after use, and refill it with mana at the Mage.

## Context

Some generated consumables currently render truthful non-equipment copy but have no practical action, for example:

- `Кава «Ще Один Квест»`
- `Чай «Заспокойся, Танку»`

Shynok/Korchma drinks also need a future take-away path: tea, beer, coffee and similar drinks should be purchasable as one-use manatky carried in inventory when the activated task explicitly supports them. They should not feel like equipment and should not become hidden procs. If they are tagged as consumable/one-use and have an actual supported effect, they should be reachable from the same one-use inventory affordances as other consumables.

Requested container loop: an immediate drink is consumed without creating a bottle; a sealed take-away drink is a carried one-use item, and using it leaves exactly one stack unit of `item.empty-tavern-bottle`. A future Mage surface can exchange one empty bottle plus a bounded price/resource cost for `item.mana-bottle`, without duplicating either side of the exchange.

## Scope

- Audit generated and authored consumable manatky that currently have no use.
- Define a compact use catalog per item family or concrete item id.
- Define a narrow take-away purchase catalog for tea, beer, coffee and similar drinks that should become carried one-use manatky.
- Keep immediate consumption and sealed take-away purchase as visibly distinct choices on the Shynok drink card.
- Make only sealed take-away drinks return one `item.empty-tavern-bottle` after successful use; immediate cups do not create reusable containers.
- Add a future Mage refill action that turns an owned empty tavern bottle into one bounded `item.mana-bottle` through a confirmed, transactional exchange.
- Decide the mana bottle's first-slice use boundary explicitly: out-of-combat recovery or a tightly bounded one-per-fight action, never an unrestricted combat refill.
- Keep empty bottles reusable as stack-based utility items and show their quantity in inventory; do not require item-instance identity for the first slice.
- Scale effects by rarity, `goldValue`, level band, tags and existing balance pressure.
- Make supported useful consumables appear in the existing `Разові` / one-use inventory surfaces.
- Add a replay-safe purchase/confirm flow that spends gold once and grants exactly one inventory stack unit.
- Keep item-detail copy truthful: consumables are applied, not equipped.
- Consume exactly one stack unit only after the action commits.
- Add stale/replay protection for preview, confirm and callback flows.
- Add focused tests for purchase, inventory visibility, item detail, consumption, stale callbacks and balance caps.

## Design guardrails

- Prefer short-lived, bounded effects or immediate utility over permanent power.
- Avoid exact future reward promises before commit.
- Do not create a broad shop, market, crafting rewrite, item-instance migration or economy loop; a bounded Korchma/Shynok take-away drink shelf is the only purchase surface in scope when this task is activated.
- Keep immediate Shynok drinking and carried one-use drink purchases visually distinct.
- The immediate/take-away choice must name the consequence before commitment: `випити зараз` applies the supported effect, while `взяти пляшку` adds a carried item.
- Empty-bottle return happens only after a committed successful use of a sealed take-away item; stale, blocked, full-resource and duplicate callbacks do not create a bottle.
- Mage refill must spend the empty bottle and its confirmed cost atomically, and replay must return the stored mana-bottle result without spending again.
- Do not create an infinite free-mana loop: the bottle effect, refill price/resource cost, use location and combat gate need an explicit balance cap.
- Do not make consumables mandatory for ordinary progress.
- Keep prices and effects aligned: cheap common drinks should stay small, while expensive or rare consumables need caps, cooldowns or period gates before they can affect combat/resource loops.
- Do not let rarity or price create runaway combat power.
- Consider separate behavior for combat-safe, out-of-combat and social/flavor consumables.

## Candidate effect directions

- Common low-value drinks: tiny HP/mana recovery, minor short-lived comfort effect, or flavorful no-combat utility.
- Uncommon drinks such as coffee: small action-economy-adjacent utility only if bounded and non-repeatable enough to avoid farming loops.
- Beer and tavern drinks: either immediate Shynok-style consumption or a carried one-use version, with separate copy and callbacks so players know whether they are drinking now or buying one for later.
- Mana bottles: a carried one-use recovery item created only by refilling a returned empty take-away bottle at the Mage; the refill cost and recovery cap are part of the activated balance task.
- Rare/epic consumables: stronger but narrow one-shot effects with cooldown, once-per-fight, once-per-period or current-life gates as needed.
- Joke consumables: explicit harmless use result if they should remain flavor rather than power.

## Non-goals

- No implementation in `0.2.31`.
- No new Mantok ability family.
- No hidden proc system.
- No new reward faucet.
- No broad player market, shop, crafting expansion or Prisma schema work unless the activated task proves a tiny schema addition is unavoidable.

## Focused tests when activated

- Inventory / `Разові` filter includes useful consumables and excludes unusable junk/flavor-only stacks.
- Take-away purchase preview/confirm spends gold and grants exactly one carried consumable once.
- Stale purchase callbacks after gold, inventory, feature flag or availability changes do not spend or grant.
- Item-detail use buttons appear only when the consumable has a supported use.
- Confirm/replay consumes one unit exactly once.
- Immediate drink purchases do not create empty bottles; take-away use creates exactly one empty bottle.
- Empty-bottle quantity survives inventory refresh and can be exchanged at the Mage for exactly one mana bottle per confirmed unit.
- Replayed/stale Mage refill callbacks do not consume another empty bottle, grant another mana bottle or spend another cost.
- Mana-bottle use respects the selected out-of-combat/one-per-fight boundary and current HP/mana caps.
- Stale callbacks after quantity, reservation, combat state or remort-life changes do not consume.
- Combat-use consumables do not bypass active-combat turn safety.
- Balance tests cover rarity/value scaling and cap outliers such as generated high-value consumables.

## Manual Telegram QA when activated

- Open `🎒 Манатки` -> `Разові` with coffee/tea-like consumables in inventory.
- Buy tea, beer or coffee as a take-away one-use manatka; verify gold changes once and the item appears in inventory instead of applying immediately.
- Choose immediate drinking and take-away purchase separately; verify only the latter creates a carried sealed bottle.
- Verify useful consumables are visible there and unusable flavor-only consumables are not presented as usable.
- Open item detail and verify short truthful copy plus the correct use button or no-use explanation.
- Use one take-away bottle, replay the old callback, and verify the drink quantity/effect and returned empty-bottle quantity change exactly once.
- At the Mage, refill one empty bottle, replay the refill callback, and verify the empty bottle, cost and mana-bottle quantity change exactly once.
- Try use during active combat, raid and non-combat scenes according to the supported effect type.
