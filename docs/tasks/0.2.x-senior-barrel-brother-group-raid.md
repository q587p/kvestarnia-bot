# 0.2.x - Senior Barrel Brother Group Raid

Rename `0.2.x` to the next free version only when implementation starts.

## Goal

Activate the first production group raid for level `8+`: recruit up to eight characters into one concrete hourly Barrel session, resolve a difficult seven-round shared boss fight, apply current equipment and eligible PvE buffs, and settle contribution-aware rewards exactly once.

## Prerequisites

- Raid Party Session Foundation is merged and smoke-tested.
- Party Vs One Boss is merged and smoke-tested as the first production party-combat proof.
- Current combat/ability/effective-stats APIs are stable after intended architecture work.
- Current Barrel period, notification and success-gate behavior is understood.
- If item tags/one-use consumables are not shipped, omit raid item-use actions rather than inventing a private subsystem.
- Re-read current `main`; do not assume the unmerged planning branch/file layout.

## Scope

### Production route

- Level `1–7` keeps the existing solo Barrel flow.
- Level `8+` creates/opens the Senior Brother recruiting flow when the feature flag is enabled.
- A successful Senior Brother raid is the only Barrel success/reward for that character in the period.
- Existing legacy pending rows always finish as legacy.

### Recruiting

- Reuse canonical hourly `periodId`, Kyiv time and frozen existing wait duration; all live-session checks use that frozen period across a wall-clock boundary.
- Capacity `8`, minimum `1`, qualitative party-size warning.
- Early start after `23` seconds for `2+` participants.
- Solo start after `93` seconds plus explicit second confirmation.
- Deadline starts with every still-eligible participant; no separate ready check; audit break blocks new creation but never strands an existing session.
- Deep link and `👀 Хто поруч` target the same opaque session.
- At most `3` actually-started failed attempts per character/period; success remains exactly one.

### Combat

- Add group raid active state, round actions, due-round scheduler and per-participant private cards.
- Acquire `ActiveCombatLease(kind=group-raid)` for each active participant.
- Freeze participant resources, effective stats, equipment, identity, remort life and eligible queued PvE buffs.
- Use `23`-second simultaneous hidden rounds and timeout auto-defend.
- Use shared canonical actor combat primitives for attack, skill, defend, mana, cooldown, armor/resist and item effects.
- Implement the Senior Brother single-boss HP formula, target scaling, phase thresholds, marks, `Нагляд`, watcher hazard stacks, enrage and round-7 terminal pressure from the balance doc.
- No targetable adds; watcher stacks are a raid hazard/state mechanic.
- Knockout/withdrawal/AFK statuses and contribution ledger.
- Best-effort private card edits/replacements and spectator-safe shared summary.

### Settlement and rewards

- Terminalize once, then settle each participant replay-safely.
- Persist HP/mana/regen and consumed buffs exactly once.
- Store/grant XP, gold, personal loot roll, first-life trophy and one group affinity spotlight exactly once.
- Reuse canonical item candidate/grant/affinity logic; no raid-only inventory mutation.
- Write canonical Barrel success and preserve beer/round access.
- Failure grants stored `1 XP` only to meaningful contributors, with no gold/item/success.
- Release all membership keys and combat leases on every terminal/repair path.

### Tooling and rollout

- Add deterministic group raid simulation command and report.
- Add dev controls to create, fill, advance deadline/round and terminalize a controlled session.
- Keep a production feature flag and kill switch that never rewrites already-active sessions.
- Add balance telemetry without public damage ranking.

## Non-goals

- No targetable minions or party-vs-multiple-enemy runtime.
- No healing role, resurrection, threat/aggro system or class redesign.
- No permanent party, matchmaking, guild, raid finder or cross-server queue.
- No leader kick, loot master, need/greed roll, tradable raid currency or auction.
- No leaderboard, season, achievement board or public damage meter.
- No multiple difficulty tiers or level-10 hard mode.
- No Mini App.
- No broad combat engine rewrite.
- No exact reward/odds/formula preview before commitment.

## Balance contract

Starting constants and target bands live in `docs/design/SENIOR_BARREL_BROTHER_BALANCE.md`.

Hard implementation requirements:

- boss HP freezes at start and never scales from equipment/buffs/remort;
- party-size HP scaling is sublinear after player five;
- raw boss damage does not multiply by party size;
- marked target count and shared mechanics create large-party pressure;
- solo is allowed but not the balance baseline;
- recommended wins average `4–6` rounds;
- round `7` is the last player action window;
- simulation covers levels `8/10/13`, party sizes `1/2/3/4/5/8`, classes and gear/buff profiles;
- no class/race aggregate exceeds the comparable mean by more than `15` percentage points without an explicit accepted reason.

If simulation cannot meet the bands with the starting formula, tune documented constants and update the task/balance doc in the same PR. Do not silently ship different numbers.

## State and concurrency requirements

- One live raid membership per character.
- Start revalidates all participants and handles leader invalidation/transfer.
- Partial lease failure cannot leave a half-active session.
- Unique action per `(session, turn, actor)`.
- All-actions callback and timeout scheduler race through one CAS resolver.
- Duplicate/stale action has no mana, cooldown, RNG or contribution mutation.
- A process crash after terminalization can resume every remaining participant settlement.
- Duplicate settlement cannot grant XP, gold, items, spotlight, trophy or Barrel success twice.
- Old/forwarded buttons replay canonical state.
- Remort/delete/life mismatch invalidates or settles safely with no orphan lease.
- Feature-flag disable affects new creation only; active sessions remain recoverable.

## Acceptance criteria

### Route and compatibility

- Level 7 completes the unchanged legacy Barrel flow.
- Level 8 enters Senior Brother recruiting only when the flag is enabled.
- A pre-existing legacy pending row remains legacy after level-up/deploy/restart.
- Senior success unlocks every existing completed-Barrel dependent action.
- The same character cannot collect legacy plus Senior rewards in one period.

### Recruiting

- Deep-link and nearby invite join the exact same session.
- Full/cancelled/expired/active links return controlled canonical cards.
- Early start rules and solo confirmation are server-authoritative.
- Start removes newly invalid participants without leaking private reasons.
- Participant count and boss scale freeze together.

### Combat

- Every living participant can submit once per round.
- Choices remain hidden until all actions or timeout.
- Timeout auto-defends; repeated misses reduce/forfeit contribution safely.
- Attack/skill/defend use canonical current combat math.
- Equipment and eligible frozen PvE buffs visibly affect outcomes and are consumed once.
- Marks are telegraphed before heavy damage.
- `Нагляд` succeeds/fails from stored actions once.
- Watcher stacks can be cleared and never become invisible targetable enemies.
- Phase transitions occur once even when one round crosses both thresholds.
- Boss does not act after lethal aggregate player damage.
- Seven-round terminal rule is deterministic.
- Knocked-out participants stop acting but can receive the correct partial/full stored tier.

### Rewards

- Multiple participants can qualify for full contribution; there is no single DPS winner.
- Exactly one affinity spotlight exists for a won raid and cannot duplicate on replay.
- Every reward and resource result is stored and replayed.
- Failure never writes success or grants gold/items.
- Old result/action callbacks cannot reroll item rarity/recipient.
- Personal/spotlight item candidates obey current level/equipment/content rules.

### Recovery and privacy

- Restart during recruiting, each major phase, terminalization and partial settlement recovers.
- Scheduler and callback overlap never advance twice.
- Telegram send/edit failures do not roll back or duplicate state.
- Shared cards omit personal HP/mana/actions/inventory and private ids.
- Forwarded links reveal no exact location.

### Balance

- Deterministic simulator and report meet or explicitly explain every target band.
- `npm run check` passes after focused suites.
- Manual multi-account Telegram QA covers at least solo, 3-player, 5-player and full-cap sessions.
