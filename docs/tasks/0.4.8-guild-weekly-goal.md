# 0.4.8 — Guild Weekly Goal

Status: implemented and locally validated on
`codex/0.4.8-guild-weekly-goal`; owning PR and CI remain release gates. Manual
Telegram QA, merge, deployment and production enablement remain separate
pending evidence.

## Goal

Give an active guild one optional weekly reason to form ordinary left-passage
parties without adding combat power, private rankings or a guild-only encounter.

## Shipped contract

- The server owns one `ordinary-party-expeditions.v1` goal with target `13`.
  Periods start Monday at `00:00 Europe/Kyiv`; the visible identifier uses the
  Holocene ISO-week form such as `12026-W35`.
- A successful ordinary left-passage GroupCombat start freezes whether the
  weekly feature was enabled. A terminal win contributes only when at least two
  manual participants belonged to the same active guild at `completedAt`.
- One immutable session receipt selects one guild and one period. Per-user
  contributor receipts freeze Character id and remort count, while the period
  freezes the guild name and crest used by its public completion fact. Damage,
  healing, guard and control values never weight credit: every eligible manual
  participant counts equally.
- Membership is evaluated historically: `joinedAt <= completedAt` and
  `leftAt` is absent or later than completion; the guild must already be active
  and not yet disbanded. Later join, leave, kick, rename or remort cannot rewrite
  a receipt.
- Progress is capped at `13`. Completion time is the thirteenth canonical
  expedition timestamp. Completion grants no XP, gold, item, buff, combat-stat
  change or expedition multiplier; it emits one privacy-safe guild Chronicle
  fact and one rewardless achievement for frozen contributors.
- The current period appears in the private guild hub. Old Telegram cards are
  ordinary read snapshots with no weekly mutation callback; refreshing reloads
  the current authoritative period while old receipts remain immutable.
- Settlement/replay and the GroupCombat repair pass reconcile missing receipts.
  `/dev_guild_weekly` repairs the current period and
  `/dev_guild_weekly finish` completes it for local QA. Both are unavailable in
  production even if the rollout flag is set.
- `GUILD_WEEKLY_GOAL_ENABLED=false` blocks new frozen eligibility, new weekly
  writes and the weekly hub section. It does not block ordinary party
  expeditions or delete existing evidence.
- Aggregate metrics expose periods started/completed and expedition/contributor
  receipt counts only; no message content, Telegram identity or individual
  ranking is published.

## Non-goals

- New combat engine, guild boss or guild-only encounter.
- Guild bank, shared items, power buff, wars, leaderboard pressure or FOMO loss.
- Locking non-guild players out of ordinary party expeditions.
- Full guild XP tree; that follows only after observed weekly participation.

## Ability parity audit

All nine catalog class abilities plus the unknown-class fallback used by
PartyBoss and GroupCombat use the same typed class profile and shared combat
resolver. GroupCombat adds its explicit
multi-enemy focus semantics. Four mechanics remain genuinely Big-Barrel-specific:
Warrior raid taunt, Bard Lament, Kharakternyk ward sign and Bureaucramancer
Protocol 13-Z. Their reasons and separate future ownership live in
[`group-combat-raid-specializations.md`](../backlog/group-combat-raid-specializations.md).

## Explicit adjacent decisions

- Remort/reset: receipts are eternal historical guild evidence and deliberately
  persist. Completion selects at most one frozen Character per contributing User
  from the first thirteen receipts, so later remort or expeditions cannot grant a
  duplicate.
- Achievements: `achievement.guild.weekly-goal-completed` is rewardless and is
  projected from the authoritative completed period for frozen contributors.
- `📜 Хроніки Квестарні`: one public guild-subject row appears in `all` and
  `adv`; it exposes no participant identity, role, location or token.
- `📖 Перекази`: guild customs explain the weekly journal and no-power boundary.
- `🗺️ Квести`: no quest state, route or turn-in changes, so the overview is
  intentionally unchanged.
- Commands: no new production command exists; the helper belongs only to
  guarded `/dev_help`.
