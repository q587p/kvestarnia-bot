# 0.4.8 — Guild Weekly Goal

Status: implemented and locally validated on
`codex/0.4.8-guild-weekly-goal`; owning PR and CI remain release gates. Manual
Telegram QA, merge, deployment and production enablement remain separate
pending evidence.

## Goal

Give an active guild one optional weekly reason to form ordinary left-passage
parties and one bounded guild-only `Книга слави`, without adding combat power,
individual rankings or a guild-only encounter.

## Shipped contract

- The server owns one `ordinary-party-expeditions.v1` goal with target `13`.
  Periods start Monday at `00:00 Europe/Kyiv`; the visible identifier uses the
  Holocene ISO-week form such as `12026-W35`.
- A successful ordinary left-passage GroupCombat start freezes whether the
  weekly feature was enabled. A terminal win contributes only when at least two
  manual participants belonged to the same active guild at `completedAt`.
- Every frozen weekly-eligible terminal session gets one typed reconciliation
  decision, including bounded ineligible reasons. The bounded repair queue is
  oldest-first across periods, derives each period from authoritative
  `completedAt`, and never rescans a rejected prefix forever.
- One immutable session receipt selects one guild and one period. Start-time
  participant snapshots freeze internal User id before Character deletion;
  per-user contributor receipts retain the historical Character id and remort
  count, while the period
  freezes the guild name and crest used by its public completion fact. Damage,
  healing, guard and control values never weight credit: every eligible manual
  participant counts equally.
- Membership is evaluated historically: `joinedAt <= completedAt` and
  `leftAt` is absent or later than completion; the guild must already be active
  and not yet disbanded. Later join, leave, kick, rename or remort cannot rewrite
  a receipt.
- Progress is capped at `13`. Completion time is the thirteenth canonical
  expedition timestamp. One immutable guild/period source receipt grants exactly
  `13` non-spendable guild `Слава`; repair derives it and cannot award it twice.
  Glory buys nothing, changes no stat/reward/capacity/admission rule, is not
  guild XP, and remains historical after rename, remort or membership changes.
- Completion emits one normal-severity privacy-safe guild Chronicle fact in
  `all` and `adv`, not `imp`, including `+13 Слави`. Contributor achievement
  entitlement is User-level and durable: the current Character receives each
  unlock and notice exactly once, or the entitlement waits through `/restart`
  until Character recreation and later `/guild`/repair/recovery projection.
- `📜 Книга слави` is a read-only, guild-only surface in `🪺 Гніздо ґільдій`.
  `✨ Слава` densely ranks active guilds by all-time Glory; `🏁 Першість` ranks
  the current Kyiv/Holocene week by completion time, then incomplete progress.
  Ties share a visible place. Both views show five escaped crest/name aggregate
  rows, deterministic pagination and the viewer guild's own off-page place;
  they expose no player, roster, role, identity, token or private timestamp.
- The private guild hub shows current Glory and weekly place as well as progress.
  Old Telegram cards are ordinary read snapshots with no weekly mutation
  callback; refreshing reloads current authority while old receipts remain
  immutable.
- Settlement/replay and GroupCombat recovery reconcile missing decisions and
  reproject pending entitlements. `/dev_guild_weekly` runs the same bounded
  cross-period repair. `/dev_guild_weekly finish` creates one typed QA-only
  completion override which recompute/restart preserve with the same completion,
  Chronicle, Glory and entitlements. Production cannot create either helper path.
- `GUILD_WEEKLY_GOAL_ENABLED=false` blocks new frozen eligibility, new weekly
  writes, weekly hub section, Glory reads and both board views. It does not block
  ordinary party expeditions or delete existing evidence.
- Aggregate metrics expose period, receipt, reconciliation, Glory and entitlement
  counts only; no message content, Telegram identity or individual ranking is
  published.

## Non-goals

- New combat engine, guild boss or guild-only encounter.
- Guild bank, shared items, power buff, wars, material ranking rewards or FOMO loss.
- Any individual-player contribution, superiority or winner board.
- Spendable Glory, guild XP/level tree, capacity unlock or `0.4.15` cosmetics.
- Locking non-guild players out of ordinary party expeditions.
- Full guild XP tree; that follows only after observed weekly participation.

## Balance review

The only new quantity is one immutable `13`-Glory guild receipt per completed
period. Because Glory cannot be spent and changes no combat, reward, capacity or
admission formula, replay cannot inflate the economy and board position grants
no snowballing benefit. Primacy resets its read view each Kyiv week but preserves
old evidence; there is no winner payout, personal competition or loss penalty.
The remaining abuse surface is reputational coordination between guilds, bounded
by active-guild-only rows, canonical receipts and no material incentive.

## Ability parity audit

All nine catalog class abilities plus the unknown-class fallback used by
PartyBoss and GroupCombat use the same typed class profile and shared combat
resolver. GroupCombat adds its explicit
multi-enemy focus semantics. Four mechanics remain genuinely Big-Barrel-specific:
Warrior raid taunt, Bard Lament, Kharakternyk ward sign and Bureaucramancer
Protocol 13-Z. Their reasons and separate future ownership live in
[`group-combat-raid-specializations.md`](../backlog/group-combat-raid-specializations.md).

## Explicit adjacent decisions

- Remort/reset: receipts are eternal historical guild evidence and deliberately
  persist. Achievement entitlement is User-level, resolves the current Character
  at projection and cannot duplicate across later lives.
- Achievements: `achievement.guild.weekly-goal-completed` remains rewardless.
  `achievement.guild.three-weekly-goals` and
  `achievement.guild.thirteen-weekly-goals` count distinct completed periods in
  which that User has an eligible receipt. No damage/healing/top/first-place
  achievement exists.
- `📜 Хроніки Квестарні`: one public guild-subject row appears in `all` and
  `adv`, never `imp`, at normal severity; it exposes no participant identity,
  role, location or token.
- `📖 Перекази`: `Книга слави` has its own entry explaining the weekly journal,
  immutable Glory and no-power/no-individual-ranking boundary.
- `🗺️ Квести`: no quest state, route or turn-in changes, so the overview is
  intentionally unchanged.
- Commands: no new production command exists; the helper belongs only to
  guarded `/dev_help`.

## Automated evidence

- Thirteen ineligible decisions cannot starve the later eligible terminal;
  Sunday settlement recovers into its old period after Monday restart.
- Start-time User identity survives Character deletion/recreation; User-level
  achievement projection and durable notice delivery remain exact-once.
- Concurrent thirteenth receipts award one Glory source; repair/replay, rename,
  remort and dev completion preserve it.
- Glory/Primacy tie ordering, five-row pagination, own-place recovery, privacy,
  location/membership/flag guards and Chronicle filter membership.
- Flag-off read/write isolation and ordinary expedition availability.
- Production-unregistered dev command and command/help catalog coverage.
- Prisma additive migration plus apply/rollback/restore with unrelated populated
  User, Character, Guild, PartySession and GroupCombat rows preserved.
- Executable ten-profile ability matrix for targets, resources, cooldowns,
  support/side damage, focus contribution and terminal/restart replay.
