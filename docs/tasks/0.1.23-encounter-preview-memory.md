# 0.1.23 — Encounter Preview Memory and Anti-Repetition

Target version: `0.1.23`.

## Goal

Make ordinary Nyz passage previews server-owned, sticky and non-farmable, while reducing accidental monster repetition in ordinary fights.

## Scope

- Durable `pending_passage_encounters` storage for ordinary Nyz passage previews.
- Opaque server-owned passage attack tokens instead of client-carried encounter seeds.
- Sticky preview reuse per character and passage until expiry.
- Atomic pending encounter consumption into one persistent solo combat session.
- Expired, stale, missing-catalog and already-consumed preview handling.
- Bounded recent ordinary monster history for anti-repeat selection.
- Preserve separate left/straight/right passage presence and nearby-player behavior.

## Non-goals

- No monster roster, stat, ability, tag, reward, loot or Yeger rebalance.
- No player race/signature/title/item active abilities.
- No party, raid, boss-lobby or multi-enemy runtime.
- No timeout, reward replay or combat analytics schema expansion.

## Acceptance criteria

- Reopening the same passage before expiry returns the same monster and effective level.
- Different passages can keep distinct pending previews.
- Pressing `Атакувати` starts the exact frozen monster or visibly refreshes an expired/invalid preview.
- Duplicate attack callbacks recover the same combat session instead of creating another fight.
- Forged or other-player tokens do not select a monster.
- Legacy seed-shaped passage callbacks refresh a current server-owned preview instead of starting a seeded fight.
- Anti-repeat excludes the immediately previous ordinary monster when alternatives exist, excludes the last three distinct monsters when the pool is large enough, and falls back deterministically for small pools.
- Yeger targeted selection, adventure forced fights, training doppelgangers and starter fights keep their existing selection rules.
