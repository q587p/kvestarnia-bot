# 0.1.23 — Encounter Preview Memory and Anti-Repetition

Target version: `0.1.23`.

## Goal

Make ordinary Nyz passage previews server-owned, sticky and non-farmable, while reducing accidental monster repetition in ordinary fights.

## Scope

- Durable `pending_passage_encounters` storage for ordinary Nyz passage previews.
- Opaque server-owned passage attack tokens instead of client-carried encounter seeds.
- Sticky preview reuse per character and passage until expiry.
- Atomic pending encounter consumption into one persistent solo combat session.
- CAS-safe pending encounter expiry and consumption guarded by row status, version and current time.
- Transactional frozen-encounter validation before creating a solo combat session.
- Expired, stale, missing-catalog and already-consumed preview handling.
- Bounded recent ordinary monster history for anti-repeat selection.
- Preserve separate left/straight/right passage presence and nearby-player behavior.
- Follow-up copy polish for nearby touched Telegram surfaces when playtest screenshots reveal cramped or misleading text.
- Follow-up memorial-board remort detail buttons from PR #73, with corrected post-remort level semantics.
- Follow-up remort memorial milestone recording so levels reached after remort use per-remort keys and existing current-life progress can be backfilled.
- Follow-up persistent reply-keyboard refresh when an inline callback changes the stored location, rendered as a short movement line before the new place card for place callbacks.
- Follow-up battle-card polish: show monster level in passage previews, keep unconsumed previews for 93 minutes, and make the active fight card self-contained with opponent header and start tip.
- Follow-up survivor-monster memory: if the player attacks a passage preview and the monster survives a terminal non-win fight, the same consumed trail can be re-attacked until the trail expires, even if the hero dealt no damage.
- Follow-up remort milestone provenance and remort-board deduplication so legacy/base/backfill rows do not appear as duplicate winners for the same remort life.
- Follow-up remort lifecycle hardening so a successful remort canonically expires old solo/training combat and cancels live passage trails without rewards or stale re-attacks.
- Follow-up combat terminal settlement hardening so ordinary/training terminal side effects are guarded by frozen combat life, use durable pending/completed/forfeited settlement state, and cannot mutate a newer remort life from stale callbacks or recovery.
- Follow-up deployment-boundary compatibility so exact leased legacy solo/training combat sessions without life/settlement JSON are atomically adopted into the current guarded settlement protocol before mutation, while historical no-lease legacy records remain replay-only.

## Non-goals

- No monster roster, stat, ability, tag, reward, loot or Yeger rebalance.
- No monster gender, animacy or case-form content metadata. Passage preview copy should stay neutral until that future content slice exists.
- No player race/signature/title/item active abilities.
- No party, raid, boss-lobby or multi-enemy runtime.
- No timeout, reward replay or combat analytics schema expansion.

## Acceptance criteria

- Reopening the same passage before expiry returns the same monster and effective level.
- Unattacked passage previews expire after 93 minutes; killed encounters still make the next preview select a fresh monster through the normal anti-repeat rules.
- Consumed ordinary passage encounters whose linked fight ended without killing the monster can show the same monster again while the original 93-minute trail is live, including full-health survivors after a one-sided player loss.
- Re-attacking a consumed survivor trail starts a new persistent combat session with the same monster, same effective level and recovered monster HP.
- Different passages can keep distinct pending previews.
- Pressing `Атакувати` starts the exact frozen monster or visibly refreshes an expired/invalid preview.
- Duplicate attack callbacks recover the same combat session instead of creating another fight.
- A consume/expiry race has exactly one winner. The loser rereads current state and cannot corrupt `combatSessionId` or silently create another session.
- Survivor re-attack relinking validates that the prior linked session belongs to the same character and monster, ended as a terminal non-win, still has monster HP above 0, and has not been replaced by a newer linked session.
- Forged or other-player tokens do not select a monster.
- Passage attack callbacks from another current place do not start combat or move presence; they refresh the actual current passage/location view.
- Legacy seed-shaped passage callbacks refresh a current server-owned preview instead of starting a seeded fight.
- Anti-repeat scans bounded pages of recent sessions, skips active and non-ordinary sessions, orders by real completion time with a safe fallback, excludes the immediately previous ordinary monster when alternatives exist, excludes the last three distinct monsters when the pool is large enough, and falls back deterministically for small pools.
- Yeger targeted selection, adventure forced fights, training doppelgangers and starter fights keep their existing selection rules.
- Passage preview copy avoids guessing monster gender or using uninflected monster names in accusative contexts.
- Passage preview copy includes the shown monster's level before the attack button is pressed.
- Wounded passage preview copy shows the monster's current recovered HP; full-health survivor previews keep the same monster/token without showing a misleading wounded HP line.
- Active persistent fight cards include a fight header, opponent name, opponent level and the start tip on the card with combat buttons.
- Cellar start combo flavor keeps a blank line between the title-in-cellar sentence and the following race/class beat.
- `Реморт N` detail buttons on the memorial board show level-first rows from the life after remort N, not base-life milestone rows from before that remort.
- Characters who already reached levels after remort can appear on the selected remort detail board after the board backfills current-life milestones; future post-remort level-ups record remort-specific milestone keys immediately.
- Historic remort lives that have a later completed remort can still appear on intermediate remort-detail levels even if levels 2-12 were never recorded with remort-specific milestone keys.
- Remort milestone rows keep provenance in `daily_actions.resultJson`, and detail boards deduplicate legacy/backfilled/recorded rows for one character-level with deterministic precedence.
- After a place inline callback changes the current stored location, Telegram receives a short movement line with a persistent reply keyboard whose place button matches the new location before the new place card is rendered.
- Confirming remort during a solo or training fight expires that old fight as a replay-safe terminal `expired` session, releases the active lease, preserves the new-life starter HP/mana, grants no combat rewards and cancels live pending/consumed passage trails; unsupported turn-based duel leases still block remort without mutation.
- Persistent ordinary and training combats freeze the character remort life in combat JSON. Terminal settlement is durable and idempotent: pending terminal sessions keep the solo-combat lease until settlement completes or remort forfeits them, completed settlements replay stored rewards, and forfeited old-life sessions never retry reward/resource/cooldown writes against a later remort life. Legacy sessions without life metadata derive their expected remort count from `session.createdAt` versus the remort ledger.
- Active exact-leased legacy ordinary/training sessions created before the settlement JSON shipped are adopted atomically by adding derived `life` plus pending settlement metadata before any turn, timeout, hard-expiry, resource, reward or cooldown mutation; missing/mismatched leases and historical no-lease records do not mutate current resources or claim new rewards.
- Solo-combat discovery follows the character's active combat lease before new ordinary, passage, Adventure and training starts. A leased terminal pending ordinary/training session is recoverable after a process crash; completed, forfeited or missing supported stale leases are cleared by exact reference; unsupported lease kinds are preserved. Settlement completion/forfeit uses repository guards against pending status, settlement version, combat status and life identity, and forfeited won sessions are excluded from problem-chain and Yeger victory progress while completed and valid legacy wins still count.

## Manual Telegram QA

1. From `Ярус I: Сутерени Корчми`, open each passage twice and verify the same preview stays stable before expiry.
2. Confirm each passage preview shows the previewed monster's level.
3. Press `Атакувати` from the matching passage and verify the fight starts against the previewed monster.
4. Confirm the active fight card repeats the opponent name/level and shows a start tip beside the combat buttons.
5. Lose or expire an ordinary passage fight after damaging the monster, recover the hero quickly, reopen the same passage and verify the preview shows the same wounded monster and current monster HP.
6. Lose an ordinary passage fight without damaging the monster, reopen the same passage before the 93-minute trail expires and verify the same monster/token waits without a wounded HP line.
7. Attack either surviving preview and verify the new fight starts with the same monster at its recovered HP.
8. Wait until the 93-minute trail expires, or kill the monster, then verify the next preview uses a fresh token/selection path.
9. Press an old/expired preview button and verify a fresh preview appears with a short explanation, not a silent fight.
10. Press a preview button from another location and verify it refreshes the current passage preview instead of teleporting into combat.
11. Finish an ordinary Nyz fight, press `Новий бій`, and verify it opens the stored passage preview.
12. Verify `👀 Хто поруч` and duel eligibility remain scoped to the concrete passage.
13. Use inline location buttons such as `Спуститися` and verify Telegram first sends a short movement line such as `Ви спустилися до Сутеренів Корчми.` with the updated bottom place button, then renders the new location card.
14. Start a solo or training fight, confirm remort, and verify the old fight replays as expired, the new hero keeps starter HP/mana, no fight reward appears, and old passage attack buttons no longer start combat.
15. Start or accept a turn-based duel, try remort, and verify it stays blocked without changing the character, draft, duel lease or combat state.
