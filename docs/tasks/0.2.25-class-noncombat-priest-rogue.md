# 0.2.25 — Class Noncombat Priest/Rogue

## Goal

Ship the first noncombat class identity actions for level 3+ Priest and Rogue:

- Priest direct aid outside combat: self/nearby heal and direct blessing.
- Rogue same-location risky pickpocket: tiny bounded gold theft with replay-safe stored outcome.

These are not combat class ability changes and do not rebalance `src/content/playerAbilities.ts`.

## Scope

- Add narrow Prisma tables for Priest aid actions, Priest blessings and Rogue pickpocket attempts.
- Add a class noncombat domain/service/repository slice without a universal technique engine.
- Surface actions through `Хто поруч` / same-location presence:
  - `✨ Жрецька поміч` for eligible Priests, including self-heal/self-bless when alone.
  - `🗡️ Тиха кишеня` for eligible Rogues when another active same-location target exists.
- Target lists use exact normalized same-location semantics for this MVP; legacy aliases that normalize to the same actionable location are included, but broader front/hall-style grouping is not treated as actionable.
- Recheck actor/target class, level, remort life, location, activity and active blocking flows at mutation time.
- Use 93-minute actor-scoped cooldowns for Priest heal, Priest blessing and Rogue pickpocket.
- Store Rogue attempts once per actor-target Kyiv day and replay duplicates without rerolling.
- Add rewardless achievements backed by durable rows.
- Update `📖 Перекази` class entries for Priest and Rogue.

## Decision Changes

- Priest help is direct in this MVP. There is no accept/decline offer flow; successful aid sends a private best-effort notification after durable mutation.
- Rogue player-targeted gold theft is allowed only in this bounded MVP:
  - same active location;
  - target level 3+;
  - once per actor-target Kyiv day;
  - 93-minute actor cooldown after every resolved attempt;
  - 1-13 gold max and never more than target balance;
  - no item theft, public shame row, quest/combat progress or extra caught cooldown.
- Priest blessing ships as a durable visible timed status with `bonusStat = null` / `bonusAmount = 0`. The `+1 luck` gameplay hook is deferred until a broader timed-status/effective-stat architecture exists.
- No local `/dev_*` reset helper ships in this slice. The new actions are immediate callbacks, production rules stay unchanged, and focused tests cover cooldown/day gates; manual QA can use existing `/dev_heal`, `/dev_restore_mana`, `/dev_add_gold` and fresh actor-target pairs. A future timed-status QA helper can cover multiple noncombat cooldowns once there is a shared status/cooldown operator surface.

## Non-goals

- No combat class ability changes.
- No taunt/shield/threat system.
- No duel tournaments.
- No new equipment slots or item rebalance.
- No item theft.
- No public failure/shame feed.
- No private location tracking.
- No universal noncombat/profession engine.
- No paid advantage.
- No global action lock after caught badly.
- No exact hidden odds in player-facing pre-commit copy.

## Acceptance Criteria

- Priest heal:
  - applies the preserved formula and mana cost;
  - cannot overheal or heal full HP;
  - spends mana/cooldown only on successful healing;
  - notifies another healed target privately after durable mutation.
- Priest blessing:
  - spends mana/cooldown only on successful blessing;
  - creates one non-stacking 93-minute visible blessing;
  - blocks already-blessed targets;
  - notifies another blessed target privately after durable mutation.
- Rogue pickpocket:
  - enforces same-location active target gates and target level protection;
  - transfers gold atomically on success and caps stolen gold by target balance;
  - stores empty/no-op attempts safely when target has no gold;
  - stores caught-badly attempts and sets Rogue HP to 0;
  - replays duplicate/stale callbacks without rerolling or double transfer, even if live location has drifted after the stored attempt.
- Achievements:
  - first Priest heal;
  - first Priest blessing;
  - first Rogue pickpocket attempt;
  - first successful Rogue pickpocket;
  - first caught-badly outcome.
  - actor notifications are sent only for fresh completed actions/attempts, not for blocked/no-op states or duplicate Rogue replay.
