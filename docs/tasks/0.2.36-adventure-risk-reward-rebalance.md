# 0.2.36 — Adventure Risk/Reward Rebalance

Status: draft future version task. Do not implement this as part of the `0.2.31` polish PR.

Use `$kvestarnia-version-task`.
Use `$balance-review` for chance, reward and economy math.
Use `$ukrainian-rpg-content` for player-facing Ukrainian copy changes.

## Goal

Rebalance level 3+ Adventure Choice method odds and rewards so selected problem cards no longer collapse into many `майже надійно` rows after stat, race, class and signature bonuses.

Players should care about the method help / `Памʼятка`: safer methods should feel safer but pay less, while riskier methods should visibly be riskier and pay better. Keep exact odds hidden.

## Problem

After the `0.2.14` readability pass, selected Adventure method-help cards often show nearly every method as `майже надійно`, including rows that mention injury or other danger. The issue is global chance math, not just one scene: current bonuses can stack high enough to flatten the intended risk shape.

Representative five-method Adventure sets should usually look closer to:

- 0-1 `майже надійно`.
- 1-2 `добрі шанси`.
- The rest `непевно` / `дуже непевно`, especially generous, fight-shaped, local-failure, serious-injury, deception, unstable ritual and wild-improvisation methods.

Do not merely raise label thresholds while leaving real deterministic `check.chance` values high.

## Scope

- Primary surface: level 3+ Adventure Choice selected problem cards and `💡 Підказка` / method-help cards.
- Shared quest-check math may change, but level 1-2 starter onboarding must stay gentle if it inherits helpers.
- Revisit the global bonus stack: primary/secondary stat bonuses, class/race/signature affinity and luck adjustment.
- Prefer an explicit, testable risk-band helper over scattered constants.
- Make risk/reward tradeoffs real in XP/gold and, where clean, manatka drop odds or quality.
- Keep deterministic seeds and replay behavior unchanged.
- Keep player-facing help compact and hidden-formula-safe.

## Risk / Reward Model

Preferred implementation shape:

- Derive or author a small `QuestRiskBand`: `safe`, `steady`, `risky`, `wild`.
- Derive from `rewardProfile`, `consequenceByGrade.complication`, `intent`, `goldCost` and/or small authored method metadata.
- Use risk bands to cap or compress final chance after bonuses.
- Let safe/modest methods still reach `майже надійно`.
- Let steady/standard methods usually top out around `добрі шанси`.
- Keep risky/generous methods normally `непевно` unless the hero is a very strong fit.
- Keep wild/local-failure/fight-handoff methods genuinely uncertain.

Reward direction:

- Safer methods: smaller XP/gold and lower/no manatka upside.
- Standard methods: current-ish middle payout.
- Risky/generous methods: meaningfully higher XP/gold on success and stronger manatka upside.
- Local failure still grants 0 XP/gold/items and consumes the Adventure period.
- Fight handoff remains separate: no quest reward until the fight path resolves as already designed.

If changing `QUEST_REWARD_PROFILES`, audit downstream economy expectations and tests. For manatky, inspect existing `rollLootExpansionItem` source id / source tag hooks first. If a small risk-based quality nudge is not clean, make only drop chance risk-aware and document the quality limitation.

## Player-Facing Copy

- Add a compact `Памʼятка` to method help:
  - reliable means lower reward;
  - risky means better reward but can hurt, fail or call a fight;
  - exact odds stay behind the bar.
- Avoid repetitive rows like `Можна постраждати. Майже надійно.` when the authored hint already says the method can hurt.
- Do not expose internal ids or terms such as `riskBand`, `rewardProfile`, `grade`, `consequence`, `race`, `class` or exact percentage odds.
- Keep Telegram method rows short.

## Non-goals

- No schema migration unless absolutely unavoidable.
- No new `/dev_*` command unless existing `/dev_adventure_reset` is insufficient for QA.
- No global random failure roll after the deterministic grade.
- No broad combat reward rewrite.
- No exact odds in player-facing copy.
- No broad loot expansion data regeneration unless a tiny code-level source/tag adjustment cannot solve the manatka risk nudge.

## Acceptance Criteria

- Representative visible Adventure method sets no longer contain many `майже надійно` rows.
- Content/domain tests cover all active general Adventure problems and generated race/class/title families with representative active race/class profiles; full active-race/class matrix is preferred if runtime stays reasonable.
- Riskier methods have higher expected base rewards than safer methods.
- Local failure remains no-reward/no-item/no-fight and does not count as resolved Adventure achievements.
- Fight handoff still grants no quest reward until the fight path resolves.
- Presenter tests cover the new `Памʼятка` and prevent exact odds from leaking.
- Existing adventure callback, idempotency, achievement recalculation, local-failure and fight-handoff rollback tests remain green.
