# 0.1.20 — Authored Quest Resolutions

Target version: `0.1.20`. This design package was originally prepared against the `0.1.17` repository snapshot, so revalidate current `main` before editing, but do not renumber this task unless the user explicitly changes the release target. Keep the feature slug `authored-quest-resolutions`; do not use a PR number in artifact names.

## Goal

Replace repeated global `safe / flair / risky` resolution buttons with authored methods that belong to the selected quest scene and visibly reflect the hero's race, class and exact race+class signature/title.

The player should be able to solve problems through meaningfully different tactics such as force, investigation, negotiation, deception, bribery, ritual, performance, tracking, traps, craft or improvised character-specific nonsense. Outcomes must be specific to the problem and method, use bounded deterministic stat checks and produce more than the current binary “reward or fight” result.

Apply the same content contract to:

- level 3+ Adventure Choice problems;
- the level 1–2 starter mimic-shawarma adventure;
- the level 2–3 repeatable cellar mouse errand.

Follow-up polish in this slice also moves `🎒 Манчкін-скупник` between the korchma front door and `Спуск до Низу` by Kyiv local night schedule (`21:00` through before `07:00`), with the relevant paragraph and button shown only at his current surface. His level-barter still costs `1000` total value, but now requires at least `587` value from eligible manatky before wallet gold may fill the rest. Fighting Corner return buttons on training and duel result screens use an explicit return label so they do not look like another challenge action. The korchma hall now hides both `🥊 Бійцівський куток` and `Спуск до Низу` action buttons before level 3 while keeping stable hall prose, and stale direct corner/duel-board callbacks show the level gate instead of entering the corner.

Final hardening in this branch keeps the same release scope while tightening the implementation: paid quest/cellar methods debit inside guarded repository transactions, effective equipment stats are used for actual checks, cellar-mouse payouts remain deliberately tiny, Adventure Choice uses compact stable problem and method callback keys, starter/cellar callbacks use stable compact method keys, unknown/stale method ids show a stale state instead of resolving, and player-facing result copy omits internal race/class/signature source labels. Follow-up copy polish suppresses repeated reliability phrases in method hints, replaces universal generated method templates with scene-native анкета/кухоль/портрет/підручник/форма/іспит/титул methods, and uses grammar-neutral generated outcome copy so plural problem titles do not break agreement. Starter shawarma and the starter combat probe each grant `75%` of the level 1-to-2 XP gap rounded up on the remort-adjusted curve, so completing both reaches level 2; the quest archive shows completed starter shawarma beside the completed starter combat probe.

## Scope

### 1. Pure quest-resolution model

Add a small pure domain/content layer that represents a method as a stable content unit rather than a global risk tier.

Each method needs enough data to resolve and present:

- compact stable `methodId` scoped to a scene;
- source/slot: scene, race, class or signature;
- Ukrainian button label and qualitative hint;
- intent/technique tags;
- governing primary stat and optional secondary stat;
- conservative difficulty/base chance;
- reward profile;
- optional visible gold cost;
- grade-specific consequence kind;
- authored grade-specific outcome text;
- optional existing combat skill id as class vocabulary.

Recommended new boundaries:

- `src/content/questResolution.ts` — shared types and technique/profile registries;
- `src/content/adventureResolutionContent.ts` — level 3+ methods/outcomes;
- `src/content/starterQuestResolutionContent.ts` — shawarma and mouse content/adapters;
- `src/domain/quests/questChecks.ts` — deterministic bounded check math;
- `src/domain/quests/questMethodResolver.ts` — slot selection, composition and deduplication.

Names may differ if the existing code suggests a smaller fit. Keep Telegram imports out of the domain layer.

### 2. Character-aware method slots

For a selected level 3+ problem, render up to four genuinely different methods:

1. one scene-native fallback;
2. one race-shaped option;
3. one class-shaped option;
4. one exact race+class signature option, with current title flavor when available.

If four distinct options cannot be produced, use another authored scene method rather than a cosmetic duplicate. Render at least three methods. Starter shawarma and cellar mouse may also render four compact methods when the scene, race, class and signature slots are all available without overloading the mobile screen.

Slot rules:

- exact combo identity is `raceId + classId`;
- player-facing title may override label/outcome, but is not the primary mechanical key;
- no duplicate normalized label or duplicate tactic disguised by a different emoji;
- no more than two visible methods governed by the same primary stat;
- every character gets a usable fallback;
- no race, class, title or hidden path is required to finish the scene.

### 3. Reuse existing stats and class skill vocabulary

Use the canonical effective-stat pipeline already shared by profile/combat/equipment. Do not manually re-add race/class/path/item bonuses inside AdventureService. Actual quest checks must use the same effective snapshot, including equipped manatky/item effects, that the player-facing summary uses.

All five current stats must matter across the content pool:

- STR — force, lifting, intimidation through obvious physical competence;
- DEX — finesse, stealth, traps, sleight of hand;
- INT — investigation, arcana, paperwork analysis, craft;
- CHA — negotiation, performance, authority, deception;
- LUCK — improvisation, omen reading, risky coincidence.

Reuse the identity/stat mapping from existing combat skills where logical:

- `skill.forceful-strike`;
- `skill.hot-spell`;
- `skill.form-thirteen-b`;
- `skill.dangerous-couplet`;
- `skill.trick-shot`;
- `skill.strict-blessing`;
- `skill.steppe-side-eye`.

Do not call combat damage resolution for a quest check. Do not copy combat damage, mana-cost or cooldown math into the quest resolver.

### 4. Deterministic bounded checks

Resolve checks through injected/pure deterministic RNG using stable inputs including character, current quest period/storage key, scene and method.

Use the caps and relative weights from `docs/QUEST_SKILLS_AND_CHECKS.md`:

- a primary stat carries most of the character bonus;
- optional secondary stat contributes less;
- class/race/signature affinity is small and capped;
- LUCK may add a small bounded adjustment without becoming a universal best stat;
- final internal success chance stays inside the documented safe band;
- exact percentage is never shown in normal Telegram copy.

Return one of:

- `strong-success`;
- `success`;
- `mixed-success`;
- `complication`.

The same valid callback must resolve to the same grade and result on replay. Do not use `Math.random()` in services or presenters.

### 5. Varied consequences and conservative rewards

Keep the current Adventure Choice reward envelope approximately equivalent to the existing modest/standard/generous bands. Do not turn this into a new farm.

Support authored consequence kinds such as:

- full reward;
- reduced reward;
- XP only;
- paid success;
- cosmetic mess/no power penalty;
- existing persistent-fight handoff.

A complication must not always start combat. Across the active pool, include non-combat embarrassment, partial closure, lost gold opportunity, reduced reward and scene-specific messes.

At most one method per ordinary scene should normally hand off to combat unless the fiction is explicitly combat-centered.

### 6. Real small bribery cost

Add real bribery/payment methods where the scene supports them.

For this slice:

- cost is `1..3` gold;
- the exact cost is visible on the button or immediate pre-commit text;
- insufficient gold returns a scene-aware refusal and spends neither claim nor gold;
- debit, claim and reward/result persistence are atomic and replay-safe in the repository transaction;
- repeated callbacks never charge twice;
- duplicate paid callbacks either replay the existing stored result/cooldown or fail before debit;
- a failed combat handoff or blocked resolution does not leave a partial debit;
- do not spend mana in quest methods in this version.

Use an existing transaction/repository pattern. In the inspected `0.1.17` snapshot, `DailyAction` stores only the claim key/date and gross XP/gold, so the expected minimal persistence change is optional `spentGold` plus versioned `resultJson` fields on `daily_actions`. Existing rows remain valid with `0/null`. The new claim transaction must conditionally debit gold, create the unique claim, apply rewards/items and persist the exact method/grade/result snapshot atomically.

For the repeatable cellar path, add a transaction-safe paid cooldown-claim operation (or optional paid input with an explicit `insufficient-gold` result) rather than debiting gold in the service. No separate social-skill table is needed.

### 7. Level 3+ Adventure Choice content

Preserve the current offer loop:

- three deterministic distinct problems;
- one 93-minute period per character;
- broad general + race + class + current-title pool;
- at least one personalized offer when available;
- reroll/dev reset behavior;
- level gate;
- active-fight priority;
- daily-action idempotency;
- existing fight-handoff rollback behavior.

Replace `AdventureApproach = safe | flair | risky` as the active method model. Do not keep a new global synonym ladder.

Author problem-specific method and outcome content for all current general problem ids:

`stew`, `barrel`, `helmet`, `calendar`, `receipt`, `bench`, `cloak`, `spoon`, `mirror`, `boots`, `chimney`, `candle`, `chair`, `broom`, `door`, `map`, `teapot`, `menu`, `sign`, `portrait`, `key`, `ledger`, `rug`, `bell`.

Generated race/class/title problems must also use scene-aware authored templates. They may share family builders, but their visible methods and outcome nouns must fit the actual survey/mug/portrait/manual/uniform/exam/title scene rather than falling back to one universal result.

Use `docs/QUEST_RESOLUTION_CONTENT_SEEDS.md` as the minimum content direction, not necessarily literal final copy.

### 8. Starter mimic-shawarma

Keep the level 1–2 starter path reachable from `/adventure` and Quest Hub. Preserve completion visibility, idempotent rewards, existing item grants and early mimic reveal timing.

Replace the one-off rogue-only label switch with the shared resolution contract or a thin adapter over it.

Requirements:

- labels visibly differ for active races and classes;
- exact combo/signature can alter one method and its outcome;
- starter UI may use three methods instead of four to stay compact;
- outcomes depend on method and grade, not only `poke / receipt / flee`;
- existing receipt/wrapper item grants map to stable intents, not arbitrary biography labels;
- old `v1:adv:mimic:*` callbacks remain idempotent and safe.

### 9. Cellar mouse errand

Keep current level gates, repeatable cooldown, item grants, presence and reward idempotency.

Replace the hard-coded class/race label switch tree with the shared method contract or a thin adapter.

Requirements:

- negotiation, trap and domesticity remain valid scene-native families;
- add character-shaped deception, authority, performance, ritual, bribe or signature methods where fitting;
- all active races and classes receive a meaningful label/outcome route;
- exact combo/signature affects a method or outcome;
- item grants map to intent/family and remain conservative;
- old cellar callbacks remain safe and do not duplicate rewards.

Do not expand the separate grown-up cellar bottle quest unless a small shared helper change is required; its behavior is otherwise out of scope.

### 10. Telegram callbacks and presentation

Add compact versioned callback data for authored methods, for example a `v2` Adventure Choice action callback. Exact shape may vary, but it must:

- remain at or below Telegram's 64-byte callback-data limit;
- allowlist problem and method ids;
- reject malformed/stale ids through the current problem/method resolver before any claim, cost, cooldown or reward mutation;
- bind the period/problem/method safely;
- never silently map an old `safe / flair / risky` callback to a newly selected method.

Legacy level 3+ `v1` approach callbacks should refresh the current selected problem/offer with a short stale-paper explanation.

Selected problem presentation must show:

- problem-specific scene text;
- 3–4 authored buttons;
- concise qualitative hints when useful;
- visible gold cost where applicable;
- no exact odds or hidden reward numbers before commit.

Result presentation must show:

- scene- and method-specific headline/body;
- no extra biography/signature source labels that reveal race/class/signature mechanics;
- no mechanical labels such as `Расовий спосіб`, `Класова техніка`, `signature` or method-source captions in player-facing result cards;
- grade-appropriate reward/cost lines with a clear `Винагорода за справу` reward block;
- correct follow-up button/state;
- escaped player/content HTML.

The current universal success and complication copy may remain only as defensive legacy fallback. Coverage tests must prove that active content never needs it.

## Non-goals

- No new combat engine or combat formula rewrite.
- No broad generic quest framework for every future activity.
- No persistent skill tree, social-skill XP or new skill-rank database table.
- No mana spending in quest resolution.
- No item loss, negative XP, level loss or punitive long debuffs.
- No large reward/economy increase; level 3+ Adventure Choice may apply only a small stored XP/gold variance and low item-drop chance.
- No shops, crafting, trading, guilds, group raids or new PvP mode.
- No mandatory biography/class gate.
- No rewrite of the separate grown-up cellar quest.
- No production dependency unless strictly required and justified.

## Acceptance criteria

- A selected level 3+ problem no longer renders the global `Обережно / хитрий кут / красиво й небезпечно` ladder.
- Every selected active problem renders 3–4 distinct, scene-appropriate methods.
- Race, class and exact race+class signature/title visibly affect buttons and/or outcomes.
- All active races and classes have starter shawarma and cellar mouse coverage.
- Every valid onboarding race+class combination resolves a deterministic signature method or explicit fallback.
- All 24 general Adventure Choice problems have authored method and grade-specific outcome coverage.
- Generated race, class and title problem families have scene-aware methods/outcomes.
- STR, DEX, INT, CHA and LUCK each govern meaningful methods somewhere in the active pool.
- Existing class skill ids inform quest technique/stat identity without invoking combat damage logic.
- Checks are deterministic, bounded and hidden behind qualitative player-facing wording.
- Strong success, success, mixed success and complication are reachable and tested.
- The pool includes fight, negotiation, deception, bribery, investigation, ritual/performance and trap/track methods.
- At least two non-fight complication kinds are exercised in runtime tests.
- Gold-cost methods check affordability and charge exactly once atomically, including replay/duplicate callback cases.
- A blocked fight handoff spends neither the adventure claim nor a method cost.
- Duplicate/replayed callbacks do not reroll, double-charge or duplicate rewards/items.
- Unknown current-version method ids are treated as stale and do not claim, charge, start cooldowns or grant rewards.
- Level 3+ authored Adventure Choice stores the exact post-resolution XP/gold variance and any low-chance item grant in the daily claim.
- Legacy `v1` Adventure Choice, shawarma and cellar callbacks land in safe states.
- New callback payloads stay at or below 64 bytes.
- Current offer period, three-choice generation, level gates, cooldowns, presence behavior and starter availability remain intact.
- Active content never falls back to the old universal success/complication paragraphs.
- Player-facing copy is Ukrainian, compact, escaped and does not expose hidden path ids or exact odds.

## Manual Telegram QA

1. Create or reset several level 1–2 heroes with different races/classes and open the starter shawarma.
2. Confirm button labels and at least one outcome differ across race, class and exact combo while the scene stays understandable.
3. Complete the shawarma, repeat the old/new callback and confirm no duplicate reward or item.
4. Use level 2–3 heroes in the mouse errand; compare a Домовик, Бюрокромант, Бард, Єгер and another fallback character.
5. Confirm the same cooldown and item-grant safety still hold after personalized methods.
6. Use a level 3+ hero and open the three-problem offer. Confirm the offer itself is stable for the period.
7. Open several different problems and verify their verbs/buttons are genuinely scene-specific rather than renamed risk tiers.
8. Compare two races, two classes and at least two exact combos on the same selected problem using local reset helpers.
9. Exercise a strong success, success, mixed success and non-combat complication using deterministic test/dev inputs.
10. Exercise a fight-handoff complication; verify blocked rest/active-fight handoff does not spend the claim or gold.
11. Exercise a paid method with enough gold, insufficient gold and a repeated callback. Confirm exactly one debit.
12. Press an old `safe/flair/risky` button and confirm a safe refresh/stale-paper screen rather than an arbitrary new method.
13. Check button lengths, paragraph spacing, HTML-sensitive character names and all return paths.
14. Confirm `/dev_adventure_reset` still rerolls the current period and invalidates old method buttons safely.
