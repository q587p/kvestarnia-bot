Runtime summary:
- `TAVERN_GAMES_ENABLED=false` by default keeps `🎲 Ігри за столом` hidden.
- Per-game flags control `♟ Тавлеї` and `🎲 Кості`.
- `/games` appears in help and the Telegram side menu only while tavern games are enabled, and opens the same games hub as the Shynok button.
- Stakes are equal, escrowed in transaction-safe participant rows and settled through terminal payout/refund states.
- Tavlei supports 1v1 tactic choice and automatic win/draw resolution.
- Kosti supports 2-7 players, style + sign choices and automatic 5d6 main/sign bank resolution.
- `🏆 Рейтинг` lists completed table-game win/draw/loss leaders for the last day, week and month; Kosti leaderboard wins use the main-pot winner, not side sign-pool recipients.
- `👀 Хто поруч` in the Shynok lists open tavern game tables and exposes the same join callbacks as the games hub.
- Joins, decisions, resolves and safe refunds send fresh private table cards to other seated participants for both Tavlei and Kosti.
- Completing games now emits rewardless achievement events for first play, first draw, win milestones and loss milestones, and recalculation can prove them from completed table rows.
- Create cooldown copy clearly explains that the player is waiting on a new-table creation pause, not an already-open table, and includes remaining minutes when available.
- Tavlei cancel buttons are visible only to the creator while the table is still open and empty; Kosti resolve-now buttons stay visible only while the table is open or ready; blocked cancel copy explains that cancellation is no longer available after someone joins or the table starts.
- Open Kosti tables stay joinable after early decisions; resolution starts only through creator resolve-now, table cap/ready completion, or join TTL expiry with enough players.
- Per-game flags gate stale rules/create/join/decision/resolve/cancel callbacks; disabled existing tables refund escrow instead of accepting new joins or trapping decision flows.
- Resolver invariant failures use the terminal `failed_safe_refund` path and replay without double refunds.
- `TAVERN_GAME_ACTIVE_SESSION_LIMIT` was removed before merge because the runtime intentionally enforces one active stake session through `activeStakeKey`.

Rollout notes:
- Richer daily net-win enforcement and repeated-pair reporting remain follow-up rollout hardening; this slice stores per-session result audit data.
- New visible gameplay surfaces must keep the achievement checkpoint explicit: either add rewardless hooks for durable visible actions/milestones or document the missing durable ledger before PR-ready handoff.
