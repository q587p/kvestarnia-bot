# 0.2.30 — Item Upgrades / Charkokovalnia

## Goal

Implement the item-upgrades / Charkokovalnia feature package as a separate stacked PR on top of `codex/0.2.29-mantok-ability-grants`.

## Scope Shipped

- Equipment upgrade foundation for eligible gear from `+0` through `+5`.
- Deterministic cost/chance calculation with luck, pity and optional donor modifiers.
- Failure safety: attempts do not break, delete, downgrade or unequip the upgraded item.
- Upgrade levels are represented as concrete item ids (`base`, `base.plus-1` ... `base.plus-5`) instead of a new per-stack column.
- `Іскрокамінь` as a stackable tradeable material item.
- Additive monster reward merge where the small bandage-style material drop resolves to either ordinary bandage or Iskrokamin.
- Very rare authored equipment plus-drops can appear from sufficiently high-level combat rewards, with Luck and effective monster level improving the tiny post-drop chance.
- Charkokovalnia Telegram surface under the Korchma hall with compact stable item callback keys.
- NPC Plusoslav orders for higher-level upgrade preparation; combat wins can advance pending orders.
- Mage-style self upgrade method, `Іскровий підкрут`, with mana spend and weaker odds.
- Item detail, equipment and effective-stat presentation of `+N` upgrades.
- Rewardless achievements for first Iskrokamin, upgrade success/failure, donor use, `+5`, set-item upgrade and completed Plusoslav order.
- Local QA helpers:
  - `/dev_add_iskrokamin [count]`
  - `/dev_set_item_plus itemId=<item.id> level=0..5`
  - `/dev_set_upgrade_pity itemId=<item.id> target=1..5 failures=0..5`
  - `/dev_complete_upgrade_order`
  - `/dev_cancel_upgrade_order`

## Data Model Decision

The current repository does not have per-copy item instances. Inventory is stored as one `CharacterItem` row per `(characterId, itemId)` with quantity, and equipment points at `itemId`.

For this slice, enhancement level is encoded in the owned `itemId`: base items remain `+0`, while upgraded copies use generated content ids such as `item.pan-of-persuasion.plus-1`. An upgrade atomically moves one copy from the current id stack to the next id stack and updates equipment rows that pointed at the old id.

Same-template donor support therefore consumes one item from the same current-level stack when quantity is at least `2`. A later true item-instance migration can split individual copies more richly without changing the player-facing Charkokovalnia contract.

Pity and Plusoslav order state reuse the existing daily-action ledger with item-upgrade keys instead of adding new Prisma tables in this PR.

## Balance Notes

- Upgrade caps at `+5`.
- Pity adds bounded chance after failures and guarantees after the configured repeated-failure threshold.
- Donor bonuses are helpful but do not bypass gold/mana/material spend.
- Mage self-upgrade is weaker than NPC upgrade and spends mana.
- Set bonuses do not scale with `+N`; only the item primary equipment stat receives the visible enhancement bonus.
- Random plus-drops are post-selection upgrades: they do not raise the overall item drop rate, require level 5+ sources, cap at a very low chance, and gate higher `+N` behind higher effective monster levels plus additional falling checks.

## Out Of Scope

- Shops, market, crafting recipes or broad economy surfaces.
- True item-instance storage.
- Broad generated upgrade loot; this PR only allows a very rare bounded post-drop upgrade for authored eligible equipment.
- Broad combat formula rebalance.
- Breaking existing Mantok set or ability-grant semantics.
