# 0.3.6 - Bureaucramancer Personal Protocol 13-Z

Status: active release candidate in PR #158; review-fix regression coverage and full local automated checks pass, with refreshed CI and review still required before merge. An earlier-runtime Telegram pass was partial and found a stale leader recruiting card plus easy-to-miss cooldown feedback; the fixes have not been rechecked in a refreshed runtime. Merge, deploy, and full manual Telegram QA are not proven.

## Goal

Ship a narrow `class.bureaucramancer` social raid-prep action for Big Barrel Brother recruiting.

A level 3+ Bureaucramancer can file `Форма 13-А` during a live Big Barrel Brother recruiting session to open `Протокол 13-З: персональні претензії`. Joined participants may sign once. When the fight starts, each signer blocks the first eligible personal/single-target boss attack against themselves.

This is not a generic bureaucracy engine, a combat class ability catalog change, Warrior Taunt, or broad party mitigation.

## Release Candidate Behavior

- Eligible joined level 3+ Bureaucramancers see `📄 Форма 13-А` on live Big Barrel Brother recruiting cards.
- Filing costs `8 - min(3, floor((level + effective intelligence) / 8))` mana, starts a 93-minute Bureaucramancer cooldown only after committed success, creates at most one protocol per recruiting session, and auto-signs the filer.
- A committed protocol remains owned by the recruiting session if its filer leaves; only final joined, remort-valid signatures are frozen into the raid, and a second protocol cannot replace it.
- Duplicate filing callbacks replay the existing state without a second mana spend, second protocol, or duplicate signature.
- Joined participants can sign the open protocol once for free before raid start.
- Duplicate sign callbacks replay the signed state without changing the signature count.
- Non-joined, stale, expired, terminal, non-Big Barrel, remort-mismatched, active-combat-blocked, ineligible, cooldown, and insufficient-mana paths fail closed with Ukrainian copy.
- Recruiting cards show only compact protocol state and signature count. Signer names are not public.
- Successful filing/signing refreshes every stored joined-participant recruiting card, including the actor's canonical card when the callback came from another copy.
- A filing cooldown blocker sends a separate durable message with the canonical remaining wait; a transient callback alert is never the only explanation.
- Starting the Big Barrel fight freezes the joined signer set into party-boss state.
- Each signer blocks the first eligible personal/single-target Big Barrel retaliation against themselves. The stored boss action id, turn, prevented damage, spent count, and signature count replay from boss state.
- `Бочковий гуркіт`, broad/all-party attacks, unsigned targets, and later personal attacks after a signer protection is spent are not blocked.
- Kharakternyk ward signs remain the broad Big Barrel mitigation. Protocol 13-З runs only on focused personal retaliation, so the same broad damage event is not reduced twice.

## Persistence

- No Prisma schema migration.
- Recruiting state is stored in `PartyParticipant.snapshotJson`:
  - `bureaucramancerPersonalProtocol13B`
  - `bureaucramancerPersonalProtocol13BSignature`
- The filer cooldown uses `characterCooldown` key `class.bureaucramancer.personal-protocol-13b.cooldown`.
- Started Big Barrel boss state freezes only joined, remort-matching signatures into `PartyBossState.personalProtocol`.
- Every committed filing has a unique protocol id. Signature identity is the complete `protocolId + filerCharacterId` pair.
- Leaving and rejoining in the same remort life preserves only validated protocol/signature snapshot extensions; a remort mismatch starts from a fresh character snapshot.
- Raid start compare-and-swaps the exact recruiting party version, re-reads canonical party state inside the transaction, then freezes roster, ward, and protocol state. Losing preparation callbacks do not spend resources.
- Join/rejoin, leave, readiness, ward support, and Protocol 13-Z signing claim the recruiting session version before participant writes in the same transaction; a participant/remort/protocol mismatch rolls the claim back.
- Join, leave, readiness, and ward-support CAS losses return the canonical terminal/result state when provable, otherwise an explicit stale result; they do not report a false domain success or failure.
- Exhausted Protocol filing and Kharakternyk ward-placement CAS retries report duplicate success only when the canonical protocol or ward exists; otherwise they return explicit stale state without spending mana or starting cooldowns.
- Join, leave, and cancel callbacks against an already active or completed party return explicit stale state for the canonical participant or leader instead of misreporting expiry, membership, or leadership.
- Participant membership keys are cleared only when the matching recruiting-to-terminal parent transition commits, so a concurrent raid start keeps its active roster discoverable.
- Protocol INT and Mantok Chest confirmation LUCK query attunement rows by the exact current equipment identities rather than a bounded history window. Mantok confirmation LUCK also includes a currently active Priest blessing as part of canonical effective LUCK.

## Charkokovalnia Balance Evidence (No Retune)

Baseline NPC attempts at LUCK 10 with no donor, including current pity, are approximately `1.051 / 1.198 / 1.446 / 1.859 / 2.427` for `+1..+5`. That puts expected gold fees at `52.55 / 143.80 / 375.94 / 929.42 / 2184.40`, plus expected Iskrokamin consumption of `5.26 / 15.58 / 33.26 / 78.07 / 225.72`. Across currently authored upgradeable variants, nominal values span `36..360 / 42..482 / 144..774 / 162..1204 / 600..1720`; the 42% Mantok sale payout spans `16..152 / 18..203 / 61..326 / 69..506 / 252..723`.

No formula is changed in this pass. There are 27 authored `+1` transitions where the expected sale-payout increase exceeds the expected 50-gold NPC fee by up to about `49.45` gold if Iskrokamin is treated as having zero opportunity cost; no such positive margin appears for `+2..+5`. Whether that gold-only view is acceptable requires an explicit product decision after 0.3.6 rather than an implicit retune here.
