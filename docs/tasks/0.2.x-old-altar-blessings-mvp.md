# Old Altar Blessings MVP

## Goal

Ship the first **Old Altar** runtime slice:

- make the Korchma Yard a stable route to `🪨 Старий жертовник`;
- add private gold offerings that grant per-character `Благовоління`;
- let level 3+ Priests at the yard spend mana + `Благовоління` to apply one short selected-stat blessing to self or active same-yard targets;
- preserve the existing direct Priest heal/bless behavior from `Хто поруч`.

Do not implement item offerings or a separate grove location in this task.

## Versioning

Use the next versioned task number after verifying current `main` and `package.json`. Do not assume this document's filename is the final versioned task path.

This is a docs-only draft until a human explicitly activates it as a concrete versioned task.

## Player-facing names

- Surface: `🪨 Старий жертовник`
- Offering action: `🎁 Принести требу`
- Resource: `Благовоління`
- Priest altar action: `✨ Провести обряд`

## Scope

### Location / UI

- Update the existing `Задвірок корчми` card to mention the old altar.
- Add a `🪨 Старий жертовник` button on the yard keyboard.
- Ensure `🪣 У задвірок` is reachable from `Перед корчмою` when this feature is available, while preserving current daily-yard quest markers.
- Add altar open/help/offering/ritual cards and keyboards.
- Keep presence as `location.korchma.yard`; do not add a new presence location in this MVP.

### Economy

- Add a per-current-character/remort-life altar account/balance for `Благовоління`.
- Add a replay-safe offering ledger.
- Gold-only MVP:
  - `13 gold -> 1 Благовоління`.
  - cap gold offerings at `3 Благовоління` per current character/remort life per Kyiv day.
- Offerings are private; no public feed row.
- No XP, quest progress, hunt progress, reward multiplier or item grants.

### Priest altar blessing

- Actor requirements:
  - current character exists;
  - `class.priest`;
  - level >= existing `CLASS_NONCOMBAT_MIN_LEVEL`;
  - current location is `location.korchma.yard`;
  - not in combat or raid;
  - enough mana;
  - enough `Благовоління`.
- Target scope:
  - self;
  - active same-yard targets using existing active presence cutoff semantics.
- Blessing types:
  - `Тверда рука` -> `strength`;
  - `Легкий крок` -> `dexterity`;
  - `Ясний розум` -> `intelligence`;
  - `Ласкаве слово` -> `charisma`;
  - `Добра прикмета` -> `luck`.
- Use one visible Priest blessing status.
- Duration: existing Priest blessing duration (`13 minutes`).
- Repeat wait: existing same actor-target Priest blessing wait (`93 minutes`).
- No stacking: block if target already has an active Priest blessing.
- Bonus: selected stat `+1..+3`.
- Mana cost: `[8, 12, 16]` for `+1..+3`.
- Favor cost: `[1, 2, 3]` for `+1..+3`.
- Notify a different target privately after durable mutation, following current Priest blessing notification behavior.

## Non-goals

- No item/manatka offerings in this MVP.
- No new `Тихий Корінь` / root-grove presence location.
- No accept/decline request flow for non-Priests asking Priests.
- No resurrection, death save, heavy defeat, ambush, travel or adventure-choice effects.
- No loot multiplier status separate from `luck`.
- No public latest-events rows for offerings.
- No achievements in the first draft unless the activated implementation stays small enough to add a rewardless first-offering / first-altar-rite hook safely. If achievements remain out of scope at implementation time, the task doc and PR body must say why.
- No broad noncombat/profession engine.
- No changes to ordinary direct Priest heal/blessing semantics.
- No combat formula rebalance.

## Data model acceptance

The implementation must durably know:

- current character/remort-life favor balance;
- gold offerings by local Kyiv day;
- favor spent on each altar blessing;
- selected `bonusStat` and `bonusAmount`;
- actor/target snapshots sufficient for replay/audit.

It must not let favor carry across remort/current character life boundaries.

## Callback and stale handling

- All callbacks must stay under Telegram callback data limit.
- Recheck current actor character, remort count, class, level, location, active flow and balance at mutation time.
- Recheck target active same-yard presence at mutation time.
- Stale offering confirmation must not spend gold twice.
- Stale blessing confirmation must not spend mana/favor twice.
- Duplicate/replayed terminal callbacks show the stored result or a safe no-op card.

## Acceptance criteria

### Yard / altar route

- Yard card mentions the old altar.
- Yard keyboard has `🪨 Старий жертовник`.
- Front route exposes yard when feature is enabled while preserving daily yard markers.
- Opening altar keeps the current presence at `location.korchma.yard`.

### Gold offering

- Character with enough gold can confirm `13 gold -> 1 Благовоління`.
- Gold is deducted and favor is granted in one durable transaction.
- Replaying the same confirmation does not double spend or double grant.
- Character without enough gold receives a no-spend blocker.
- Daily cap blocks after 3 favor gained from gold offerings on the same Kyiv day.
- Favor balance is scoped to current character/remort life.

### Priest altar blessing

- Eligible Priest at yard can bless self using favor + mana.
- Eligible Priest at yard can bless an active same-yard target; target receives private notification.
- Non-Priest can open altar and offer gold but cannot conduct the rite.
- Priest outside yard cannot use the altar rite from stale callbacks.
- Priest in combat/raid cannot use the altar rite.
- Target in combat/raid is blocked if current class noncombat target gates block it.
- Target already holding an active Priest blessing is blocked; no stacking.
- Same actor-target repeat wait is enforced.
- Selected stat appears in the resulting blessing and affects effective summary while active.
- Expired altar blessing does not affect effective stats.
- Direct Priest blessing from `Хто поруч` still gives the existing luck blessing and keeps current behavior.

### Developer / QA support

- Add a narrow non-production `/dev_*` helper for local QA before calling the implementation PR ready.
- Useful helper scope can be one or more of:
  - set or grant a small `Благовоління` balance;
  - reset the gold-offering Kyiv-day cap for the current character;
  - clear the altar/direct Priest same-target blessing wait;
  - expire the active Priest blessing for the current character.
- Production config must not register, show or mutate through the helper, even if a feature-specific helper flag is set.

### Balance

- No XP/gold/item reward is created by blessing.
- Offering is a gold sink only.
- Blessing does not directly change reward amounts, quest progress, Yeger progress or loot formulas.

## Manual Telegram QA

1. Open front, go to yard, open `🪨 Старий жертовник`.
2. Offer gold with enough gold; verify gold decreases and favor increases.
3. Replay/refresh old confirmation; verify no duplicate spend/grant.
4. Hit daily cap; verify blocker.
5. Open altar as non-Priest; verify offering works and ritual is explained/blocked.
6. Open altar as level 3+ Priest at yard; bless self with each available stat type.
7. Verify hero card shows the selected stat bonus while active.
8. Verify expired blessing no longer affects stats.
9. Bless another active same-yard target; verify private notification.
10. Try same target again; verify 93-minute wait blocker.
11. Try while in combat/raid; verify no mutation.
12. Verify existing `✨ Жрецька поміч` direct heal/bless still works outside altar.
