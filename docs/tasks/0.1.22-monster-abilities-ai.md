# 0.1.22 — Monster Abilities, Titles, Skill Identity, Battle Journal & Passage Presence

Target version: `0.1.22`.

This task imports the monster ability/loadout proposal after `0.1.21` Combat Action Foundation was merged into `main`. The proposal JSON was treated as authored design input and converted into typed, validated content catalogs.

## Goal

Give every canonical non-training monster a small frozen ability loadout and a fair AI that still uses basic attacks and defense.

Complete the currently selectable character-title matrix and make every current class combat skill identity distinct without changing class skill balance.

Clean up active persistent fight copy, switch overdue persistent PvE turns from auto-attack to auto-defend, store a paged battle journal for resolved turns, and make the three Nyz passages distinct social locations.

## Scope

- Typed content catalogs for 132 monster abilities and 93 monster combat profiles.
- Runtime compiler/audit coverage for every authored monster ability parameter; unsupported, invalid or effectless parameters fail content validation instead of becoming silent no-ops.
- Backward-compatible `CombatState.monsterRuntime` JSON for frozen loadouts, cooldowns, once-per-fight usage, telegraphs, shields and short-lived effects.
- Pure monster AI/effect runtime in `src/domain/combat`, used by persistent fights, timeout auto-defend recovery and failed flee responses.
- Hardened runtime semantics for shield absorption, effect duration/charge consumption, direct-damage defense formulas and fallback loadout safety.
- Compact player-facing presentation for named monster actions, telegraphs, shields/heals and stored bark IDs.
- Combat simulator action-mix and ability-usage metrics through level 23.
- Authored combo titles for every active selectable race/class/pronoun path, while keeping generic fallback titles defensive for unknown or legacy combinations.
- Distinct class skill IDs and player-facing labels for Mage vs Varenyk-mancer and Rogue vs Ranger, with legacy cooldown aliases for in-flight combats.
- Persistent fight turn logs stored in combat state JSON and browsed from terminal/result cards through a paged `Журнал бою` view.
- Persistent PvE timeout recovery now commits `defend` with `timeout-auto-defend` instead of a basic attack.
- Nyz left/straight/right passage buttons are separate presence locations, so nearby-player/duel discovery and post-fight `Новий бій` preserve the chosen passage instead of merging everyone into the shared tier landing.
- `Хто поруч` only shows `Кинути виклик присутнім` when at least one other active same-location duel target exists.
- Fight copy cleanup for active cards: no service-log "turn recorded" note, no repeated `Остання дія` heading, named skill cooldowns, clearer monster response wording and visible monster ability consequences.
- Active persistent fight and training keyboards keep `Вдарити` and `Захищатися` in one compact first row.
- Monster context cues must not ship mojibake placeholder text such as `????`.

## Non-goals

- No player race/signature/title abilities.
- No item or consumable active abilities.
- No multi-enemy, party, raid or boss-lobby runtime.
- No Yeger matching/progress change.
- No timeout cap, participation gate or auto-victory reward suppression.
- No reward/economy/loot rebalance.
- No new Prisma analytics migration.
- Training doppelganger keeps copied class-skill behavior.
- No title-specific, race-specific, signature or item player ability catalog.
- No class skill damage, accuracy, crit, mana, cooldown, mitigation, reward, loot or economy rebalance.
- No schema migration for battle logs; journal entries live in existing combat state JSON.
- Training doppelganger and turn-based duel timeout semantics are not changed by the persistent PvE timeout pivot.

## Behavior Decisions

- New ordinary monster fights freeze selected ability IDs at combat start. Old active fights without `monsterRuntime` keep legacy basic-attack behavior until they finish.
- Explicit authored ability IDs fill identity slots first. Deterministic fallback only fills legal missing slots after difficulty scaling raises the effective level.
- Ordinary monsters cannot use abilities on consecutive monster actions. Boss profiles can chain at most two different abilities before owing a basic/defend action.
- Telegraph abilities spend one monster activation warning the player, then resolve the promised ability on the next legal monster activation if the monster is still alive.
- Class-skill locks are server-authoritative no-ops: no mana, turn, cooldown, monster action, bark or RNG advance when the locked skill is pressed.
- Group-ready target scopes degrade to the current solo fight target set; no Telegram user IDs enter target resolution.
- Ally/group-only support abilities must compile to an observable solo fallback, such as self-shield, self-heal, resistance or protection; otherwise content validation fails.
- Monster runtime shields account absorbed and applied damage from pre-hit HP, without healing or reviving the monster.
- Runtime effect durations tick on committed activations, while charges are consumed only by their matching event: marks on later direct monster hits and reflect on actual reflected HP damage.
- Marks are resolved through one direct monster-hit modifier path, so ordinary forced basic attacks can consume them exactly like monster abilities; missed basics, defend-only turns, telegraphs, shields and heals do not consume them.
- Authored monster ability riders now have persisted event semantics: turn parity/cycle riders choose bounded effects deterministically, repeated-action prediction only punishes an actual repeated committed hero action, expired-effect reapply uses a bounded negative-effect snapshot, copied potency remembers the last direct hero damage, shield-survival bonuses arm only after a shield survives incoming damage, and counter chance rolls injected RNG.
- Runtime basic attacks use the same defend stance contract as legacy monster basics: evasion, damage reduction, fatigue and bounded counter chance. Runtime ability mitigation applies the stance once, not as a second hidden flat reduction.
- Target accuracy/evasion penalties affect later target rolls; current monster ability accuracy uses only caster accuracy penalties and context accuracy once.
- Positive monster accuracy context now raises current runtime ability hit chance, negative context lowers it, and monster evasion affects the hero hit roll only instead of also reducing successful hit damage.
- Support/control abilities are legal only when they can change state: equal-or-stronger shields, empty cleanses, missing cooldown targets, missing positive effects and missing expired effects do not produce misleading consequence text.
- Monster abilities now compile into an explicit per-component execution plan before legality checks and resolution. Each component records its source parameter, target actor, condition, duration/charges, direct-hit requirement and applied-result key, and AI legality uses the same plan as resolution.
- Optional heal riders no longer gate the whole ability when healing is unnecessary; direct damage, shields, self-buffs and eligible purge/control riders can still resolve independently, while pure healing with no observable state change remains illegal.
- Low-HP damage parameters are normalized as additive bonuses to the authored base multiplier, not replacement multipliers.
- Turn-cycle riders resolve only the selected persisted activation branch. `monster.fire-safety-cycle` no longer applies fire damage, self-shield and potency-down riders together.
- Runtime basic attacks and monster abilities share the same direct-hit modifier rule: marks and next-attack bonuses are consumed only by actual landed direct hits after defend evasion is known.
- Repeated-action prediction tracks eligible committed hero hits, misses and defense; rejected/no-op skills do not update it, and the penalty expires by target activations even if the player avoids repeating.
- Mixed-scope buffs route by parameter intent rather than a self-only heuristic, so `monster.mountain-on-installments` marks the hero while buffing the monster's outgoing damage.
- `lockAbilitySource: "race"` uses a documented non-lock solo fallback while race actions are not implemented; `"class"` still locks the current class skill.
- Player-facing monster result text is based on applied results only: heal, shield, cooldown, purge, cleanse and reapply lines appear only when state changed.
- Runtime effects now carry or derive an explicit target/polarity/removability/source contract in combat-state JSON. Legacy effects without that metadata remain readable, but cleanse/purge decisions use the normalized contract instead of broad target guesses.
- `cleanseNegativeEffects` removes only harmful removable monster effects; monster shields, evasion, outgoing-damage buffs, next-hit bonuses, reflect and status resistance survive it. `removePositiveEffects` is truthful and only announces a purge when a real removable beneficial hero effect was removed.
- `statusResistancePp` resolves as an explicit non-removable monster `status-resistance` runtime effect fallback while broader status-resistance mechanics remain future scope.
- Zero-damage monster support actions that actually change state are stored as successful monster outcomes in turn summaries, durable logs, journal replay and analytics instead of being inferred as misses from `damage === 0`.
- Direct-hit-required monster components now execute only after an actual landed direct hit: attack chosen, hit roll succeeded, defend evasion failed and final direct damage stayed above zero. Misses, defend evasion, telegraph announcements, monster defend and support-only actions do not apply or consume those riders.
- Every compiled monster component now receives an explicit trigger classification (`on-cast`, `on-landed-direct-hit`, deferred shield/counter/activation triggers), so equivalent hostile riders such as burn, chill and outgoing-damage reductions follow the same matrix while self-support and cycle support branches remain independently applicable.
- Effect consumers use target plus polarity or documented magnitude semantics: beneficial hero accuracy/evasion/flee rows are not interpreted as penalties, and `bonusAgainstDebuffedTargets` counts only active harmful hero effects.
- `nextAttackBonusIfShieldSurvives` no longer creates a neutral next-hit placeholder at cast time. The exact authored shield must absorb damage and survive before one bounded next-hit bonus is armed; broken shields and old neutral value-1 states do not arm, block or consume the real bonus.
- Deferred next-hit bonuses use source/trigger identity, so copied-potency and shield-survival bonuses can coexist, repeated shield survival refreshes only its own source and one landed direct hit consumes the active stacked next-hit window exactly once.
- `copyLastDirectActionPotency` derives a bounded replay-safe next-hit multiplier from persisted `lastDirectHeroDamage`, with a small deterministic fallback when no eligible direct hero action exists.
- `counterChance` is stored as an explicit probabilistic counter effect, not as flat reflect damage. It rolls injected RNG, derives damage from the authored source and current monster attack, keeps its charge on failed rolls and consumes one charge on a successful counter.
- Monster defend, telegraph and retained timeout-skip paths preserve resolver outcomes instead of recomputing zero-damage actions as misses.
- Deterministic fallback loadouts filter unsupported recipes and avoid low-level strong/ultimate fallback picks.
- Active race/class/pronoun choices must never fall back to `Пригодник місцевого значення`, `Пригодниця місцевого значення` or `Пригодники місцевого значення`.
- `class.varenyk-mancer` uses `skill.boiling-filling` / `🥟 Кипляча начинка`; `class.rogue` uses `skill.shadow-cut` / `🌘 Тіньовий різ`. Their numeric profiles remain the old shared Mage/Ranger values.
- Legacy persisted cooldowns under `skill.hot-spell` and `skill.trick-shot` still block the renamed Varenyk-mancer/Rogue skills until the cooldown naturally ticks away; new skill use stores only the new IDs.
- Overdue persistent PvE turns put the hero into `🛡 Захищатися`; old `auto-attack` debug values remain readable as legacy state.
- Battle journal pages show one stored turn at a time, with first/previous/next/last navigation and a return button.
- Battle journal buttons are shown only after a fight reaches a result. Terminal journal views return with `↩️ До результатів`; new `turnLog` rows store explicit `terminal:*` event IDs for `won`, `lost`, `fled` and `expired`, while older/partial state still synthesizes the terminal `lastTurn` page safely.
- Durable battle history is capped at 587 stored turn-log entries, which is intentionally above the current hard session lifetime while bounding combat-state JSON.
- Active fight cards show the 23-second timeout rule directly below the named `що робимо?` prompt, without an empty spacer.
- Timeout recovery refreshes the current combat row before committing an automatic turn, so stale due records preserve newer active-card message references.
- `Ярус I: Сутерени Корчми` remains the shared landing/choice screen; `Лівий прохід`, `Прямий прохід` and `Правий прохід` are specific locations used for fight origin, nearby candidates and same-passage rematches.
- Entering a specific passage shows a pre-fight passage card with the spotted monster and `Атакувати` / `Повернутися до Сутеренів`; combat starts only after `Атакувати`, using the preview encounter seed.
- Persistent fight callbacks, journal/result replays and combat-lock redirects restore presence from the stored fight origin instead of stamping the quest table.
- Legacy active fights without `originLocationId` are not backfilled; they use the neutral straight-passage fallback for `Новий бій` and generic `Низ` return routing until they finish.
- Terminal result cards expose `Новий бій` only for ordinary Nyz passage origins; non-passage origins return to their original surface without starting another fight from the result card.
- Night `🎒 Манчкін-скупник` level-barter return buttons point back to `Спуск до Низу`, not the outside front door.
- The persistent reply keyboard labels its place button with the current known location when a normal reply-keyboard message is rendered; location-changing inline callbacks no longer send standalone `📍 <місцина>` refresh messages, and pressing any recognized location label opens the current location surface/actions instead of always jumping to the generic korchma hall.

## Acceptance Criteria

- Content validation finds exactly 132 stable ability IDs and 93 current monster profiles with no missing/extra monster IDs.
- Content validation compiles every authored monster ability into at least one legal runtime consequence and covers every `MonsterAbilityParameterKey`.
- New fights persist a frozen runtime block; legacy rows lacking it remain readable and legacy-safe.
- Monster AI is deterministic under injected RNG and falls back to basic attack when no legal ability remains.
- Shields, marks, reflect, cooldown pressure, target accuracy/evasion penalties and runtime defend semantics are covered by focused regression tests.
- Parity/cycle riders, repeat prediction, expired-effect reapply, copied potency, shield-survival setup, counter chance and reactive terminal precedence are covered by focused regression tests.
- Runtime accuracy, evasion-as-hit-probability-only, and selected-passage presence restoration are covered by focused regression tests.
- Runtime state round-trips through the Prisma solo combat repository without unsafe blanket casts.
- Fight cards show concise Ukrainian labels/effects without exposing internal weights or effect keys.
- Runtime effect polarity/removability/source metadata is persisted or derived safely for legacy rows; malformed effect metadata is ignored without dropping the whole combat state.
- Monster cleanse, purge, status-resistance fallback and support-only outcomes are covered by focused regression tests and the 132-ability semantic audit.
- Trigger-based components, deferred next-hit/counter effects and monster non-attack outcomes are covered by focused regression tests and the 132-ability semantic audit.
- Trigger classification, polarity-aware consumers, effect merge identity and combined next-hit source handling are covered by focused regression tests and the 132-ability semantic audit.
- Timeout auto-defend recovery calls the same monster AI exactly once.
- Yeger progress and reward semantics remain unchanged.
- The derived active title matrix has 54 valid pairs, every valid pair has at least one allowed pronoun, every valid race/class/pronoun triple has an authored unique title for that pronoun, and invalid/unknown combinations still return defensive fallback titles.
- All nine current classes map to unique class skill IDs and distinct player-facing skill labels.
- Persistent PvE, training doppelganger and turn-based duel skill rendering all use the new class skill identities.
- Active fight cards do not show `Хід записано` or an `Остання дія` heading, skill cooldowns name the exact skill, and monster ability summaries include damage/effect/no-direct-damage consequences.
- Active persistent fight and training keyboards place `Вдарити` and `Захищатися` in the same row.
- New successful persistent turns append durable `turnLog` entries, while unavailable skill no-ops do not add fake journal rows.
- `Журнал бою` appears only on terminal/result cards, can page through stored turns plus the terminal result turn exactly once, and returns to the result card without mutating combat state.
- Nyz passage callbacks open the matching passage preview/location; `Атакувати` starts the matching difficulty from that passage, old `fight-hard/normal/easy` callbacks map to the same passage locations, and `Новий бій` reuses the stored passage origin when available.
- Legacy terminal persistent fights without `originLocationId` pin to the neutral straight-passage fallback.
- Duplicate persistent fight turn callbacks stale out without duplicate reward/level-up side effects.
- `Хто поруч` does not show the nearby challenge button for a one-person location containing only the current player.
- Scheduled/lazy timeout turns edit the latest stored active-card message reference when a newer battle card was opened before the due tick resolved.
- Monster context cues are covered against `????` placeholder mojibake.
- Night Munchkin level-barter open/preview/result cards return to `Спуск до Низу`; daytime/default cards still return to the front door.
- Persistent reply-keyboard location labels are derived from current presence, and all recognized location labels route through the current-place lookup.
- Location-changing inline callbacks do not send standalone `📍 <місцина>` reply-keyboard refresh messages under the inline card.
