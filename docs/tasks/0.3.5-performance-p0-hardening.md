# 0.3.5 - Performance P0 Hardening

## Status

Queued as the next implementation task. This docs update only records the task; do not start implementation from this change.

## Source

Based on the static performance audit package provided as `kvestarnia-performance-audit.zip`, especially the P0 task files:

1. `01-instrumentation.md`
2. `02-daily-action-bounded-queries.md`

The audit was static, not a live production profile. Treat instrumentation as the first step so later ranking uses measured route, DB, compute, Telegram API, and row-count data instead of guesses.

Before editing code, verify the current `main` branch against this task. The `0.3.3` follow-up already landed some Yeger paid-bandage early-return, slow-route timing, and paid-bandage `DailyAction` narrowing work; this task should preserve that behavior and complete the remaining P0 gaps rather than duplicating or reverting it.

## Goal

Make the current Telegram callback hot paths measurable and bounded before inviting more players. The release should add low-noise performance instrumentation, remove unbounded `DailyAction` scans from hot paths, make the Yeger bandage purchase path cheap, and narrow Daily Korchma Round step-row loading to the current day.

## Scope

### 1. Instrumentation

Add structured, low-noise timing around route, service, repository, and Telegram API boundaries.

Cover at least these surfaces:

- Inventory page, filter, and item-detail callbacks.
- Yeger open, bandages, buy preview, confirm, cancel, and free bandage callbacks.
- Daily Korchma Round overview, scene, action, and claim callbacks.
- Mantok Chest overview, auto preview, manual selection, and confirm callbacks.
- Item upgrade list, preview, and attempt callbacks.
- Fight overview, turn, and reward callbacks.
- Main menu keyboard with quest markers.

Requirements:

- Gate production sampling by environment/config.
- Always log calls above the slow threshold.
- Separate `dbMs`, `computeMs`, and `telegramMs` where practical.
- Include bounded row counts for heavy repository calls.
- Do not log player-facing text, large JSON payloads, secrets, tokens, or private chat content.
- Keep logs compact enough for the current Render runtime.

Suggested shape:

```ts
const span = startPerfSpan("yeger.buy-bandage-preview", { telegramUserId });
// ...
span.end({ resultState, rows });
```

### 2. DailyAction bounded queries

Remove unbounded historical `DailyAction` scans from hot paths.

Problem to solve:

- Existing hot paths can call broad `listForTelegramUser({ key })`-style methods that return every historical row for a key.
- `countLimitedActionQuantity`-style behavior can load all rows and filter JSON in memory.
- The Yeger bandage purchase limit and Daily Korchma step lookup get slower as accounts accumulate days of history.

Expected implementation direction:

- Extend `DailyActionRepository` with purpose-specific bounded methods, such as current-day prefix lookup, `existsAnyForTelegramUser`, and daily item quantity aggregation for paid claims.
- Use Prisma-side filters and row-count logging.
- Add the required `DailyAction` index coverage, including a new index shaped for character, key, and time filtering while preserving the existing idempotency uniqueness contract.
- Replace hot-path unbounded uses for Yeger bandage daily counts, item `quantityLimit` claims, Daily Korchma step records, Friday Barrel first-solo-raid checks, and easy starter historical completion checks.
- Keep broad legacy/admin/dev list methods only where intentionally non-hot, and document the hot-path warning near them.

### 3. Yeger bandage fast path

Make Yeger bandage preview, confirm, and cancel self-contained and cheap.

Expected behavior:

- Successful `buy-bandage-preview` should answer the callback, mark presence, render `presentYegerBandageBuy(result)`, attach `buildYegerBandagePurchaseKeyboard(result.token)`, and return.
- Successful preview must not rebuild the full Yeger menu, quest state, craft options, quest markers, field-kit help, or broad navigation; if current `main` already has this fast path, add or tighten coverage instead of rewriting it.
- Confirm/cancel success, replay, and cancellation states should use a cheap keyboard with back-to-Yeger and back-to-Barrel navigation.
- Rebuild the full Yeger menu only for stale, locked, daily-limit, no-character, or affordable-preview fallback states.
- Combine this with the bounded `DailyAction` quantity fixes from this same task.

The `93 бинти` preview path is the main smoke case: it should not grow with historical bandage rows.

### 4. Daily Korchma Round step query

Make Daily Korchma Round context load only the current day's step rows.

Expected implementation direction:

- Change `listStepRecords`-style behavior to query by the current `localDatePrefix`, such as `${dayKey}:`.
- Keep JSON scene-id validation after DB filtering.
- Add a low cap/take so the route remains bounded even after unusual data growth.
- Preserve current player-facing behavior for overview, scene, action, and claim callbacks.

## Non-Goals

- Do not implement P1/P2 audit items in this release unless measurements reveal a tiny urgent follow-up needed to complete P0 safely.
- Do not redesign quest markers, achievements, Mantok Chest cleanup, inventory rendering, combat, or broad caching as part of this task.
- Do not change balance, rewards, item names, class identity, or player-facing Ukrainian copy unless a small text adjustment is unavoidable.

- Do not add unrelated Prisma schema changes.

## Acceptance Criteria

- Slow-route logs can identify whether time is spent in DB, compute, or Telegram API calls.
- Logs include row counts for newly bounded heavy repository calls.
- No new production hot route in this task calls an unbounded `DailyAction` list method for key-based history.
- Yeger paid bandage preview avoids full menu recomputation on the normal successful preview path.
- Yeger confirm/cancel remain idempotent for replayed callbacks.
- Daily Korchma scene/action routes load a bounded current-day step set regardless of account age.
- Existing idempotency and replay behavior is preserved.
- No player-facing text, large JSON payload, secret, token, or private chat content appears in perf logs.
