# 0.2.8 — Achievements and Cosmetic Title Records

## Goal

Ship the first rewardless achievements surface and persisted cosmetic title grant records. Players can browse earned, locked and hidden achievements from `/hero`, while future title-selection/title-ability work can read stable title-grant provenance without adding power in this release.

## Scope

- Add typed achievement definitions and validation, with a first catalog that is large enough to make the journal feel worth browsing.
- Persist `CharacterAchievement`, `CharacterAchievementProgress` and `CharacterCosmeticTitleGrant`.
- Unlock a seed set from existing successful boundaries:
  - character creation;
  - current race/class identity, so remort choices can grow a collection over time;
  - level reached and level milestones;
  - combat finished and terminal combat counts;
  - problem quest turn-in and completed problem-chain stage counts;
  - restored Phase 1 records for list opening, level 8, first remort, starter shawarma/cellar/Yeger/adventure rows, problem-chain 93, senior-fight milestones and special stored fight outcomes where current rows can prove them;
  - item received through existing reward claims, carried manatky totals and `Бинт відповідальної паніки` owned/used thresholds;
  - item equipped and equipped manatky counts;
  - existing durable side-action ledgers for chest recycling, level barter, Doppleganger training wins, quick/turn-based duels, Barrel, Korchma rounds, gifts, manatka sales, Bard performances, Yeger free bandage claims, drinks, passage searches, hunt contracts, Adventure choices and Nyz threat pressure.
- Add `🏅 Ачівки` to the character screen with earned, locked, hidden and paged rows.
- Add achievement filters for all, earned and locked rows.
- Add a manual `🔎 Перевірити` action that idempotently recalculates currently provable achievements for existing characters from persisted state.
- Use historical stored dates for recalculated achievements when existing ledgers can prove the original event time.
- Group unlock notifications from one successful action.
- Route local dev grant commands through the same achievement tracking flow where the grant mutates level or items.
- Document the shipped catalog, including secret/disabled entries and future ledger gaps, in `docs/ACHIEVEMENTS_CATALOG.md`.

## Non-goals

- No XP, gold, item, stat, loot, quest, Yeger, Shynok, remort or combat rewards from achievements.
- No active title selection.
- No active title ability runtime or title combat button.
- No party/raid runtime, broad telemetry engine, bestiary collection, automatic background backfill or invented historical events.
- No aggregate achievement analytics/dashboard yet; completion percentages and admin stats are a future follow-up.
- No class/race ability-use count achievements yet; those require a durable ability-use counter so future 42-use records are replay-safe and not inferred from missing history.

## Acceptance Criteria

- Achievement ids, sort order and cosmetic title grant ids are stable and unique.
- Hidden locked achievements do not reveal criteria.
- Duplicate events and replayed callbacks do not duplicate unlocks or title grants.
- Progress only moves forward.
- Manual recalculation only unlocks records proven by current persisted character identity, fight, problem, inventory and equipment rows.
- Manual recalculation uses stored historical event dates where available; if an old event has no durable timestamp series, the task documents that limitation instead of inventing history.
- Normal combat, problem-chain, item and equipment events unlock just-reached non-level thresholds from current persisted counts without requiring a manual `🔎 Перевірити` press.
- Disabled future definitions, including the current level-23 placeholder while the cap is 13, do not appear in player pages or visible totals unless the row was already earned and stored.
- Dev grant level/item commands trigger the same achievement hooks as normal successful level/item paths.
- Unknown stored achievement rows remain readable as safe archive rows.
- Remort does not clear achievements or title grants.
- Callback data stays under Telegram limits.

## Manual Telegram QA

1. Open `/hero`, press `🏅 Ачівки`, page if needed, and return to the character card.
2. Create a fresh character and verify the first achievement notification appears once.
3. Trigger level 3/5 through normal rewards or dev grant and verify grouped unlock text.
4. Win a monster fight and repeat terminal callbacks; verify no duplicate achievement.
5. Turn in Korchmar problem thresholds and equip a third manatka; verify threshold achievements unlock from the action and title-grant markers appear only as records.
6. On an existing character, press `🔎 Перевірити`; verify already-provable race/class, level/combat/problem/inventory/equipment/side-action achievements appear once with historical dates where possible and the second press reports no new records.
7. View a hidden locked achievement and verify it shows no criterion spoiler.
8. Switch `📚 Усі`, `✅ Отримані` and `🔒 Не отримані`; verify pagination and `🔎 Перевірити` preserve the selected filter.
9. Remort locally and verify achievement/title-grant rows remain.
10. Confirm XP, gold, items, stats and combat power do not change from achievements.

## Follow-up closure notes

- Current catalog count after restoration: 113 enabled achievements and 12 disabled hidden future placeholders.
- `achievement.level.23` is disabled/hidden because the current level cap is 13; it is excluded from visible totals unless already stored as an earned archive row.
- Disabled future placeholders cover PvE critical/defend/flee oddities, distinct Kyiv-day presence receipts and unequipped-start wins because current persisted state cannot honestly backfill them.
- Normal event tracking now consults current recalculation snapshots for threshold-bearing combat/problem/item/equipment definitions, while `🔎 Перевірити` remains the idempotent broader backfill path.
