# 0.3.8 — Measured Runtime Stability

## Goal

Make production performance evidence privacy-safe, terminal on failures, and attributable to one deploy, while exposing truthful runtime readiness for database and Telegram polling startup.

## Evidence

The sanitized Render export for deployed commit `9b00adc2df26f55a535add76de92a7b44d6fb139` contains 426 complete slow-tail events from machine timestamp `2026-07-11T17:56:00Z` through `2026-07-12T13:44:59Z` with effective configuration:

- `KVESTARNIA_PERF_SAMPLE_RATE=0`
- `KVESTARNIA_PERF_SLOW_MS=350`
- `YEGER_PERF_DEBUG=false`

The tail is concentrated in `fight.turn` (205 events, 48.1%, conditional p50 680.5 ms and p95 1793.1 ms) and `main-menu.quest-markers` (145 events, 34.0%, DB-conditional p50 589.2 ms and p95 924 ms). The export has no fast-call denominator and the current logger omits thrown spans, so it cannot establish route slow rates, error rates, or population percentiles.

## Scope

### Privacy-safe terminal performance telemetry

- Keep the existing disabled-by-default random sampling and always-on slow threshold.
- Remove Telegram user ids from emitted performance payloads.
- Record each span at most once and emit a terminal error event when measured DB, compute, or Telegram work throws.
- Preserve elapsed component time on thrown work.
- Emit only allowlisted error categories; never emit raw messages, stack traces, callback data, SQL parameters, tokens, URLs, database values, or serialized player state.
- Include the effective sample rate, slow threshold, evidence kind, and Render commit/instance metadata when available.

### Runtime readiness

- Keep `/health` as process liveness.
- Add `/ready`, returning `503` until the database probe succeeds and grammY invokes `onStart` immediately before polling.
- Return readiness to `503` during shutdown and after polling startup failure.
- Catch and report polling startup rejection instead of leaving a floating unhandled promise.

### Operations evidence

- Document the optional performance environment variables and their defaults.
- Document a controlled post-deploy full-sampling window only after privacy-safe telemetry is deployed.
- Update the compact context and playtesting checklist with the new readiness and sampling contract.

## Non-goals

- No combat, quest-marker, inventory, Mantok Chest, DKR, Yeger, reward, balance, or player-flow behavior changes.
- No speculative optimization from slow-tail counts alone.
- No scheduler repair rewrite, passage behavior change, attunement schema/index change, migration, cache, or dependency.
- No PR #162 delivery follow-up; that remains 0.3.7 history.
- No PR #159 work.
- No raw production logs in the repository or PR.

## Acceptance criteria

- Performance payloads contain no Telegram user id field.
- Successful sampled/slow spans and thrown measured spans emit at most one terminal record.
- Error records preserve measured duration and expose only an allowlisted category.
- Payloads distinguish slow-tail and random-sample evidence and include effective non-secret configuration.
- Render runtime metadata is emitted only from documented `RENDER_*` values.
- `/health` remains a lightweight `200` liveness endpoint.
- `/ready` is `503` before database/polling readiness, `200` after both, and `503` during shutdown or startup failure.
- Existing gameplay behavior and focused route tests remain unchanged.
