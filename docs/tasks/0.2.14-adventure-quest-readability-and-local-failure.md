# 0.2.14 - Adventure Quest Readability and Local Failure

Target version: `0.2.14`.

Prerequisite: start only after the active `0.2.13` work has landed on the branch this task uses. If the checked-out base is still `0.2.12` or otherwise missing the `0.2.13` release state, stop with a short base-not-ready note instead of silently building the `0.2.14` slice on the wrong baseline.

## Goal

Make level 3+ Adventure Choice selected-problem cards read like actual quests: the player should understand who brought the problem, what is wrong, and what the listed methods are trying to fix. Add a narrow authored local failure consequence for risky methods so some non-combat complications can genuinely fail the attempt with no reward, without turning the whole quest loop into a random punishment system.

Primary player feedback to address: the current hook can be funny, but the selected quest screen may not clearly explain the problem itself.

## Scope

- Add explicit problem/objective copy to active Adventure Choice problem content.
- Render that copy on the selected Adventure problem card before `Можливі способи`.
- Cover all current level 3+ Adventure problem ids:
  - general ids: `stew`, `barrel`, `helmet`, `calendar`, `receipt`, `bench`, `cloak`, `spoon`, `mirror`, `boots`, `chimney`, `candle`, `chair`, `broom`, `door`, `map`, `teapot`, `menu`, `sign`, `portrait`, `key`, `ledger`, `rug`, `bell`;
  - generated race families: survey, mug, portrait;
  - generated class families: manual, uniform, exam;
  - generated title family.
- Polish hooks only where they duplicate the new problem/objective line or still fail to explain the scene.
- Add a method-owned local no-reward failure consequence, preferably `local-failure`, for a small number of clearly risky authored methods.
- Ensure local failure consumes the current 93-minute Adventure claim, grants no XP/gold/items, does not start combat, and replays safely.
- Adjust already-completed/period-used copy so it works for failed attempts as well as successful closures.
- Update docs and release surfaces for `0.2.14`.

## Non-goals

- No broad quest engine rewrite.
- No new persistent social skill tree, quest rank, reputation system, quest inventory, market, crafting, raid or party feature.
- No global random failure roll after the deterministic quest grade.
- No exact chance/roll display in player-facing copy.
- No broad reward/economy rebalance.
- No schema migration unless a backward-compatible type/JSON-only update is impossible.
- No change to the 93-minute Adventure offer cadence except copy that explains a consumed failed attempt.
- No change to starter shawarma or cellar mouse unless a shared helper/presenter type requires a tiny compatibility update.

## Acceptance criteria

- Every selected level 3+ Adventure problem card clearly renders a scene hook plus explicit client/problem/objective information before the method list.
- The new copy is short, concrete, Ukrainian, Kvestarnia-flavored and not generic placeholder text.
- The compact offer list remains readable and does not become overloaded unless the implementation finds a very small safe improvement.
- Method labels/buttons still name scene actions and do not expose internal `race`, `class`, `signature`, technique or grade mechanics.
- At least one authored risky method can produce a local no-reward non-combat failure through the existing deterministic quest check path.
- Local failure result copy does not claim the quest was closed; it explains that this attempt did not work and that the next set of affairs comes with the next 93-minute period.
- Local failure claim is idempotent: duplicate callbacks do not reroll, duplicate rewards are impossible, and replay surfaces a safe existing state/result.
- Fight handoff rollback/idempotency remains unchanged.
- Existing authored quest result bodies, item grants, paid method handling and HP injury behavior remain stable.

## Manual Telegram QA

Minimum manual coverage:

1. Level 3+ character opens the quest/adventure table.
2. Select at least five different general problems and one generated race/class/title problem when forceable.
3. Confirm each selected card clearly shows:
   - title;
   - scene hook;
   - client/requester;
   - concrete problem;
   - objective/what the methods are trying to solve;
   - method list.
4. Confirm the card still fits Telegram comfortably and has no repeated walls of text.
5. Complete a normal success and mixed result; confirm rewards and result copy are unchanged except for any intended context polish.
6. Force/sample local failure; confirm no XP/gold/items, no fight, no `Справу закрито` headline, and period is consumed.
7. Duplicate-tap local failure and paid/non-paid methods; confirm replay safety and no duplicate charge/reward.
8. Confirm old stale callbacks and old `safe/flair/risky` Adventure callbacks still refresh/stale safely rather than resolving hidden methods.

## Implementation note

This slice rides the existing Adventure 93-minute claim and stored quest result JSON. It adds no schema, no new persistent reset/remort state, no new player action, no new achievement hook and no new `/dev_*` command; `/dev_adventure_reset` remains sufficient for local/manual QA.
