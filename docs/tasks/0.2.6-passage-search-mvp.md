# 0.2.6 — Passage Search MVP

Status: implemented from the provided `passage-search-feature.zip` design package.

Follow-up hardening before merge also adds server-side current-location validation for search starts, the safe passage-rest search path requested for the short monster-rest window, the missing safe search buttons on the actual `Спуск до Низу` and `Ярус I: Сутерени Корчми` cards, automatic completion messages, cooldown-aware hiding of fresh search buttons, preserved combat intro/fight-card context for danger handoffs, broad active-search guards for mutating buttons/commands, and a narrow restore-to-full bandage reservation recovery fix reported during QA.

## Goal

Ship a narrow timed search loop for the first Nyz combat surface:

- safe tiny search at `Спуск до Низу`;
- safe tiny search at `Ярус I: Сутерени Корчми`;
- risky timed search in each first-tier passage;
- local cooldown per search node;
- one active search per character;
- cancel confirmation and replay-safe results.

## Scope

- Add `🔎 Пошукати` to `Спуск до Низу`.
- Add `🔎 Пошукати` to `Ярус I: Сутерени Корчми`.
- Add `🔎 Пошукати` to `⬅️ Лівий прохід`, `🚪 Прямий прохід` and `➡️ Правий прохід` passage preview cards.
- Search cooldown is 13 minutes per node: each passage and descent location cool down independently.
- Passage search lasts 42 seconds; descent and `Ярус I` safe searches last 23 seconds.
- Starting search consumes the node cooldown immediately.
- One character can have only one running search.
- Due searches with a stored chat target resolve automatically and send a new result message.
- Other mutating or movement-like actions during a running search show the active search card instead of mutating state.
- Confirmed cancel grants no reward and does not refund cooldown.
- Safe descent and `Ярус I` searches have no monster danger and only tiny rewards.
- Risky passage search snapshots the current pending passage encounter; on danger it grants no reward, starts the existing passage fight and skips the first hero turn.
- Danger handoffs still show the normal new-fight intro before the active fight card, including threat escalation, `Натиск Низу`, full opponent names and the start tip when applicable; this also holds when a due dangerous search is lazily resolved by current-location or place actions.
- During the short monster-rest window, first-tier passage cards can start a safe 42-second passage search with no encounter token, no monster snapshot, no danger and no early preview refresh.
- Defeating a pending passage monster opens that same passage's short 3-minute rest window instead of immediately creating a new pending monster preview.
- Start callbacks re-read current presence server-side: `Спуск до Низу` search requires current `Низ`, `Ярус I` safe search requires current `Сутерени Корчми`, and passage search requires the matching passage location.
- Search loot is deliberately narrow: gold and the existing `Бинт відповідальної паніки`.
- Local `/dev_reset_passage_search` clears running search/cooldowns for manual QA.

## Non-Goals

- No broad loot catalog, new item family, shops, market, crafting or item-instance rewrite.
- No race/class/title search modifiers beyond a zeroed future hook.
- No party search, public search feed, Mini App UI or group movement.
- No new combat damage formula; monster danger uses the existing passage fight flow.
- No second durable monster-state model beyond existing pending passage encounters.

## Acceptance Criteria

- Passage A cooldown does not block passage B or `Спуск до Низу`.
- A second search cannot start while the first is running.
- Running search cards show remaining time, check and cancel controls.
- Due searches with a stored chat target send a new terminal result message without requiring a manual check tap.
- Check before `endsAt` grants nothing and keeps the action running.
- Check after `endsAt` resolves exactly once.
- Cancel resolves exactly once with no reward and keeps the node cooldown spent.
- Passage danger grants no search reward and hands off to canonical combat.
- Passage danger preserves the canonical new-fight intro even though the first hero turn is skipped.
- Descent and `Ярус I` searches are always safe and use the tiny reward table.
- Passage-rest search is always safe, uses the passage node cooldown, keeps left/straight/right tiny loot floors distinct, and does not create or refresh a pending passage encounter.
- Reopening the same passage right after defeating its pending monster shows the rest/search card and does not create a fresh pending encounter until the short rest ends.
- Stale descent, `Ярус I` or passage search starts from another current location do not create a search action, consume cooldown, create/refresh/consume an encounter or start combat.
- Fresh `Спуск до Низу`, `Ярус I` and passage cards hide `🔎 Пошукати` while that node cooldown is still active.
- Old fight/place buttons during search do not start combat or move the character without cancel confirmation.
- Active search blocks fight/place/training, quest/adventure/hunt/Yeger, inventory/item/equipment/economy, tavern/Shynok/cellar/social callbacks, plus the matching mutating slash commands and main-menu buttons; search check/cancel continue to work, due results replay first, due danger still opens the canonical fight card, and low-risk read-only slash commands such as `/help`, `/version`, `/news` and `/online` may remain available.
- `/dev_reset_passage_search` works only through local/dev command visibility.

## Manual QA

1. Start `🔎 Пошукати` at `Спуск до Низу`; check before and after the timer.
2. Open `Ярус I: Сутерени Корчми`, start `🔎 Пошукати`, and verify it is a safe 23-second location search.
3. Start a passage search with a visible monster; press `⚔️ Атакувати` from an old card and verify cancel confirmation appears.
4. Wait for the timer without pressing `Перевірити`; verify a new result message appears automatically.
5. Reopen the same Nyz surface/passage before 13 minutes and verify the fresh card does not show `🔎 Пошукати`.
6. Press `↩️ Повернутися до Сутеренів` from an old card during search and verify cancel confirmation appears.
7. Confirm cancel and verify no reward, then try the same node before 13 minutes.
8. Search one passage, resolve/cancel it, then immediately search a different passage.
9. Force or repeat until a danger outcome; verify no search reward, the ordinary passage fight opens, and the intro still shows any second-monster/`Натиск Низу`/opponent-list/tip context before the active card.
9a. Let a dangerous search become due, then use a current-location reply button or an old place button; verify the search result is followed by the intro and the active fight card.
9b. While a search is active, press old quest/fight/inventory/Yeger/Shynok/social buttons and `/fight`; verify the active search card appears and the attempted action does not move presence, spend resources, create orders or start another activity. If the search is due, verify only the search result/fight handoff replays.
10. Repeat old check/cancel/result callbacks and verify no duplicate reward.
11. Move to another location, press an old `🔎 Пошукати` from `Спуск до Низу`, `Ярус I` or a different passage, and verify no cooldown/action/combat/preview mutation occurs.
12. Defeat a pending monster in a first-tier passage, reopen that same passage before 3 minutes, press `🔎 Пошукати`, and verify the safe 42-second search starts without a monster token or early preview refresh.
13. Use `/dev_reset_passage_search` locally to clear the search state for another pass.
