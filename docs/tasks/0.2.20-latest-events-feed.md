# 0.2.20 - Latest Events Feed MVP

Status: Active implementation task
Type: Versioned implementation task

## Goal

Add `📣 Останні події` / `📜 Хроніки Квестарні`: a compact Telegram feed of recent public, socially interesting game events.

This is not an admin audit log and not a second achievement system. It is a player-facing tavern chronicle for moments worth seeing: new adventurers, level-ups, group raid victories, rare manatky and underdog combat wins.

## Scope

- Inspect current `main` before implementation and reuse existing repository/service/presenter/callback patterns.
- Add a structured `ActivityEvent` / latest-events ledger with a Prisma migration, repository interface and Prisma implementation.
- Add an `ActivityEventService` with `record`, `recordSafely` and `listRecent` behavior.
- Add event type/category/severity constants for the MVP event types.
- Add a Telegram presenter for `📜 Хроніки Квестарні`, grouped by Kyiv day.
- Add compact callback parsing for feed filters/pagination under a short prefix such as `v1:ev:*`; old refresh callbacks may remain parse-compatible, but new keyboards should not show a manual refresh button.
- Add an entry point from the existing board/news/Korchma surface using `📣 Останні події` without breaking `/news` or `Дошка корчми` navigation.
- Emit public activity rows for:
  - new character created;
  - configured level reached rows;
  - group raid victory, one row per terminal boss session;
  - rare/epic manatka received, based on current item rarity data;
  - underdog combat victory when monster level is at least 5 above player level.
- Add dedupe keys for every emitted event.
- Store snapshot display fields at event time so rendering does not require expensive joins.
- Escape and truncate all dynamic player/item/monster names in Telegram output.
- Add focused unit/integration tests for repository/service, renderer, callbacks and emission hooks.
- Update release surfaces for a runtime versioned change.

## Achievement Decision

Add a one-time rewardless achievement for first opening/reading the feed.

Reason: the feed is a new discoverable player-facing surface, and the existing `CharacterAchievement` ledger can store a first-open record without adding a per-read reward faucet. Opening the feed must not grant XP, gold, items, combat power or title power; filtering, paginating and stale legacy refresh-compatible callbacks must not have separate achievements or repeatable hidden progress.

The matching achievement is `achievement.journey.latest-events-opened`, triggered by `latest-events.opened`. It unlocks from the first successful feed render only; old refresh-compatible callbacks count only if they are the player's first successful feed interaction.

Activity events may be emitted from the same successful gameplay boundaries that already feed achievements, but do not forward every achievement unlock into the public feed.

## Non-goals

- No broad refactor of achievements, combat, raids, inventory, item content or Telegram routing.
- No proactive group/channel auto-announcements unless explicitly requested later.
- No public death/loss/failure shame rows.
- No item-upgrade rows unless current `main` already has a durable item-upgrade mechanic.
- No overlevel item rows unless current `main` already has item level / required level data.
- No guilds, market, crafting, PvP, Mini App UI, admin audit viewer or moderation tooling.
- No reward, economy, drop-rate or combat-power changes.
- No exact future reward amounts, hidden odds or unreleased mechanics in player-facing copy.

## Acceptance Criteria

- `📣 Останні події` is reachable from the appropriate existing board/news/Korchma surface.
- The feed title is `📜 Хроніки Квестарні`.
- Rows are grouped by Kyiv day and show a short emoji + `HH:mm` + event sentence.
- Empty, error and stale-callback states are safe and short.
- The default feed shows a bounded page of recent public rows.
- Filters work for important/adventurer/combat/manatky categories.
- Callback data stays within Telegram's 64-byte limit.
- Dynamic names are escaped and truncated; blank/invisible display names use a fallback.
- Character creation creates one deduped public row.
- Level-up creates deduped public rows according to the implemented threshold rule.
- Group raid victory creates one deduped row per terminal boss session, not one per participant.
- Rare/epic manatka receipt creates rows only for configured public rarities.
- Underdog combat win creates a row only for wins with monster level delta >= 5.
- Underdog combat win uses the frozen effective monster level from the persistent fight session when one exists, not only the authored content monster level.
- Ordinary combat wins, common items, losses/deaths, passive feed reads and achievement recalculation do not create public rows.
- Activity logging failure does not rollback the primary gameplay action.
- Historical rows may be populated by the dry-run-first `npm run maintenance:backfill-activity-events` script for events that can be reconstructed without guessing.
- Operators can inspect or poll the current feed ledger with the read-only `npm run maintenance:poll-activity-events` script.
- Follow-up release fixes keep the daily Korchma round as explicit opt-in (`Берусь за обхід` starts it, `Пізніше` does not), keep active table-located daily scenes actionable from the physical table callback, and align failed grownup cellar roleplay retry timing to the intended `93`-minute pause.
- Follow-up help fixes keep `/help` and the main `📖 Допомога` button on the public command catalog, while dev-only commands live in `/dev_help` and `🧰 Адмінка`.
- Follow-up archive fixes keep the completed first Yeger board `Неспокійні справи` visible in `📦 Архів` while `Неспокійні справи 2.0` is active or completed.
- Follow-up starter archive fixes keep completed `Підозріла шаурма` and `Новачкова сутичка` visible in `📦 Архів` after the player outlevels the starter table, while active starter entries remain on `📋 Стіл зі справами`.
- Follow-up Yeger corner fixes hide the closed quest-detail button after the current board is completed, and `Неспокійні справи 2.0` turn-in grants two `Єгерська риска на дощечці` keepsakes alongside XP and gold.
- Follow-up operator-script fixes make `maintenance:poll-activity-events` explain the exact migration preflight command when `ActivityEvent` is missing from the current `DATABASE_URL`.
- Empty polling output explains that existing characters/items require `ActivityEvent` archival backfill before they appear in the feed ledger.
- Backfill dry-run output and docs now show the exact npm `-- --apply` form and the isolated local bot `DATABASE_URL` flow for local-bot-visible rows.
- `maintenance:backfill-activity-events` and `maintenance:poll-activity-events` have scoped lint/typecheck coverage without broadening checks to unrelated legacy scripts.
- Relevant automated tests pass or blockers are named.
- Manual Telegram QA status is listed in the PR body/final handoff.
