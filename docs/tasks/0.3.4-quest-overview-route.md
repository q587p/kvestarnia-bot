# 0.3.4 - Quest Overview Route

## Goal

Turn the persistent `🗺️ Квести` button into a compact quest overview/journal route instead of another opener for `📋 Стіл зі справами`.

## Scope

- Render a read-only `🗺️ Квести` overview from the current quest snapshot.
- Show compact rows only for active/taken/current-period progress or claimable quest work.
- Hide starter rows, retired rows, locked future quests, generic available untaken quests, completed/reward-claimed rows, and informational unlock hints.
- Each visible row should carry progress, what is already done when available, next-step guidance, and a location/turn-in hint in text.
- Show a compact empty state when no active/taken/claimable rows exist.
- Keep the existing `/quest`, physical `Стіл зі справами`, `v1:quest:list`, and Quest Hub archive behavior.
- Keep overview buttons navigation-only: `📋 До Столу зі справами`, optional refresh, and hall/back navigation. Do not add per-quest direct route buttons from overview rows.

## Non-goals

- No new quest engine, journal archive, rewards, schema, migrations, public feed rows, combat rebalance, Mini App, or Yeger/Adventure/Daily reward changes.
- No new achievement: this is a UX/readability route over existing gameplay.
- No new `/dev_*` helper: the slice adds no timer, cooldown, random offer, pending session, retry, once-per-period gate, or wait rule.
- No lore-board update: the shipped in-world behavior of quest systems is unchanged; only the navigation overview changes.

## Acceptance criteria

- `🗺️ Квести` shows a useful active/taken/claimable overview from safe Korchma states and does not stamp quest-table presence.
- Locked, retired, completed/reward-claimed and generic available untaken quest rows stay out of the overview.
- Empty overview states explain that new papers come from `Стіл зі справами`.
- Outside-Korchma, no-character, active combat, turn-based duel, pending/active Big Barrel, active passage-search and stale callback blockers keep existing behavior.
- Overview buttons are navigation-only; per-quest locations are mentioned in text rather than offered as direct route buttons.
- Quest Table and archive callbacks remain compatible.
- Overview text is Ukrainian, compact, HTML-escaped and under Telegram callback-size limits.

## Manual Telegram QA

1. High-level character with completed starter quests: open `🗺️ Квести`; verify starter shawarma/fight rows are absent.
2. Character with no active/taken quests: verify the compact empty state points to `Стіл зі справами`.
3. Active Daily Korchma Round 1/2: verify the row appears with done step, next step and location/turn-in text, without a direct `До обходу` button.
4. Daily Korchma Round 2/2 turn-in-ready: verify the row appears as claimable and explains where to turn in.
5. Problem Quest in progress: verify the row appears with progress and turn-in guidance.
6. Problem Quest completed and reward claimed: verify the row disappears.
7. Yeger not started: verify no row.
8. Yeger in progress / claimable: verify the row appears with progress or turn-in guidance and no direct `До Єгеря` button.
9. Barrel Beer Tutorial completed, retired or merely available: verify no row; in progress / turn-in-ready still appears.
10. From the full Quest Hub, open the available Barrel Beer Tutorial paper; verify it shows a preview/confirmation card, does not grant the stipend or mark the quest accepted yet, and only `🛢️ Взяти записку` grants the accepted result with the 39-gold received line.
11. Verify the overview keyboard contains only `📋 До Столу зі справами`, optional `🔎 Оновити`, and `🍺 До зали` / back navigation.
12. Verify opening overview does not complete, claim, accept, start fights, start raids, move presence to `Стіл зі справами`, or expose per-quest route buttons such as `До Низу`, `До Єгеря`, `До бочки`, `До шинку`, `До льоху`, `До задвірка`, `До Корчмаря`, `До обходу`, or `До Трьох справ`.
13. Verify `📋 До Столу зі справами` still opens the full Quest Hub.
14. Active solo combat, active turn-based duel, active/pending Big Barrel and active passage search: verify existing blockers win over overview.
15. Stale `v1:quest:overview` callback: verify it fails closed or routes to the current canonical overview without mutation.
