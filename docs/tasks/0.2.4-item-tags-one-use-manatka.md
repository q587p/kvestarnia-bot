# 0.2.4 — Item Tags and One-use Manatka

## Goal

Introduce a narrow item tag contract and one explicit out-of-combat one-use healing bandage manatka.

This task is intentionally not a full consumable catalog. It ships one low-power healing bandage with preview, confirmation, transactional consumption, and replay-safe completion.

## Scope

- Add the supported item tag vocabulary for this slice:
  - `consumable`
  - `one-use`
  - `tradeable`
  - `trade-blocked`
  - `duel-blocked`
  - `raid-blocked`
  - `story`
  - `memory`
  - `sentimental`
  - `soulbound`
- Reject unknown tags, duplicate tags, and contradictory trade tags in content validation.
- Keep legacy items unchanged unless they opt into tags.
- Add `Бинт відповідальної паніки` with `consumable` and `one-use` tags.
- Let players use that item only from item detail.
- Show exact current HP recovery in the preview.
- Block use at full HP, during combat, or if ownership/content/reservation state changes.
- Confirm in a transaction, settle passive recovery at confirmation time, consume one item, apply capped HP recovery, and persist a terminal result.
- Treat duplicate or concurrent confirmation as replay, not a second consume/heal.
- Let eligible heroes buy one bandage from the Єгер.
- Give `class.ranger` a Єгер-specific bandage advantage through a lower buy price plus a periodic free bandage claim.
- Let the bandage appear occasionally through existing monster loot by adding it to one low-level authored monster loot list. The broader loot engine already applies existing LUCK/drop mechanics; a new tag-weighted bandage formula is a later slice.

## Non-goals

- In-combat consumables.
- A broad item action catalog.
- Mana, damage, buff, debuff, cooldown, duel, raid, party, broad shop, crafting, daily faucet, or food systems.
- Retagging the whole item catalog.
- Race abilities, achievements, cosmetic titles, or signature techniques.
- A new broad monster type/tag drop weighting engine.

## Acceptance

- Content tests cover the tag contract and the shipped consumable.
- Service/repository tests cover preview, full HP blocking, combat blocking, atomic consume/heal, and replay.
- Telegram callback data stays under 64 bytes.
- Release surfaces describe the visible player behavior without exposing hidden odds.
- Backlog docs distinguish this shipped slice from deferred race/signature/title/achievement work.
- Єгер bandage buy/free claims are replay-safe and tested without adding a general shop.
