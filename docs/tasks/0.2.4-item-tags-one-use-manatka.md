# 0.2.4 — Item Tags and One-use Manatka

## Goal

Introduce a narrow item tag contract and the first one-use manatka flow, including combat-safe use as a current persistent PvE fight action.

This task is intentionally not a full consumable catalog. It ships one low-power bandage with out-of-combat preview/confirmation, transactional consumption, replay-safe completion, and a reusable combat item-use route for the currently supported `heal-hp` effect.

## Scope

- Add the supported item tag vocabulary for this slice:
  - `consumable`
  - `one-use`
  - `tradeable`
  - `trade-blocked`
  - `duel-blocked`
  - `raid-blocked`
  - `story`
  - `memory`
  - `sentimental`
  - `soulbound`
- Reject unknown tags, duplicate tags, and contradictory trade tags in content validation.
- Treat `trade-blocked` and `soulbound` as transfer-blocking for Safe Gifting while preserving legacy untagged priced item eligibility.
- Keep legacy items unchanged unless they opt into tags.
- Add `Бинт відповідальної паніки` with `consumable` and `one-use` tags.
- Let players use that item from item detail.
- Show exact current HP recovery in the preview.
- Block out-of-combat use at full HP or if ownership/content/reservation state changes.
- Confirm in a transaction, settle passive HP/mana recovery at confirmation time with canonical Shynok recovery windows, consume one item, apply capped HP recovery, and persist a terminal result without wiping unrelated fractional recovery progress.
- After a successful out-of-combat bandage use and on the hero card, offer `До відновлення` when the remaining stack can fully restore HP; the shortcut creates a replay-safe server-owned preview/order, then confirmation consumes exactly the frozen needed number of bandages in one transaction.
- Treat duplicate or concurrent confirmation as replay, not a second consume/heal.
- During an active persistent PvE fight, route item-detail use through a fight callback that consumes one eligible one-use manatka, applies its supported combat effect to `CombatState`, advances the current turn, and lets monsters respond like a normal committed action. Stale turns, missing stacks, reserved stacks and full-HP healing attempts must not consume the item or advance the fight.
- Let eligible heroes preview, confirm/cancel and replay-safely buy 1, 5, 17 or 93 paid bandages from the Єгер, capped by the shared 93-bandage paid daily limit.
- The paid Єгер bundle day uses the existing shared UTC ISO-date boundary; periodic free ranger claims and loot do not count toward the paid cap.
- Give `class.ranger` a Єгер-specific bandage advantage through a lower buy price plus a periodic free bandage claim.
- After the first 5-target Єгер board is completed, offer a second 17-target board with separate once-per-life keys; remort resets both boards so each new life starts from zero.
- Reset current-life daily actions, cooldowns, hunt contracts and Barrel raid notification rows on successful remort so paid Єгер bandage counts and other current-life gates do not leak across lives.
- Add local `/dev_reset_yeger_trail` so manual QA can finish the Єгер trail wait without changing production tracking rules.
- Add local `/dev_add_bandage [count]` and let `/dev_heal [HP]` work during active combat for faster local item QA.
- Add local `/dev_reset_yeger_bandage_day` so manual QA can clear the paid Єгер bandage purchase day without waiting for the UTC date boundary.
- For lost multi-enemy persistent fights, grant partial attempt XP for enemies defeated before the loss while still granting no gold, no items and no quest progress.
- Won persistent PvE fights roll an independent post-fight bandage quantity: base chances are 50% for 0, 25% for 1, 13% for 2, 8% for 3, 3% for 4 and 1% for 5. The base table ignores LUCK; bounded LUCK can improve the result by one bandage, capped at 5.

## Non-goals

- A broad item action catalog.
- New mana, damage, buff, debuff, cooldown, duel, raid, party, broad shop, crafting, daily faucet, or food systems.
- Retagging the whole item catalog.
- Race abilities, achievements, cosmetic titles, or signature techniques.
- A new broad monster type/tag drop weighting engine.

## Acceptance

- Content tests cover the tag contract and the shipped consumable.
- Service/repository tests cover preview, full HP blocking, ordinary combat-lock bypass through the fight item route, active-lease multi-enemy consume/heal, and replay/stale protection.
- Out-of-combat result and hero-card keyboards offer `До відновлення` only when enough bandages remain; pressing it creates a confirmation preview rather than mutating from the item id, and repository tests cover exact multi-bandage consumption, replay, cancel/expiry/race, stale HP/remort, and not-enough cases.
- One-use consumables appear before other carried items in the inventory list, and the restore-to-full button uses the roll icon on both the hero card and item-use result cards.
- Mantok Chest auto-pick skips consumable/one-use manatky, while manual selection can still explicitly include them.
- Telegram callback data stays under 64 bytes.
- Release surfaces describe the visible player behavior without exposing hidden odds.
- Backlog docs distinguish this shipped slice from deferred race/signature/title/achievement work.
- Єгер bandage paid bundle purchases and free claims are replay-safe and tested without adding a general shop.
- Єгер paid bandage preview copy stays prospective until the player confirms the purchase.
- Insufficient-gold Єгер paid bandage confirmation offers a new tokenized smaller bundle only when the current wallet can afford at least one bandage; the fallback respects the class-ranger discount and daily paid cap, and it does not debit gold until the player confirms that new token.
- Class-ranger free Єгер bandage claims stay available before the level-4 Єгер quest gate; only the quest row remains level-gated.
- Local `/dev_reset_yeger_bandage` skips the Єгер free-bandage cooldown for manual QA without changing production claim rules.
- Local `/dev_add_bandage [count]` grants one or more responsible-panic bandages for manual QA, and local `/dev_heal [HP]` works during active combat.
- Local `/dev_reset_yeger_bandage_day` clears paid Єгер bandage preview/confirm/cancel ledger rows so `Сьогодні куплено` returns to zero for manual QA.
- Local `/dev_reset_yeger_trail` makes an already-started Єгер trail immediately checkable for QA without claiming rewards or creating fights directly.
- Remort resets paid Єгер bandage purchase counts, both first and second Єгер unquiet boards, daily-action quest/progress rows, cooldowns, hunt contracts and Barrel raid notification rows; after remort, the quest chain begins from `0/5` and current-life counters begin from zero.
- Lost multi-enemy fights that already defeated an enemy replay a partial XP-only attempt reward; they do not grant gold, items or quest progress.
