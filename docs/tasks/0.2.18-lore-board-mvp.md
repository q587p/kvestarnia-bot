# 0.2.18 - Lore Board MVP

## Goal

Add `📖 Перекази` to the existing `Дошка корчми` / news-corner surface so players can read short in-world Kvestarnia texts about current locations, races, classes, manatky and customs, plus jump from the Lore Board into the existing Bestiary.

This is not a wiki, reward path or gameplay requirement. It should feel like tavern folklore and notice-board marginalia.

## Scope

- Inspect the existing news-corner / `Дошка корчми` flow before designing new handlers.
- Add one visible `📖 Перекази` entry point without breaking `/news`, the news archive or return navigation.
- Add static typed lore content seeded from the current lore docs.
- Cover every current active race, class and Korchma presence location with a short entry.
- Group the `🪧 Місцини корчми` category by natural Korchma areas so the Telegram keyboard stays compact instead of showing every place in one long stack.
- Keep the Bestiary as its existing runtime surface instead of duplicating a partial monster list in Lore Board; add special non-level Bestiary records for the Barrel and Big Barrel Brother, plus Bestiary first/last/random navigation.
- Preserve Lore Board source-aware navigation when Lore Board opens Bestiary, so Bestiary list/detail/random screens return to `📖 Перекази` / `Дошка корчми` instead of the hunt board.
- Keep source-of-truth references aligned with live content arrays where practical:
  - `src/content/races.ts`
  - `src/content/classes.ts`
  - `src/content/monsters.ts`
  - `src/content/items.ts`
  - Korchma presence/location constants
- Add render helpers for lore menu, category screen, entry screen, random entry, empty state and error state.
- Add compact versioned callback parsing/handlers under `v1:lore:*`.
- Keep callback data within Telegram's 64-byte limit and use existing safe callback/edit patterns.
- Add validation for broken category ids, duplicate ids, canonical refs, missing entries, explicitly external categories and random selection from empty categories.
- Add concise docs for adding new lore entries and maintaining `canonicalRefs`.

## Achievement Decision

This MVP deliberately adds no XP, gold, items, combat power, unlock progress or achievement rewards for reading lore.

There is no durable read ledger in this slice, and simple reading should not become a hidden reward faucet. If a future rewardless first-read achievement becomes desirable, add a small persisted read/progress contract with normal achievement hooks and tests in a separate task.

## Non-goals

- No Prisma schema change or migration.
- No admin UI, unlock/progress gating, WebView, separate app surface, market, ґільдії, matchmaking or monetization.
- No rewrite of the existing news-corner or `/news` flow.
- No changes to Big Barrel Brother combat/reward/session behavior, party/raid mechanics, combat, rewards, XP/gold, loot, remort or passage search behavior. A same-PR follow-up may still fix presentation-only result-card copy, such as terminal participant labels or active-only cooldown rows, when it does not change raid mechanics.
- No exact future rewards, hidden odds, hidden path ids or combat/drop formulas in player-facing copy.
- No invented playable race/class names outside current runtime content.

## Acceptance Criteria

- `Дошка корчми` has a `📖 Перекази` button and existing board/news buttons still work.
- Lore menu shows all seed categories:
  - `🏚 Про Квестарню`
  - `🪧 Місцини корчми`
  - `🧝 Раси пригодників`
  - `⚔️ Класи пригодників`
  - `🧌 Бестіарій`
  - `🎒 Манатки`
  - `📜 Звичаї й чутки`
- Category screens list only entries from that category and offer category-random navigation, except explicitly external categories such as `🧌 Бестіарій`, which link to their existing runtime surface.
- Entry screens show title, source, body, category position and safe navigation buttons.
- The `🪧 Місцини корчми` category shows compact subgroups (`Надвірʼя`, `Зала й шинок`, `Бочка й льох`, `Кутки`, `Низ`) before listing individual place entries.
- `canonicalRefs` validate against current race/class/monster/location/item ids where those registries exist.
- Race, class and Korchma place lore covers all currently active runtime ids without adding future playable races/classes or future places.
- The Bestiary category opens the existing `v1:bst` Bestiary rather than maintaining a second partial monster roster; the Barrel and Big Barrel Brother appear as special non-level Bestiary records at the end.
- Bestiary list/detail screens offer first/previous/next/last navigation where relevant and `🎲 Випадковий запис`, while preserving the level 3 Bestiary gate.
- Bestiary opened from Lore Board preserves that source through list/detail/random navigation and shows `⬅️ До переказів`; `/bestiary`, `/monsters`, Hunt Board and older `v1:bst:*` callbacks keep the existing `🏹 До дошки` return.
- Random entry never returns `undefined` when content exists and empty categories have a safe fallback.
- Invalid lore callbacks do not throw and answer callback queries without spinner hangs.
- Callback data stays within 64 bytes.
- Player-facing copy follows `docs/CONTENT_STYLE_GUIDE.md`, including `Квестарня`, `соціяльн*`, `мітолог*`, `ґільдії`, Ukrainian `«»` quotes and no separate app-surface promise.

8. Tap random lore, category-random and Bestiary random several times; verify no empty or broken result.
9. Replay old/stale lore callbacks after a restart/deploy; verify no crash or spinner hang.
10. Return to `Дошка корчми`; verify the original board card is restored through the existing flow.
11. Confirm lore and Bestiary reading grants no XP, gold, items, combat power, unlock progress or hidden achievement.
